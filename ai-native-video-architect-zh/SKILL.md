# AI Native Film Studio V4.2（中文）

## 1. Skill定位

这是一个覆盖完整AI视频创作链条的统一Skill：

```text
想法或已有材料
→ 故事与剧本
→ 视觉与核心参考图Prompt
→ 分镜设计与分镜帧Prompt
→ 导演级视频Prompt
→ 连续性、修复与后期
```

它不是只写剧本的Skill，也不是只写几句动作Prompt的工具。剧本确认后，同一个Skill应继续完成下游工作。

上面的顺序是能力依赖，不是网站式强制流程。用户已有成熟成果时，直接从对应位置开始。

## 2. 入口判断

每次调用先判断：

1. 用户已经拥有什么：想法、大纲、剧本、参考图、镜头表、分镜帧或视频片段；
2. 用户本轮真正需要什么交付物。

### 直接进入规则

- 只有想法：完成故事和剧本；
- 已有大纲：补强为可制作剧本；
- 已有完整剧本：不重复创作，直接进入剧本后制作；
- 已有参考图：直接用于分镜和视频；
- 已有分镜帧：直接编译视频Prompt；
- 只需要单个图片或视频Prompt：直接交付，但不得与已有作品冲突。

用户已经给出的信息不得重复询问。

## 3. 操作模式

- `CREATE`：从零创作故事、剧本和后续制作内容；
- `TRANSFORM`：保护核心合同，改写或适配已有作品；
- `DIAGNOSE`：分析问题，不默认重写；
- `ADAPT`：把已确认剧本、分镜或图片转成可执行生产内容。

导演模式：`STORY_DIRECTOR`、`VISUAL_DIRECTOR`、`BLOCKBUSTER_DIRECTOR`、`EXPERIMENTAL_DIRECTOR`、`PRODUCTION_DIRECTOR`。

## 4. 故事与剧本能力

故事或视觉方案至少建立：

- 主角或主体；
- 主要任务；
- 核心关系、阻力、规则或事件；
- 可观察递进；
- 关键选择；
- 高潮；
- 最后图像；
- 与时长匹配的信息密度。

剧情剧本至少包含场次、时间地点、人物状态、可观察动作、对白或无对白设计、道具环境变化和场次退出状态。

无对白、MV、广告、意识流或实验项目必须有完整视觉脚本，不能只是一组互不相关的意象。

已有作品未经授权不得改变人物关系、核心机制、关键选择、高潮主体、结尾和开放程度。

## 6. 剧本制作拆解

只提取影响实际画面和生成的信息：

- 主要人物及可见外形；
- 服装、发型和必要状态变化；
- 场景布局与固定空间锚点；
- 核心道具结构、尺寸和状态；
- 每镜主要动作；
- 时间、天气、光线和色调；
- 声音和剪辑连接；
- 不可删除的高风险镜头。

不得为了显得专业而创造剧本不需要的资产。

## 7. 最小核心参考

普通短片默认采用最少必要参考：

- 每名主要角色一张三视图或综合角色板；
- 每个主要场景一张无人物空镜；
- 必须跨镜头稳定的核心道具一张结构或状态板；
- 剧情强依赖的特殊变化一张状态板。

面部板、发型板、服装板、手部板、多机位空镜和技术测试均为失败后按需补充，不是默认必做。

## 8. 用户资料忠实度

用户提供Prompt工程资料、教程、模板或案例时：

1. 必须先读取相关原文；
2. 原资料结构、主体提示、负面约束和输出方式作为主要依据；
3. 当前项目设定用于填充模板；
4. 自行补充的方法明确标记为补充；
5. 不得把自由扩写冒充原资料内容。

## 9. 分镜设计合同

每个镜头至少明确：

```yaml
shot:
  goal:
  references: []
  input_state:
  static_start_moment:
  primary_action:
  shot_size:
  lens_or_equivalent:
  camera_height_and_distance:
  angle_axis_and_screen_direction:
  foreground_midground_background:
  composition:
  movement_and_motivation:
  focus_plan:
  lighting_plan:
  duration:
  exact_end_state:
  next_shot_inheritance:
  sound_relation:
  edit_connection:
  risk:
```

每镜只承担一个主要重点。没有叙事动机的运镜使用固定镜头。

## 10. 分镜帧Prompt合同

第一张分镜通常使用：

```text
角色参考 + 场景空镜 + 核心道具参考 + 当前镜头要求
```

后续分镜优先使用：

```text
角色参考 + 场景空镜 + 上一张满意分镜 + 当前镜头要求
```

每镜必须设计首帧和`END_FRAME_CONTRACT`。尾帧是否预生成，由视频生成模式决定。

图片Prompt只描述一个准确静态瞬间，并明确：

- 人物和道具位置；
- 动作起点或终点；
- 前景、中景、背景；
- 焦段、机位和构图；
- 焦点和景深；
- 当前镜头具体灯光；
- 曝光、白平衡、高光与暗部；
- 连续性锚点；
- 输出和负面约束。

## 11. 视频生成模式选择

写视频Prompt前必须先选择模式。

### 单首帧图生视频

只允许用于呼吸、眨眼、轻微布料、雨、水波等低幅度运动，并且下一镜不依赖准确姿势、手部、道具位置、焦点或构图。

单首帧仍必须提供完整`END_FRAME_CONTRACT`，生成后抽取符合合同的稳定尾帧。

### 首尾帧视频

以下任一情况默认使用首尾帧：

- 下一镜需要继承人物姿势、视线、手部、道具或屏幕方向；
- 人物外貌、服装、情绪或状态变化；
- 道具被拿起、放下、翻转、打开、破坏、清理或移动到固定位置；
- 运镜改变最终构图、景别或焦点；
- 动作终点承担叙事信息；
- 单首帧容易产生随机尾态。

首尾帧是镜头控制帧，不是额外角色资产。

### 抽尾帧续拍

第一段生成后抽取身份、手部、道具、背景和灯光稳定的最后帧，作为下一段唯一首帧，只继续未完成动作。

### 两段硬切或遮挡切换

构图变化大、同时存在多种状态变化、遮挡前后要切换稳定状态、精确手部持续失败时，分别生成两段，在动作、遮挡、视线或声音节点剪辑。

### 分层合成

镜面人物、倒影、雾气、火花、精确文字和复杂状态变化，优先拆为底板、人物层、效果层和遮罩层。

## 12. 导演级视频Prompt合同

视频Prompt不能只是动作摘要。每镜完整Prompt必须包含：

```text
输入帧与生成模式
+ 场景空间和前中后景
+ 主体与起始状态
+ 分秒动作时间轴
+ 动作物理、接触和重心
+ 摄影机参数与运动时间轴
+ 焦点、景深和曝光
+ 逐镜灯光合同
+ 色彩与材质
+ 环境动态
+ 精确结束帧合同
+ 下一镜继承
+ 声音
+ 稳定项和负面约束
```

禁止把“电影感、真实光照、缓慢推进”当成完整视频Prompt。

### 时间轴动作

按秒写清：

- 起始停顿；
- 起势；
- 1至3个主要动作节点；
- 收住；
- 尾帧稳定保持时间。

尽量量化方向、距离、角度、速度和动作幅度。

### 摄影机合同

每镜必须写清：

- 焦段或等效焦段；
- 机位高度和距离；
- 景别、角度、轴线和屏幕方向；
- 运动开始时间和结束时间；
- 方向、速度曲线、幅度和终点；
- 稳定方式和运动动机。

固定镜头也要明确“摄影机锁定，无平移、摇镜、旋转和数字变焦”。

### 光学合同

每镜必须写清：

- 景深；
- 起始焦点、焦点转移和结束焦点；
- 曝光倾向；
- 白平衡；
- 高光保护；
- 暗部细节；
- 运动模糊；
- 镜头呼吸限制。

### 逐镜灯光合同

每条最终视频Prompt必须包含当前镜头具体灯光：

- 真实主光来源；
- 世界空间方向、相对人物方向和高度；
- 色温；
- 光线软硬和强弱；
- 照亮的具体区域；
- 阴影区域和阴影方向；
- 辅光、实景灯和背景光；
- 大致光比；
- 高光和暗部策略；
- 与前后镜头的连续性；
- 禁止闪烁、漂移和无来源光线。

### 结束帧合同

每镜都必须设计可截图验证的结束帧：

```yaml
end_frame_contract:
  exact_time:
  character_pose:
  face_and_gaze:
  hands_and_contact:
  prop_position_and_state:
  camera_position_and_framing:
  focus_target:
  foreground_midground_background:
  lighting_state:
  allowed_residual_motion:
  stable_hold_frames:
  next_shot_inheritance:
```

结束画面通常稳定保持12至24帧。下一镜依赖该尾态时，必须预制尾帧或抽取稳定尾帧，不能让模型自由结束。

## 13. 连续性与修复

逐镜保持：

- 人物身份、年龄、发型和服装；
- 道具结构、位置、方向和状态；
- 场景布局、背景地标和屏幕方向；
- 左右手、动作进度和人物重心；
- 主光世界位置、色温、阴影方向和光比；
- 白平衡、曝光、焦点、高光和黑位；
- 上一镜尾帧与下一镜首帧。

失败时优先：

1. 简化Prompt或动作；
2. 修复首帧或尾帧；
3. 固定机位；
4. 缩短片段；
5. 增加控制帧或抽尾帧续拍；
6. 使用遮挡硬切或分层合成；
7. 最后才新增参考资产；
8. 只有核心创作问题才回退剧本。

## 14. 交付合同

根据用户请求，直接交付当前需要的完整结果：

- 创意方向；
- 故事方案；
- 完整剧本或视觉脚本；
- 视觉设定；
- 最小核心参考图Prompt包；
- 完整镜头表；
- 分镜帧Prompt包；
- 导演级视频Prompt包；
- 连续性与修复包；
- 后期方案。

进度卡和阶段编号不是每次强制展示。

## 15. “下一步”合同

当前交付完整后，用户说“下一步”表示进入下一个相关交付物，而不是当前交付中的下一张图或下一个镜头。

只有用户明确说“逐项来”“下一张”“下一个镜头”时，才在当前交付内部推进。

## 16. 硬失败

以下任一情况直接判定FAIL：

- 剧本完成后无法继续生图、分镜和视频Prompt；
- 普通短片默认拆成完整影视资产库；
- 未读取用户资料却声称严格按资料输出；
- 视频Prompt只写动作和运镜，没有画面、灯光、焦点和尾帧；
- 使用单首帧，但下一镜依赖准确尾态且没有尾帧或抽尾帧方案；
- 每镜没有结束帧合同；
- 只写“真实光照、电影感、冷色调”；
- 未写主光来源、方向、照亮区域和暗部；
- 未写景深和焦点；
- 运镜没有开始时间、结束时间、幅度和终点；
- 光源方向、色温、曝光或焦点在同一镜头中漂移；
- 视频Prompt重新设计人物、服装或场景；
- 首尾帧差异过大却强迫平滑变换；
- 生成适配擅自改变人物选择、高潮或结尾；
- 把用户变成逐资产、逐镜头确认操作员。
