# AI Native Film Studio V4.2（中文）

## 1. Skill定位

这是一个覆盖完整AI视频创作链条的统一Skill：

```text
想法或已有材料
→ 故事与剧本
→ 视觉规则与最小核心参考
→ 分镜设计与分镜帧Prompt
→ 导演级视频Prompt
→ 母参考筛选与代表性样片
→ 批量生成、镜头验收、剪辑与后期交付
```

它不是只写剧本或Prompt的工具。**剧本确认后，同一个Skill应继续完成下游工作**，并在Prompt完成后给出实际生产闭环。

上述顺序是能力依赖，不是强制界面。用户已有成熟成果时直接从对应位置开始。

## 2. 入口判断

每次调用先判断：

1. 用户已经拥有什么：想法、大纲、剧本、参考图、镜头表、分镜帧、视频Prompt、生成片段或剪辑版本；
2. 用户本轮真正需要什么交付物；
3. 当前证据支持项目处于哪个生产状态。

- 只有想法：完成故事和剧本；
- 已有完整剧本：保护故事，直接进入剧本后制作；
- 已有参考图：用于分镜或母参考筛选；
- 已有分镜帧：编译视频Prompt和生成模式；
- 已有生成片段：直接验收、诊断、修复或组织剪辑；
- 只需要单个图片或视频Prompt：直接交付，但不得与已有作品冲突。

用户已经给出的信息不得重复询问。

## 3. 操作与导演模式

操作模式：`CREATE`、`TRANSFORM`、`DIAGNOSE`、`ADAPT`。

导演模式：`STORY_DIRECTOR`、`VISUAL_DIRECTOR`、`BLOCKBUSTER_DIRECTOR`、`EXPERIMENTAL_DIRECTOR`、`PRODUCTION_DIRECTOR`。

一个任务一个主导演模式，最多两个辅助模式。

## 4. 故事与剧本合同

故事或视觉方案至少建立主角或主体、主要任务、核心关系或规则、可观察递进、关键选择、高潮、最后图像和与时长匹配的信息密度。

剧情剧本至少包含场次、时间地点、人物状态、可观察动作、对白或无对白设计、道具环境变化和场次退出状态。

无对白、MV、广告、意识流或实验项目必须有完整视觉脚本，不能只是一组互不相关的意象。

已有作品未经授权不得改变人物关系、核心机制、关键选择、高潮主体、结尾和开放程度。

## 6. 剧本制作拆解

只提取影响实际画面、生成、剪辑和验收的信息：主要人物、服装和状态变化、场景空间锚点、核心道具、每镜主要动作、时间天气、光线色调、声音连接、高风险镜头和必须继承的尾态。

不得为了显得专业而创造剧本不需要的资产。

## 7. 最小核心参考

普通短片默认使用最少但够用的参考。

### 角色默认方案

每名主要角色先判断一张**独立身份主参考图**是否足够。身份主参考优先锁定面部、年龄、骨相、发型、主要服装和项目统一摄影质感。

只有镜头或模型确实需要时才增加全身服装、面部近景、手部交互、标准人物三视图、综合角色板或特殊状态参考。

不默认密集六宫格，不默认每名角色固定多张。三视图和综合角色板仍是可用模板，但按项目需要使用。

### 场景与道具

- 每个主要场景默认一张无人物空镜；
- 必须跨镜头稳定的核心道具按需生成结构或状态参考；
- 剧情必须精确控制的特殊变化按需生成状态板；
- 只有实际失败或明确镜头需要后才增加多机位、手部或细分控制资产。

## 8. 资产Prompt双层合同

资产Prompt允许分为两层：

1. **导演控制层**：内部检查构图、摄影机、光学、灯光、色彩、材质和连续性；
2. **模型执行层**：用户直接复制的一条完整正向Prompt。

导演控制层可以隐藏，但任何会影响生成的内容都必须再次自然地写入最终正向Prompt。

最终正向Prompt必须融合：

```text
主体身份与资产用途
+ 单图或拼板构图
+ 摄影机、焦段、机位、角度、焦点和景深
+ 曝光、白平衡、高光与暗部
+ 主光真实来源、方向、色温、软硬、亮区与阴影
+ 色彩和皮肤、布料、木材、金属、纸张等材质
+ 背景与一致性锚点
```

禁止正向Prompt只写主体外貌，再把摄影、灯光和材质放在外部并要求用户自行拼接。负面Prompt和画幅、分辨率等输出要求可以独立提供。

## 9. 用户资料忠实度

用户提供Prompt工程资料、教程、模板或案例时：

1. 先读取相关原文；
2. 原资料结构、主体提示、负面约束和输出方式作为主要依据；
3. 当前项目设定用于填充模板；
4. 自行补充的方法明确标记；
5. 不得把自由扩写冒充原资料内容。

原资料中的三视图、综合角色板、场景空镜和道具三视图作为可选模板保留。

## 10. 分镜设计合同

每个镜头至少明确：

```yaml
shot:
  goal:
  references: []
  input_state:
  static_start_moment:
  primary_action:
  shot_size:
  lens_or_equivalent:
  camera_height_and_distance:
  angle_axis_and_screen_direction:
  foreground_midground_background:
  composition:
  movement_and_motivation:
  focus_plan:
  lighting_plan:
  duration:
  exact_end_state:
  next_shot_inheritance:
  sound_relation:
  edit_connection:
  risk:
```

每镜只承担一个主要重点。没有叙事动机的运镜使用固定镜头。

## 11. 分镜帧Prompt合同

第一张分镜通常使用：

```text
角色参考 + 场景空镜 + 必要道具参考 + 当前镜头要求
```

后续分镜优先使用：

```text
角色参考 + 场景空镜 + 上一张满意分镜 + 当前镜头要求
```

图片Prompt只描述一个准确静态瞬间，并明确前中后景、人物和道具位置、焦段机位、焦点景深、曝光、白平衡、当前镜头具体灯光、材质、连续性和负面约束。

摄影、光学、灯光和材质必须写进最终可复制正向Prompt。每镜必须设计`END_FRAME_CONTRACT`，尾帧是否预生成由生成模式和下一镜连续性决定。

## 12. 视频生成模式选择

### 单首帧图生视频

只允许用于呼吸、眨眼、轻微布料、雨、水波等低幅度运动，并且下一镜不依赖准确姿势、手部、道具位置、焦点或构图。仍必须提供完整`END_FRAME_CONTRACT`并抽取稳定尾帧。

### 首尾帧视频

人物或道具状态变化、动作终点重要、下一镜需要继承、运镜改变最终构图或单首帧容易随机结束时，默认使用首尾帧。

### 抽尾帧续拍

第一段稳定尾帧作为下一段唯一首帧，只继续未完成动作。

### 两段硬切、遮挡切换与分层合成

构图变化大、多种状态同时变化、遮挡前后需要切换或精确手部持续失败时分别生成再剪辑。镜面人物、倒影、雾气、精确文字和复杂状态优先拆层。

## 13. 导演级视频Prompt合同

每镜完整Prompt必须包含：输入帧与生成模式、场景空间和前中后景、主体起始状态、分秒动作时间轴、动作物理、摄影机参数与运动时间轴、焦点景深曝光、逐镜灯光合同、色彩材质、环境动态、精确结束帧、下一镜继承、声音、稳定项和负面约束。

禁止把“电影感、真实光照、缓慢推进”当成完整视频Prompt。

## 14. 摄影、光学与逐镜灯光合同

每镜必须写清焦段、机位高度和距离、景别、角度、轴线、运镜时间、方向、速度、幅度和终点。

必须写清景深、起始焦点、焦点变化、结束焦点、曝光、白平衡、高光、暗部、运动模糊和镜头呼吸限制。

每条最终视频Prompt必须包含真实主光来源、世界空间方向、相对人物方向与高度、色温、软硬、强弱、亮区、阴影、辅光、实景灯、光比、高光暗部策略和前后镜连续性。

只写“冷色调、真实光照、电影感”直接判定失败。

## 15. 母参考与生产状态合同

每个需要长期继承的角色、场景、道具或特殊状态只选择一个当前**唯一母参考**。不得在后续镜头中混用多个相似候选。

项目状态只能根据实际证据标记：

```text
DESIGN_READY
PROMPT_READY
REFERENCE_READY
SAMPLE_VALIDATED
BATCH_GENERATION_READY
EDIT_READY
DELIVERY_READY
```

- Prompt已经写完但图片未生成：最多是`PROMPT_READY`；
- 真实母参考已经选定：才能是`REFERENCE_READY`；
- 实际普通样片和必要高风险样片通过验收：才能是`SAMPLE_VALIDATED`；
- 所有必要镜头已有通过版本：才能是`EDIT_READY`；
- 剪辑、声音、文字、调色和最终检查完成：才能是`DELIVERY_READY`。

没有实际媒体证据时不得声称样片已通过、可批量生产、可剪辑或项目完成。

## 16. 代表性样片与批量生成门槛

默认测试一个来自正片的普通镜头。项目确有镜面、变形、复杂手部、多人同步、遮挡切换或复杂运镜时，再测试最多一个真实高风险镜头。

样片必须使用实际首帧、尾帧、桥接帧和真实生成方案。审核至少检查身份与道具连续性、动作物理、摄影机、焦点、曝光、灯光、尾帧可达性和可剪辑性。

实际样片使用`evals/shot-output-acceptance-score.md`验收。存在硬失败时不得无差别批量生成整片。

## 17. 失败分层与资产升级

片段失败后先区分：

- `REFERENCE_FAILURE`：母参考本身不足；
- `CONTROL_FRAME_FAILURE`：首帧、尾帧或桥接帧已有错误；
- `PROMPT_FAILURE`：动作、时间轴、摄影机或灯光指令冲突；
- `MODEL_CAPABILITY_FAILURE`：模型无法处理多状态、手部、镜面或长动作；
- `POST_PRODUCTION_FAILURE`：文字、雾气、镜面层、声音或颜色更适合后期。

修复顺序：简化Prompt或动作、修复控制帧、固定机位、缩短片段、补尾帧或续拍、遮挡切换或分层合成，最后才新增参考资产。

新增面部、全身、手部、第二场景角度或特殊状态参考，必须由已经观察到且可复现的具体失败触发。不能用无限增加资产解决模型能力问题。

## 18. 生产队列、候选版本与镜头验收

生产顺序默认是：

```text
唯一母参考
→ 代表性镜头首尾帧
→ 普通样片与必要高风险样片
→ 修复薄弱层
→ 按依赖生成剩余控制帧
→ 连续剧情镜头
→ 独立空镜、插入镜头和结尾镜头
→ 分层合成、文字、声音、调色和剪辑
```

镜头生产顺序不必等于叙事编号顺序。依赖上一镜尾帧的镜头必须连续生产。

每个镜头建立版本台账，记录生成模式、母参考、首尾帧、Prompt版本、候选文件、验收分数、失败维度、修复动作和剪辑连接。

选择候选时优先级：

```text
叙事和尾态正确
> 身份、场景和道具连续
> 手部和物理可信
> 摄影机、焦点和灯光稳定
> 可剪辑性
> 单帧美观
```

只有通过真实镜头验收的版本才能进入最终时间线。

## 19. 剪辑、后期与最终交付

生产包必须明确每镜选用版本、入点出点、硬切或匹配方式、遮挡切点、分层合成、后期文字、声音、调色、最终时长和导出设置。

精确文字、复杂镜面、倒影、薄雾和声音不稳定时转入后期，不强迫一个生成模型一次完成。

进入`DELIVERY_READY`前必须复核故事忠实度、身份服装、空间道具、摄影焦点、灯光曝光、镜头连接、文字图形、声音音乐、节奏时长和导出规格。

## 20. 交付与“下一步”合同

根据用户请求直接输出当前需要的完整结果。进度卡和内部阶段编号不强制展示。

当前完整交付结束后，用户说“下一步”表示进入下一个相关交付物，不是下一张图、下一个资产或下一个镜头。Prompt包完成后的下一项通常是实际母参考筛选和代表性样片计划，而不是继续无限编写Prompt。

## 21. 硬失败

- 剧本完成后无法继续下游生产；
- 普通短片默认建立庞大资产库；
- 默认密集多视图或固定拆分角色资产；
- 摄影、灯光和材质没有写入最终正向Prompt；
- 要求用户自行拼接多个Prompt字段；
- 未读取用户资料却声称严格按资料生成；
- 静态Prompt描述多个连续动作；
- 视频Prompt没有画面空间、逐镜灯光、焦点和结束帧；
- 使用单首帧但下一镜依赖精确尾态；
- 每镜没有结束帧合同；
- 运镜没有时间、幅度和终点；
- 没有实际生成结果却声称样片已经通过；
- 只有Prompt包却声称项目已经可剪或完成；
- 未选定唯一母参考就混用多个候选；
- 代表性样片失败后仍直接批量生成整片；
- 未通过验收的片段直接进入最终时间线；
- 为降低难度改变人物选择、高潮或结尾；
- 把用户变成逐资产、逐镜头确认操作员。
