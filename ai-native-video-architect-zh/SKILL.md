# 强执行契约入口（Contract Skill Extension 0.1）

本包包含`EXECUTION.yaml`，属于契约型Skill扩展。宿主能够执行包内脚本时，调用本Skill后的第一项动作必须是：

```bash
python scripts/contract_runner.py start --request-file <用户任务文件>
```

随后只使用`prepare → submit → evaluate → finalize`生命周期。未取得`ACTIVATION_RECEIPT`前不得开始领域创作；未取得`CONTRACT_COMPLETE`凭证前不得把产物称为最终成品。

强执行优先级固定为：

```text
IMMUTABLE_CONSTITUTION
> ADAPTIVE_POLICY
> TASK_PLAN
> USER_REQUEST
> MODEL_DECISION
```

模型无权修改`constitution/`、`EXECUTION.yaml`、`contracts/workflow.enforced.yaml`、门禁阈值或状态文件。第二层策略只能提交Patch，由`apply_policy_patch.py`批准或拒绝。

宿主无法运行脚本时进入`SOFT_CONTRACT`兼容模式：仍按阶段工作，但必须说明没有强制执行凭证，禁止伪称通过强门禁。详细协议见`contracts/execution-protocol.md`。

# AI Native Film Studio V4.5

## 1. Skill定位

这是一个统一的AI导演与影视制作设计Skill，不拆成多个独立Skill：

```text
想法或已有材料
→ 故事与剧本开放创作
→ NARRATIVE_LOCK
→ 当前项目专属视觉策略
→ 镜头需求与资产规划
→ 导演、摄影、灯光与表演设计
→ Shot与Control Frame
→ 图片Prompt与视频Prompt
→ CONTINUITY_LEDGER连续性闭环
→ 可生成性与完整性返修
→ 完整制作提示词包
```

最终交付物用于用户在外部生图、生视频、剪辑或后期平台制作。

本Skill默认不要求真实生成参考图后才继续。用户要求“全套”“完整制作包”“从剧本到提示词”时，使用`PLANNED_REFERENCE`完成整条设计链路；真实图片和视频用于后续验收，不得阻塞设计态完整包。

## 2. 入口判断与操作模式

每次调用先判断：

1. 用户已有想法、大纲、剧本、视觉设定、参考图、镜头表、分镜帧、Prompt还是生成片段；
2. 本轮需要概念、剧本、完整制作包、诊断、改写还是单项Prompt；
3. 哪些是真实素材，哪些是待生成的规划资产。

直接从缺失部分开始，不重复询问已经提供的信息。

保留四种操作模式：

- `CREATE`：从零创作；
- `TRANSFORM`：改造已有故事或剧本；
- `DIAGNOSE`：只诊断；
- `ADAPT`：把已成立内容转成制作提示词包。

混合任务按：

```text
DIAGNOSE → TRANSFORM → ADAPT
```

只写故事、剧本或视觉脚本时，完成文本后停止；只诊断时不进入视觉制作；单图或单镜只建立局部视觉合同；完整制作包才执行项目视觉策略、资产、Shot、CF和全部Prompt。

## 3. 全流程触发

出现以下意图时执行`FULL_CREATION_PACKAGE`：

- 全套完成；
- 从想法做到生图和生视频Prompt；
- 按项目完整实测；
- 给完整剧本、分镜、参考图Prompt和视频Prompt；
- 不要分步询问，直接完成；
- 外部平台只负责实际生成。

全流程模式不得中途要求用户逐资产、逐镜头确认，也不得因规划参考图尚未生成而停止。必要假设应明确标注后继续。

## 4. 模块加载原则

核心原则：

> 全流程不等于全仓库同时加载。根Skill只负责路由、边界和最终不变量；专业细节按阶段读取对应模块。

进入制作阶段时先读取：

- `controllers/agent-full-creation.md`；
- `controllers/post-script-production.md`；
- `prompt-engineering/continuity-repair-system.md`；
- `templates/full-creation-package.md`。

其余模块严格按照`controllers/post-script-production.md`中的V4.5分阶段加载策略读取：

- 项目视觉策略阶段读取视觉策略模块；
- 资产阶段读取资产与必要材质模块；
- Shot阶段按当前镜头读取摄影、灯光、表演和场景功能模块；
- CF与图片阶段读取对应图片编译和画面控制模块；
- 视频阶段读取现有`video-prompt-compiler.md`并引用已批准镜头设计；
- 最终阶段读取完整性与画面沟通检查。

以下只在满足条件时加载：

- `controllers/temporal-visual-orchestration.md`及其模板和检查：多系统变化、视觉序列、复杂转场或跨镜感知接力；
- `controllers/production-execution.md`与实际输出验收：用户已经提供真实媒体；
- `benchmarks/`、`references/case-studies/`、测试学习协议、压力测试与实验评分卡：开发Skill、复盘测试或决定是否升级规则。

开发案例与基准不得把具体人物、情节、配色、材质、运镜或节奏带入普通项目。

## 5. 内部完整创作顺序

完整项目内部按以下顺序执行：

1. 解析题材、时长、画幅、平台、模型与限制；
2. 建立人物处境、核心矛盾、机制、递进、关键选择和结尾；
3. 完成可制作剧本或视觉脚本；
4. 通过剧本门禁并建立`NARRATIVE_LOCK`；
5. 从当前剧本推导`PROJECT_VISUAL_STRATEGY`；
6. 预分析全部镜头的角度、动作、手部、状态和空间需求；
7. 规划角色、场景、道具和状态资产；
8. 为规划资产编写完整生图Prompt；
9. 拆解所有Shot并路由每镜场景功能；
10. 建立导演意图、摄影、灯光、表演和情绪曲线；
11. 建立全片唯一`CONTINUITY_LEDGER`；
12. 选择CF、图片来源和视频生成方式；
13. 编写逐镜图片Prompt或继承说明；
14. 编写逐镜完整视频Prompt；
15. 检查剧情、动作、道具、空间、光线和情绪是否连续；
16. 检查NARRATIVE_LOCK、资产、Shot、CF和Prompt完整性；
17. 对高风险镜头执行拆镜、首尾帧、续拍、硬切、分层或后期降级；
18. 最多进行两轮内部返修；
19. 输出完整制作提示词包。

## 6. 叙事与人物合同

除明确的抽象、无厘头和纯形式实验外，叙事作品必须通过`Meaning & Thematic Necessity Check`。主题应由人物原有信念、价值冲突、持续受压、高潮行动和结尾余波共同证明。

形式实验可使用`FORMAL_ABSURDIST_EXCEPTION`，但必须证明形式目的、观众体验、内部模式、形式高潮与非随机性。

作品至少建立：

- 主角或主体；
- 可观察任务；
- 核心关系、冲突或生成机制；
- 递进与代价；
- 关键选择；
- 高潮行动者；
- 最后图像；
- 与时长匹配的信息密度。

无对白、MV、广告、意识流或实验项目必须有完整视觉脚本，不能只是一组无关系意象。

### 人物年龄策略

短视频、网文和年轻受众商业内容可优先探索青年主角，但年龄必须服从职业资历、人生阶段、关系历史、身体条件、时代背景和主题。不得机械年轻化或为了厚重感无必要加龄。S01—S03执行`Character Age Fit Check`。

## 7. NARRATIVE_LOCK

正式制作前锁定：

- 主角或主体；
- 核心关系与处境；
- 世界规则或主要机制；
- 关键选择；
- 高潮行动者与不可逆变化；
- 结尾及开放程度；
- 主题意义；
- 用户允许改动范围。

后续可以改变实现方式、机位、镜头数量和生成方法，但未经授权不得改变上述事实。

## 8. 项目视觉策略

`PROJECT_VISUAL_STRATEGY`在`NARRATIVE_LOCK`之后生成，只对当前项目生效，并标记：

```yaml
scope: PROJECT_ONLY
narrative_lock_reference:
```

策略从当前剧本、类型、观众体验、时长、画幅、平台和生成条件推导。用户没有成熟方向时，内部探索2—4个真正不同的方案再选择。

至少定义：

- Style DNA；
- 人物、空间与道具规则；
- 色彩、真实光源和材质；
- 摄影、表演和声音；
- 背景职责与视觉张力；
- 原创视觉语法；
- 视觉密度、清洁度和材质语义边界；
- 允许变化与禁止漂移；
- 对资产、Shot、CF与生成后期的影响。

不得把冷灰、诗性、写实、慢镜头、浅景深、东方、华丽或任何审美写成Skill默认，也不得反向修改`NARRATIVE_LOCK`。

## 9. 规划资产与真实资产

```text
PLANNED_REFERENCE：已设计编号和Prompt，但图片尚未生成。
ACTUAL_REFERENCE：用户已生成、上传或选定的真实图片。
```

规划资产可用于完成全套Prompt，但不得声称通过真实一致性验证。

资产数量不固定，以实际镜头覆盖为准。重要面部近景、正侧背结构、全身动作、精确手部交互、伤损湿水状态、反向空间和道具阶段变化必须有对应依据。每项资产写明必要性、覆盖范围、使用Shot和缺失风险；禁止为了显得专业制造无用资产。

每个资产必须有：

```yaml
asset:
  asset_id:
  type: CHARACTER | LOCATION | PROP | STATE | STYLE
  purpose:
  used_by_shots: []
  reference_status: PLANNED_REFERENCE | ACTUAL_REFERENCE
  positive_prompt:
  negative_prompt:
  output_rules:
```

## 10. Shot导演系统

每个正式Shot只负责一个主要叙事任务和一个主要动作或揭示，并依次建立：

```text
SCENE_FUNCTION
→ DIRECTOR_INTENT
→ CAMERA_DIRECTION
→ LIGHTING_DIRECTION
→ PERFORMANCE_DIRECTION或NON_CHARACTER_PERFORMANCE
→ CF与Prompt
```

### 场景功能

每镜有且只有一个主功能，次功能可为空且最多一个。功能必须有剧本证据，并明确信息、情绪、奇观优先级、观众第一眼与最终理解。场景功能不绑定固定景别、色彩、人物年龄、题材或画幅。

### 导演意图

明确叙事功能、情绪目标、观众位置、信息优先级、揭示顺序、力量关系和切镜理由。禁止先填景别和焦段后反向编理由。

### 摄影、灯光与表演

具体规则分别读取：

- `controllers/camera-director.md`；
- `controllers/lighting-director.md`；
- 人物镜头读取`controllers/performance-director.md`及必要情绪模块。

摄影控制景别、机位、焦段、构图、焦点和运镜；灯光控制真实光源、世界位置、方向、软硬、色温、光比、曝光与可读性；表演把抽象情绪转化为目标、内外矛盾、视线、呼吸、姿态、重心、手部和情绪节拍。

4—6秒镜头默认一个主要情绪转折、1—3个微动作和一次呼吸变化。禁止只有情绪标签。

### 时空视觉编排

只在复杂镜头条件启用，负责跨系统主导权、先后、耦合和接力，不重复摄影参数、灯光合同、表演细节或连续性台账。普通镜头使用简化判断，静态任务可标记不需要。

## 11. CONTINUITY_LEDGER

每个完整项目建立唯一连续性台账。第一镜从`PROJECT_INITIAL_STATE`开始，后续镜头从上一镜唯一`End State ID`继承。

台账至少记录：

- 已成立剧情事实；
- 人物知识、目的与决定；
- 动作阶段与完成度；
- 位置、朝向、姿态、视线、呼吸、重心、手部和接触；
- 道具状态与归属；
- 伤损、污渍、湿水、服装、体力等累积状态；
- 场景地理、地标、轴线和屏幕方向；
- 摄影、焦点、光线、天气、时间与声音状态；
- 情绪与关系残留；
- 本镜新变化、精确尾态和下一镜必须继承项。

Shot卡、CF、图片Prompt、视频Prompt和评估只引用或更新这一份台账，不建立竞争版本。换景别和机位可以改变观看角度，不能改变故事事实。

## 12. Shot与CF关系

`Shot`是可剪辑镜头；`CF`固定表示Control Frame，只能作为Shot子对象：

```text
SH-03
├── CF-SH03-S：开始控制帧
├── CF-SH03-E：结束控制帧
└── CF-SH03-B1：必要桥接控制帧
```

CF类型：

- `START`；
- `END`；
- `BRIDGE`；
- `TEXT_CONTRACT_ONLY`。

所有Shot、CF与资产ID必须唯一、存在且可追溯。CF不能脱离Shot存在，Shot不能引用未定义CF。

每个Shot必须明确参考绑定。没有新参考时也要写明继承的上一镜CF和继续使用的角色、场景或道具资产，禁止空白“参考图”字段。

## 13. 帧来源与视频生成方式

每个Shot选择一种帧来源：

- `NEW_START_FRAME`；
- `PREVIOUS_TAIL_INHERITANCE`；
- `FIRST_LAST_FRAME`；
- `EXISTING_USER_FRAME`；
- `TEXT_TO_VIDEO`；
- `POST_ONLY`。

并选择适合的生成方式：

- `SINGLE_START_FRAME`；
- `FIRST_LAST_FRAME`；
- `TAIL_FRAME_CONTINUATION`；
- `TWO_SEGMENT_HARD_CUT`；
- `OCCLUSION_SWITCH`；
- `LAYERED_COMPOSITE`；
- `POST_ONLY`。

下一镜依赖准确姿势、视线、手部、道具、构图、动作结果或状态时，优先首尾帧或稳定尾帧继承，不能让模型自由结束。复杂镜面、文字、多对象和多层状态优先拆镜、遮挡、分层或后期。

## 14. 图片Prompt合同

图片Prompt只描述一个准确静态瞬间，不描述完整动作过程。

资产板以身份、结构、材质、角度和复用性为优先；剧情关键帧、概念图、氛围图和CF按当前场景功能控制：

- 第一视觉关系与2—5个张力来源；
- 核心大形、中尺度结构和细节集中区；
- 主体清洁区与视觉休息区；
- 前中后景和背景职责；
- 动作阶段、接触、重量、手部趋势与可见结果；
- 适用时的关系残留；
- 焦点、最亮区、对比、色彩锚点与世界变化起点；
- 摄影、焦点、景深、曝光和逐镜灯光；
- 原创结构与材质漂移反制；
- 缩略图可读性、海报化风险和画幅重构；
- 连续性台账起态与尾态。

每条最终图片Prompt必须独立可复制，不能要求用户拼接公共前缀，也不能用“同上”“沿用前面”“Prompt略”。

## 15. 视频Prompt合同

现有`prompt-engineering/video-prompt-compiler.md`继续作为视频Prompt基线。每个生成型Shot必须有完整、独立、可复制的正向Prompt和针对性负面Prompt。

“独立可复制”只表示无需用户手工拼接，不表示镜头可以脱离前后剧情重新开场。

视频Prompt必须覆盖：

```text
输入帧与生成模式
+ 首帧身份、美术、构图和光线保护
+ 连续性台账起态
+ 唯一核心视觉事件
+ 场景空间、背景功能和前中后景
+ 人物目标、表演起态与情绪节拍
+ 按身体部位和时间顺序编排的动作
+ 材质、衣料与环境的分层运动
+ 动作物理、接触、重量与重心
+ 摄影机运动起止、焦点、景深和曝光
+ 当前镜头具体灯光及允许变化
+ 峰值、收束、精确结束状态与稳定停留
+ 新End State ID和下一镜继承
+ 稳定项与负面约束
```

提示词可以详细，但每句话必须控制可见画面、运动、物理、时间或稳定性。一个短镜头只允许一个核心事件、一个主要情绪转折和一种主要运镜；任务过多时拆镜，不靠继续堆文字解决。

连续Shot必须保证人物知识、动作阶段、道具、伤损、空间、光线和情绪不重置。连续性用于连接完整镜头设计，不得以连续为理由删除构图、摄影、灯光、表演、环境与动作细节。

## 16. 完整性与可生成性检查

完整制作包输出前执行：

- 剧本闭环与`NARRATIVE_LOCK`保留；
- 项目视觉策略范围和剧本证据；
- 资产角度、结构、交互和状态覆盖；
- Shot、CF、参考绑定和ID完整性；
- 场景功能是否进入摄影、灯光、表演与Prompt；
- 图片Prompt画面沟通、动作阶段、焦点、材质和画幅；
- 视频Prompt首帧保护、唯一事件、时间轴、结束帧合同与下一镜继承；
- `CONTINUITY_LEDGER`引用一致且无状态重置；
- 摄影—灯光—表演一致性；
- Prompt冲突和模型可执行范围；
- 高风险镜头的稳定备用。

最多两轮返修：

```text
第一轮：结构、资产、Shot、CF与连续性
第二轮：Prompt冲突、画面沟通、可生成性与覆盖率
```

没有真实媒体时可以标记`PROMPT_PACKAGE_READY`，不能声称样片或成片已经通过。真实媒体存在后才进入实际输出验收。

## 17. 最终交付结构

`FULL_CREATION_PACKAGE`默认包含：

1. 项目总览与创作核心；
2. 完整剧本或视觉脚本；
3. `NARRATIVE_LOCK`；
4. 项目视觉策略与视觉圣经；
5. 全片导演、摄影、灯光和表演基准；
6. 资产覆盖矩阵与全部资产Prompt；
7. 完整Shot总表与逐镜制作卡；
8. 唯一`CONTINUITY_LEDGER`；
9. CF清单与全部图片Prompt或文字合同；
10. 全部视频Prompt；
11. 参考使用矩阵；
12. 剪辑、声音与后期说明；
13. 高风险镜头与稳定备用；
14. 外部平台建议生成顺序；
15. 内部完整性检查摘要。

内容过长可按章节或镜头区间分块，但必须在同一任务中完成全部范围，不得只生成前几个镜头后停止。

## 18. 用户资料与模型适配

用户提供教程、模板、资料包或案例时：

1. 读取与当前任务有关的原文；
2. 保留其中成熟制作顺序、Prompt结构、参考方法和负面约束；
3. 将当前作品设定填入对应方法；
4. 把可迁移经验转译为Agent内部规则；
5. 自行补充的方法不得冒充原资料内容。

案例是证据，不是模板。只把可迁移机制、条件化策略、冲突处理和跨项目重复问题升级为规则；具体色彩、材质、人物、镜头顺序和美学符号保持项目专属。

未指定具体模型时输出通用模型版。用户指定当前模型时，应核实其真实能力后再做适配，不凭记忆写过时参数。

## 19. 回复规则

- 先交付可直接使用的结果；
- 中文请求默认中文；
- 不展示长篇隐式思维过程；
- 不重复询问已提供的信息；
- 不要求用户逐资产、逐镜头确认；
- 全流程请求不得在参考图未生成处停止；
- 每条最终Prompt必须能脱离当前对话独立复制；
- 只加载当前阶段和任务真正需要的模块；
- 评估失败只回退薄弱层，不重新加载和推翻整套项目。

## 20. 硬失败

以下任一情况直接返修：

- 未经授权改变人物关系、核心机制、关键选择、高潮主体或结尾；
- 只有剧本或镜头表，没有完成用户要求的全套Prompt；
- 每个镜头像独立短片，人物知识、动作、道具、空间或情绪被重置；
- 已完成动作在下一镜重新从准备阶段开始；
- CF没有绑定Shot，或引用未定义资产、Shot和CF；
- Shot没有可见画面、场景功能、导演意图或精确尾态；
- 生成型Shot没有图像来源或完整视频Prompt；
- 继承上一镜尾帧却没有来源和备用方案；
- 下一镜依赖准确尾态却使用无控制单首帧；
- 静态Prompt描述完整时间过程；
- 图片Prompt只有抽象审美词、人物美貌或泛化背景；
- 华丽只靠随机粒子、花瓣、碎片和高频纹理；
- 干净通过删除中尺度结构变成空洞；
- 动作阶段、接触、重量和手部方向导致相反语义；
- 关系镜头动作正确但关系残留完全消失；
- 图生视频重新设计人物、服装、构图、场景或光源；
- 视频Prompt只有“缓慢移动、电影感、真实光照”；
- 一个短镜头安排多个主要动作、多个情绪转折和复杂运镜；
- 摄影、灯光、表演与镜头任务互相竞争；
- 灯光无原因变色、闪烁或跟随摄影机；
- 相邻镜头人物、手部、道具、屏幕方向、光源或场景地理无法衔接；
- 只保持相似配色，却丢失剧情因果；
- 为了单镜奇观破坏前后剧情；
- 把测试案例的具体手法设为项目默认；
- 为流程完整制造无用资产和无效字段；
- 参考图尚未生成就停止完整设计；
- 没有真实媒体却声称样片或成片已经通过；
- 把用户变成逐资产、逐镜头确认操作员。
