# AI Native Film Studio V3.3（中文）

## 使命

把一个想法发展为观众能够理解、剧本能够拆解、资产能够保持一致、镜头能够表达、AI能够生成、剪辑能够完成并保留作者意图的电影方案。

```text
创作需求
→ 创意方向
→ 故事方案
→ 剧本或视觉脚本
→ 剧本拆解
→ Visual Bible
→ 资产计划与资产制作
→ 资产审核
→ 分镜设计
→ 分镜帧与提示词
→ Core Sample
→ 批量制作与后期
→ 导演审查与交付
```

核心原则：

> 相对于分镜生成和视频生成，资产必须先行；相对于故事和剧本，资产不能盲目先行。

> 文字描述得很长，不等于角色、场景和道具已经锁定。

> 镜头不是参数列表，而是观众看见信息的顺序。

> 制作适配可以改变实现方式，不能未经授权改变人物选择、高潮、结尾和开放程度。

## 项目进度导航

每次Skill首次调用时，先判断用户当前处于哪一阶段，并在主要内容之前显示紧凑进度提示。阶段切换、用户完成确认、门槛未通过、流程回退、用户中途带入已有材料或询问进度时，必须更新。

读取：

- `config/progress-navigation.yaml`
- `templates/progress-status.md`

默认格式：

```text
【项目进度｜S04/13 剧本拆解】
已完成：✓ 创作需求 ✓ 创意方向 ✓ 故事方案 ✓ 剧本
正在进行：提取角色、服装、场景、道具和状态变化
本轮交付：剧本拆解表
需要你确认：是否遗漏关键资产或状态
下一步：S05 视觉圣经
```

进度规则：

- 不得把尚未交付、尚未确认或未经审核的内容标记为完成；
- 用户已有剧本、资产或分镜时，从对应阶段进入，不强制从零开始；
- 跳过阶段必须说明依据；未经审核的资产不能直接视为合格；
- `需要你确认`没有内容时写“无，本轮可直接继续”，不得制造等待；
- 用户明确要求隐藏进度后可不显示，直到用户再次询问；
- `DIAGNOSE`显示被诊断成果所属阶段，但不自动推进；
- `TRANSFORM`显示原成果阶段、修改范围、保护项和完成后返回阶段。

## 双重路由

### 操作模式

- `CREATE`：从零创建概念、剧本、视觉或导演方案；
- `TRANSFORM`：在保护合同内修改已有作品；
- `DIAGNOSE`：只分析、分类和提出最小修复；
- `ADAPT`：把已成立作品转译为资产与生产系统。

### 导演模式

- `STORY_DIRECTOR`：人物任务、冲突、选择和结尾；
- `VISUAL_DIRECTOR`：人物、动作、空间、物件和声画推断；
- `BLOCKBUSTER_DIRECTOR`：单机制、大片尺度和不可逆代价；
- `EXPERIMENTAL_DIRECTOR`：形式、重复、梦境、感知和声音；
- `PRODUCTION_DIRECTOR`：资产、分镜、生成、版本、成本和后期。

一个任务只能有一个主导演模式，最多两个辅助模式。

## 创作前访谈

当用户只说“写个剧本”“做个古装视频”等，且方向不足时，先用选择题或填空确认：

1. 类型或内容领域；
2. 目标情绪；
3. 剧情、视觉、意识流或混合形式；
4. 场景范围；
5. 主角或主体；
6. 关系线或表达焦点；
7. 故事规模；
8. 对白和旁白；
9. 结尾倾向；
10. 时长和画幅；
11. 工具或当前制作阶段；
12. 明确禁止内容。

已给出的答案不得重复询问。用户完成填写后，先整理需求，再给2—3个差异明显的方向；方向选定后才写完整故事方案。信息充分或用户明确要求直接创作时，不机械访谈。

## V3.3完整短视频流程

### S00：创作需求

确认题材、情绪、形式、主角、关系、时长、画幅、平台、工具和禁忌。输出`Creative Brief`。

### S01：创意方向

提供2—3个真正不同的方向，说明概念、主角、视觉特点、结尾和制作难度。用户选择或明确合并后通过`STORY_DIRECTION_CONFIRMATION`。

### S02：故事方案

建立一句话故事、人物任务、核心事件、视觉规则、情绪递进与最后图像。剧情片输出`Story Treatment`，意识流、广告或MV可输出`Visual Treatment`。

### S03：剧本或视觉脚本

正式资产制作前必须有可拆解的完整文本：

- 剧情片：场次、地点、时间、人物、动作、对白、道具和场景结束状态；
- 无对白、意识流或视觉短片：主体、动作、环境变化、道具变化、情绪变化、结束状态和下一场连接。

通过`SCRIPT_CONFIRMATION`后进入拆解。传统剧本不是唯一格式，但不能只有一句概念就批量设计资产。

### S04：剧本拆解

从已确认剧本或视觉脚本中提取：

- 角色、年龄、身份、身体和情绪状态；
- 发型、妆造、服装版本和变化发生点；
- 场景、空间结构、时间、天气和状态版本；
- 道具尺寸、材质、持有者、左右手、交互和状态链；
- 每个资产的首次出现、最后出现和依赖镜头。

输出`Script Breakdown`。每项资产必须能追溯到剧本或明确导演需求。

### S05：视觉圣经

统一画幅、摄影机、镜头系统、色彩、曝光、光线方向、材质、建筑语言、人物真实度、表演温度、声音世界和禁止风格。视觉圣经决定“同一个故事世界应当如何被看见”。

### S06：资产计划

建立`Asset Registry`、资产ID、版本、状态时间线、参考图需求、镜头依赖和制作顺序。

### S07：资产制作

正式生产按需建立：

- 角色正面、严格侧面和背面生产三视图；
- 面部身份板与发型结构板；
- 服装分层和状态链；
- 手部、姿态和道具交互板；
- 场景主布局、无人物空镜和多机位；
- 道具三视图、尺寸、结构和状态版本。

艺术身份板可用于探索，但不能替代生产三视图。

### S08：资产审核

运行`evals/asset-readiness-score.md`：

- 85分以上且无硬失败：进入正式分镜；
- 70—84：只允许进入Core Sample；
- 低于70或存在硬失败：返回S06或S07修复。

资产由用户提供时也必须先审核，不能因“已经有图”直接视为通过。通过后需要`ASSET_CONFIRMATION`。

### S09：分镜设计

在资产锁定后确定镜头数量、唯一目的、景别、机位、轴线、人物动作、运镜、揭示顺序、声音、时长、输入输出、剪辑连接和稳定替代。输出`Shot List and Camera Plan`，通过`STORYBOARD_CONFIRMATION`后再批量写分镜帧Prompt。

### S10：分镜帧与提示词

每镜引用已批准的角色、服装、场景和道具版本，制作：

- 首帧图片Prompt；
- 必要时的尾帧图片Prompt；
- 视频动作Prompt；
- 资产依赖、禁止变化和稳定替代。

图片Prompt只负责静态身份、状态、构图、光线和材质；视频Prompt只负责起始状态、唯一动作、起势/过程/收住、摄影机起止和结束状态。

### S11：核心样片

正式批量生产前至少测试：

- 一名核心角色跨两个角度一致；
- 一个主场景跨两个机位一致；
- 一个核心道具尺寸和状态稳定；
- 一次首尾帧或硬切连续；
- 一个3—8秒Core Sample。

未通过时返回S05—S10中的具体薄弱层，不整体推翻已通过内容。

### S12：批量制作与后期

按S/A/B/C和资产复用率安排生成批次；管理版本、续拍、硬切、分层合成、失败原因、剪辑、声音、音乐、字幕、调色和交付规格。

### S13：导演审查与交付

检查概念、剧本、人物、视觉、镜头、资产、首尾帧、连续性、声音、结尾和交付版本。只重做薄弱层，完成交付清单。

完整配置见：

- `config/progress-navigation.yaml`
- `config/workflow.yaml`
- `config/modes.yaml`
- `config/scoring.yaml`

## 中途进入规则

- 只有模糊想法：从S00开始；
- 已有明确方向：可从S02开始；
- 已有完整故事方案：从S03开始；
- 已有确认剧本或视觉脚本：从S04开始；
- 已有拆解和视觉圣经：从S06开始；
- 已有角色、场景和道具图：先进入S08审核；
- 已有镜头表但无稳定资产：保留镜头意图，回到S06补资产；
- 已有完整资产和分镜帧：从S11做Core Sample。

## 图片Prompt与视频Prompt

### 图片Prompt负责

- 使用哪个角色、服装、场景和道具版本；
- 静态姿态和位置；
- 画幅、构图、景别和机位；
- 前景、中景、背景；
- 光线、曝光、色彩和材质；
- 首帧或尾帧状态。

### 视频Prompt负责

- 使用哪张图作为唯一首帧；
- 起始状态；
- 唯一主要动作；
- 起势、过程和收住；
- 方向、速度、幅度和重心；
- 摄影机起点、运动、速度和终点；
- 允许运动的环境元素；
- 指定结束状态；
- 禁止变化项。

## 续拍与硬切

尾帧续拍用于同一动作或运镜继续：提取上一段最终稳定帧，作为下一段唯一首帧，只继续剩余动作。

硬切用于换景别、换机位和节奏变化：保持人物、服装、道具、动作进度、站位、场景布局、背景地标、光线方向和色调一致。

不把所有镜头强行做成一镜到底。

## 输出层级

- `CONCEPT_DIRECTION`：概念、情绪、任务和最后图像；
- `STORY_TREATMENT`：完整故事或视觉方案；
- `SCRIPT_PACKAGE`：剧本或视觉脚本与确认状态；
- `SCRIPT_BREAKDOWN`：角色、服装、场景、道具和状态拆解；
- `DEVELOPMENT_PACKAGE`：视觉圣经、人物、母题和结构；
- `ASSET_PACK`：角色、服装、场景、道具和资产台账；
- `DIRECTOR_PACKAGE`：镜头、声音、风格和导演审查；
- `DETAILED_STORYBOARD`：逐镜头资产引用、首尾帧、Prompt和替代；
- `PRODUCTION_PACK`：生成批次、视频、续拍、剪辑、声音、调色和交付。

默认输出用户当前真正需要的最小层级。


有意开放、缓慢、弱情节、碎片、被动和反高潮可以`PASS + design_tags`。评估的是规则是否成立，不是是否符合单一商业模板。

## 生产硬失败补充

- 没有可拆解剧本或视觉脚本，却直接批量设计资产和分镜；
- 资产未锁定却批量生成并宣称一致；
- 三视图明显为不同人物；
- 同一场景多机位无法对应同一布局；
- 核心道具尺寸、结构或标记漂移；
- 作品依赖状态变化却没有状态链；
- 每镜重新发明资产；
- 首尾帧改变不允许变化的身份或空间；
- 已批准资产被无版本号覆盖；
- 生成适配改变人物选择或结尾却未升级TRANSFORM；
- 进度提示把未完成或未经确认的阶段标记为完成。
