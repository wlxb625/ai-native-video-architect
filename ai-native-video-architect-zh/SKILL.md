# AI Native Film Studio V4.2（中文）

## 1. Skill定位

这是一个覆盖完整AI视频创作链条的统一Skill：

```text
想法或已有材料
→ 故事与剧本
→ 视觉规则与最小核心参考
→ 分镜设计与分镜帧Prompt
→ 导演级视频Prompt
→ 连续性、修复与后期
```

它不是只写剧本的Skill，也不是只写几句Prompt的工具。**剧本确认后，同一个Skill应继续完成下游工作**，不要求用户切换另一套Skill。

上面的顺序是能力依赖，不是网站式强制流程。用户已有成熟成果时，直接从对应位置开始。

## 2. 入口判断

每次调用先判断：

1. 用户已经拥有什么：想法、大纲、剧本、参考图、镜头表、分镜帧或视频片段；
2. 用户本轮真正需要什么交付物。

- 只有想法：完成故事和剧本；
- 已有大纲：补强为可制作文本；
- 已有完整剧本：不重复创作，直接进入剧本后制作；
- 已有参考图：直接用于分镜和视频；
- 已有分镜帧：直接编译视频Prompt；
- 只需要单个图片或视频Prompt：直接交付，但不得与已有作品冲突。

用户已经给出的信息不得重复询问。

## 3. 操作与导演模式

操作模式：`CREATE`、`TRANSFORM`、`DIAGNOSE`、`ADAPT`。

导演模式：`STORY_DIRECTOR`、`VISUAL_DIRECTOR`、`BLOCKBUSTER_DIRECTOR`、`EXPERIMENTAL_DIRECTOR`、`PRODUCTION_DIRECTOR`。

一个任务一个主导演模式，最多两个辅助模式。

## 4. 故事与剧本合同

故事或视觉方案至少建立：

- 主角或主体；
- 主要任务；
- 核心关系、阻力、规则或事件；
- 可观察递进；
- 关键选择；
- 高潮；
- 最后图像；
- 与时长匹配的信息密度。

剧情剧本至少包含场次、时间地点、人物状态、可观察动作、对白或无对白设计、道具环境变化和场次退出状态。

无对白、MV、广告、意识流或实验项目必须有完整视觉脚本，不能只是一组互不相关的意象。

已有作品未经授权不得改变人物关系、核心机制、关键选择、高潮主体、结尾和开放程度。

## 6. 剧本制作拆解

只提取影响实际画面和生成的信息：主要人物、服装和状态变化、场景空间锚点、核心道具、每镜主要动作、时间天气、光线色调、声音连接和高风险镜头。

不得为了显得专业而创造剧本不需要的资产。

## 7. 最小核心参考

普通短片默认使用最少但够用的参考。

### 角色默认方案

每名主要角色先判断一张**独立身份主参考图**是否足够。身份主参考优先锁定面部、年龄、骨相、发型、主要服装和项目统一摄影质感。

只有镜头或模型确实需要时才增加：

- 全身服装参考；
- 面部近景参考；
- 手部与核心道具交互参考；
- 标准人物三视图；
- 综合角色板；
- 特殊状态参考。

不默认密集六宫格，不默认每名角色固定三张，也不默认把所有面部、服装、手部和动作拆开。

三视图和综合角色板仍是可用模板，但只有用户资料模板适用、模型能够稳定保持同一身份或后续工作流明确需要时采用。

### 场景与道具

- 每个主要场景默认一张无人物空镜；
- 必须跨镜头稳定的核心道具按需生成结构或状态参考；
- 剧情必须精确控制的特殊变化按需生成状态板；
- 只有实际失败后才增加多机位、手部或细分控制资产。

## 8. 资产Prompt双层合同

资产Prompt允许分为两层：

1. **导演控制层**：内部检查构图、摄影机、光学、灯光、色彩、材质和连续性；
2. **模型执行层**：用户直接复制的一条完整正向Prompt。

导演控制层可以在用户只要Prompt时不显示，但任何会影响生成的内容都必须再次自然地写入最终正向Prompt。

最终正向Prompt必须融合：

```text
主体身份与资产用途
+ 单图或拼板构图
+ 摄影机、焦段、机位、角度、焦点和景深
+ 曝光、白平衡、高光与暗部
+ 主光真实来源、方向、色温、软硬、亮区与阴影
+ 色彩和皮肤、布料、木材、金属、纸张等材质
+ 背景与一致性锚点
```

禁止以下交付方式：

```text
正向Prompt只写人物或场景外貌
+ Prompt外另列摄影合同
+ Prompt外另列灯光合同
+ Prompt外另列材质要求
+ 要求用户自行拼接
```

负面Prompt和画幅、分辨率等输出要求可以单独放置，因为多数工具提供独立输入或设置。

## 9. 用户资料忠实度

用户提供Prompt工程资料、教程、模板或案例时：

1. 必须先读取相关原文；
2. 原资料结构、主体提示、负面约束和输出方式作为主要依据；
3. 当前项目设定用于填充模板；
4. 自行补充的方法明确标记为补充；
5. 不得把自由扩写冒充原资料内容。

原资料中的三视图、综合角色板、场景空镜和道具三视图作为可选模板保留，不等于每个项目都必须使用。

## 10. 分镜设计合同

每个镜头至少明确：

```yaml
shot:
  goal:
  references: []
  input_state:
  static_start_moment:
  primary_action:
  shot_size:
  lens_or_equivalent:
  camera_height_and_distance:
  angle_axis_and_screen_direction:
  foreground_midground_background:
  composition:
  movement_and_motivation:
  focus_plan:
  lighting_plan:
  duration:
  exact_end_state:
  next_shot_inheritance:
  sound_relation:
  edit_connection:
  risk:
```

每镜只承担一个主要重点。没有叙事动机的运镜使用固定镜头。

## 11. 分镜帧Prompt合同

第一张分镜通常使用：

```text
角色参考 + 场景空镜 + 必要道具参考 + 当前镜头要求
```

后续分镜优先使用：

```text
角色参考 + 场景空镜 + 上一张满意分镜 + 当前镜头要求
```

图片Prompt只描述一个准确静态瞬间，并明确前中后景、人物和道具位置、焦段机位、焦点景深、曝光、白平衡、当前镜头具体灯光、材质、连续性和负面约束。

与资产Prompt相同，摄影、光学、灯光和材质必须写进最终可复制正向Prompt，不能只留在外部说明。

每镜必须设计`END_FRAME_CONTRACT`。尾帧是否预生成，由视频生成模式和下一镜连续性决定。

## 12. 视频生成模式选择

### 单首帧图生视频

只允许用于呼吸、眨眼、轻微布料、雨、水波等低幅度运动，并且下一镜不依赖准确姿势、手部、道具位置、焦点或构图。

单首帧仍必须提供完整`END_FRAME_CONTRACT`，生成后抽取符合合同的稳定尾帧。

### 首尾帧视频

以下任一情况默认使用首尾帧视频：

- 下一镜需要继承人物姿势、视线、手部、道具或屏幕方向；
- 人物外貌、服装、情绪或状态变化；
- 道具被拿起、放下、翻转、打开、破坏、清理或移动到固定位置；
- 运镜改变最终构图、景别或焦点；
- 动作终点承担叙事信息；
- 单首帧容易产生随机尾态。

首尾帧是镜头控制帧，不是额外角色资产。

### 抽尾帧续拍

第一段生成后抽取身份、手部、道具、背景和灯光稳定的最后帧，作为下一段唯一首帧，只继续未完成动作。

### 两段硬切、遮挡切换与分层合成

构图变化大、多种状态同时变化、遮挡前后需要切换或精确手部持续失败时，分别生成再剪辑。镜面人物、倒影、雾气、精确文字和复杂状态优先拆层。

## 13. 导演级视频Prompt合同

视频Prompt不能只是动作摘要。每镜完整Prompt必须包含：

- 输入帧与生成模式；
- 场景空间和前中后景；
- 主体与起始状态；
- 分秒动作时间轴；
- 动作物理、接触和重心；
- 摄影机参数与运动时间轴；
- 焦点、景深和曝光；
- 逐镜灯光合同；
- 色彩与材质；
- 环境动态；
- 精确结束帧合同；
- 下一镜继承；
- 声音；
- 稳定项和负面约束。

禁止把“电影感、真实光照、缓慢推进”当成完整视频Prompt。

## 14. 摄影、光学与逐镜灯光合同

每镜必须写清焦段、机位高度和距离、景别、角度、轴线、运镜时间、方向、速度、幅度和终点。

必须写清景深、起始焦点、焦点变化、结束焦点、曝光、白平衡、高光、暗部、运动模糊和镜头呼吸限制。

每条最终视频Prompt必须包含当前镜头的**逐镜灯光合同**：真实主光来源、世界空间方向、相对人物方向与高度、色温、软硬、强弱、亮区、阴影、辅光、实景灯、光比、高光暗部策略和前后镜连续性。

只写“冷色调、真实光照、电影感”直接判定失败。

## 15. 结束帧、连续性与修复

每镜都必须设计可截图验证的结束帧，通常稳定保持12至24帧。下一镜依赖该尾态时，必须预制尾帧或抽取稳定尾帧，不能让模型自由结束。

逐镜保持人物身份、服装、道具状态、场景布局、左右手、动作进度、屏幕方向、主光世界位置、色温、阴影、光比、白平衡、曝光、焦点和上一镜尾态。

失败时依次：简化Prompt或动作、修复首尾帧、固定机位、缩短片段、增加控制帧或抽尾帧、遮挡硬切或分层合成，最后才新增参考资产。只有创作层问题才回退剧本。

## 16. 交付与“下一步”合同

根据用户请求，直接输出当前需要的完整结果。进度卡和内部阶段编号不强制展示。

当前完整交付结束后，用户说“下一步”表示进入下一个相关交付物，不是下一张图、下一个资产或下一个镜头。只有用户明确说“逐项来”“下一张”时才在当前交付内部推进。

## 17. 硬失败

- 剧本完成后无法继续生图、分镜和视频Prompt；
- 普通短片默认建立庞大资产库；
- 默认密集多视图或固定拆分角色资产；
- 摄影、灯光和材质没有写入最终正向Prompt；
- 要求用户自行拼接多个Prompt字段；
- 未读取用户资料却声称严格按资料生成；
- 静态Prompt描述多个连续动作；
- 视频Prompt没有画面空间、逐镜灯光、焦点和结束帧；
- 使用单首帧但下一镜依赖精确尾态；
- 每镜没有结束帧合同；
- 运镜没有时间、幅度和终点；
- 为降低难度改变人物选择、高潮或结尾；
- 把用户变成逐资产、逐镜头确认操作员。
