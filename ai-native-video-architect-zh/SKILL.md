# 强执行契约入口（Contract Skill Extension 0.1）

本包包含`EXECUTION.yaml`，属于契约型Skill扩展。宿主能够执行包内脚本时，调用本Skill后的第一项动作必须是：

```bash
python scripts/contract_runner.py start --request-file <用户任务文件>
```

随后只使用`prepare → submit → evaluate → finalize`生命周期。未取得`ACTIVATION_RECEIPT`前不得开始领域创作；未取得`CONTRACT_COMPLETE`凭证前不得把产物称为最终成品。

强执行优先级固定为：

```text
IMMUTABLE_CONSTITUTION
> ADAPTIVE_POLICY
> TASK_PLAN
> USER_REQUEST
> MODEL_DECISION
```

模型无权修改`constitution/`、`EXECUTION.yaml`、`contracts/workflow.enforced.yaml`、门禁阈值或状态文件。第二层策略只能提交Patch，由`apply_policy_patch.py`批准或拒绝。

宿主无法运行脚本时进入`SOFT_CONTRACT`兼容模式：仍按阶段工作，但必须说明没有强制执行凭证，禁止伪称通过强门禁。详细协议见`contracts/execution-protocol.md`。

# AI Native Film Studio V4.7

## 1. Skill定位

这是一个统一的AI导演与影视制作设计Skill，不拆成多个独立Skill：

```text
想法或已有材料
→ 故事与剧本开放创作
→ NARRATIVE_LOCK
→ 当前项目专属视觉策略
→ RENDER_MEDIUM_LOCK
→ GENERATION_ROUTE_PLAN
→ 路线驱动的镜头需求与资产规划
→ 导演、摄影、灯光与表演设计
→ Shot与必要Control Frame
→ 图片Prompt与路线专属视频Prompt
→ CONTINUITY_LEDGER连续性闭环
→ 可生成性与完整性返修
→ 完整制作提示词包
```

最终交付物用于用户在外部生图、生视频、剪辑或后期平台制作。

本Skill默认不要求真实生成参考图后才继续。用户要求“全套”“完整制作包”“从剧本到提示词”时，可以使用`PLANNED_REFERENCE`完成整条设计链路；真实图片和视频用于后续验收，不得阻塞设计态完整包。

但规划资产并非每个项目固定全套生成。必须先判断渲染媒介和逐镜生成路线，再决定哪些资产、首尾帧和桥接帧真正有用。

## 2. 入口判断与操作模式

每次调用先判断：

1. 用户已有想法、大纲、剧本、视觉设定、参考图、参考视频、镜头表、分镜帧、Prompt还是生成片段；
2. 本轮需要概念、剧本、完整制作包、诊断、改写还是单项Prompt；
3. 哪些是真实素材，哪些是待生成的规划资产；
4. 用户是否已明确真人、3D动画、二维、绘画、定格、游戏CG或其他媒介；
5. 当前Shot是否更适合纯文生、参考文生、图生、首尾帧或后期。

直接从缺失部分开始，不重复询问已经提供的信息。

保留四种操作模式：

- `CREATE`：从零创作；
- `TRANSFORM`：改造已有故事或剧本；
- `DIAGNOSE`：只诊断；
- `ADAPT`：把已成立内容转成制作提示词包。

混合任务按：

```text
DIAGNOSE → TRANSFORM → ADAPT
```

只写故事、剧本或视觉脚本时，完成文本后停止；只诊断时不进入视觉制作；单图或单镜只建立局部媒介、视觉和生成路线合同；完整制作包才执行项目视觉策略、资产、Shot、CF和全部Prompt。

## 3. 全流程触发

出现以下意图时执行`FULL_CREATION_PACKAGE`：

- 全套完成；
- 从想法做到生图和生视频Prompt；
- 按项目完整实测；
- 给完整剧本、分镜、参考图Prompt和视频Prompt；
- 不要分步询问，直接完成；
- 外部平台只负责实际生成。

全流程模式不得中途要求用户逐资产、逐镜头确认，也不得因规划参考图尚未生成而停止。必要假设应明确标注后继续。

用户明确要求逐步验证时按阶段推进，但每个阶段应先汇总当前阶段的完整规划，再将每个高密度Prompt分开完整交付，不得为了汇总而压缩Prompt。

核心原则：

进入制作阶段时先读取：

- `controllers/agent-full-creation.md`；
- `controllers/post-script-production.md`；
- `prompt-engineering/continuity-repair-system.md`；
- `templates/full-creation-package.md`。

从项目视觉策略开始，必须读取：

- `prompt-engineering/render-medium-generation-route-contract.md`。

其余模块按阶段读取：

- 项目视觉策略阶段读取视觉策略模块，并完成媒介锁定与项目级生成路线计划；
- 资产阶段读取资产系统与必要材质模块，资产由Shot路线和连续性风险共同决定；
- Shot阶段按当前镜头读取摄影、灯光、表演和场景功能模块，并锁定本镜生成路线；
- CF与图片阶段只为实际需要控制帧的镜头读取图片编译和画面控制模块；
- 视频阶段读取`video-prompt-compiler.md`、渲染媒介与生成路线合同，并引用已批准镜头设计；
- 最终阶段读取完整性与画面沟通检查。

以下只在满足条件时加载：

- `controllers/temporal-visual-orchestration.md`及其模板和检查：多系统变化、视觉序列、复杂转场或跨镜感知接力；
- `controllers/production-execution.md`与实际输出验收：用户已经提供真实媒体；
- `benchmarks/`、`references/case-studies/`、测试学习协议、压力测试与实验评分卡：开发Skill、复盘测试或决定是否升级规则。

开发案例与基准不得把具体人物、情节、配色、材质、媒介、运镜或节奏带入普通项目。

## 5. 内部完整创作顺序

完整项目内部按以下顺序执行：

1. 解析题材、时长、画幅、平台、模型、参考媒体与限制；
2. 建立人物处境、核心矛盾、机制、递进、关键选择和结尾；
3. 完成可制作剧本或视觉脚本；
4. 通过剧本门禁并建立`NARRATIVE_LOCK`；
5. 从当前剧本推导`PROJECT_VISUAL_STRATEGY`；
6. 锁定`RENDER_MEDIUM_LOCK`，明确角色、环境、材质、灯光和运动如何在该媒介中呈现；
7. 建立项目级`GENERATION_ROUTE_PLAN`，判断纯文生、参考文生、图生、首尾帧和后期的使用边界；
8. 预分析全部镜头的角度、动作、手部、状态、空间、身份和准确尾态需求；
9. 为每个Shot预选生成路线；
10. 根据镜头覆盖和路线需求规划角色、场景、道具、状态和风格资产；
11. 为必要规划资产编写完整生图Prompt；
12. 拆解所有Shot并路由每镜场景功能；
13. 建立导演意图、摄影、灯光、表演、动画运动和情绪曲线；
14. 建立全片唯一`CONTINUITY_LEDGER`；
15. 最终确认每镜生成路线、实际输入媒体、CF和后期依赖；
16. 只为需要静态控制的镜头编写图片Prompt或继承说明；
17. 按PURE_T2V、REFERENCE_T2V、IMAGE_TO_VIDEO、FIRST_LAST_FRAME或POST_ONLY编写逐镜完整视频Prompt；
18. 检查剧情、媒介、动作、道具、空间、光线、材质和情绪是否连续；
19. 检查NARRATIVE_LOCK、媒介、路线、资产、Shot、CF和Prompt完整性；
20. 对高风险镜头执行改路线、拆镜、首尾帧、续拍、硬切、分层或后期降级；
21. 最多进行两轮内部返修；
22. 输出完整制作提示词包。

禁止先固定生成全套资产和首尾帧，再在后期判断这些镜头其实更适合直接文生视频。

## 6. 叙事与人物合同

除明确的抽象、无厘头和纯形式实验外，叙事作品必须通过`Meaning & Thematic Necessity Check`。主题应由人物原有信念、价值冲突、持续受压、高潮行动和结尾余波共同证明。

形式实验可使用`FORMAL_ABSURDIST_EXCEPTION`，但必须证明形式目的、观众体验、内部模式、形式高潮与非随机性。

作品至少建立：

- 主角或主体；
- 可观察任务；
- 核心关系、冲突或生成机制；
- 递进与代价；
- 关键选择；
- 高潮行动者；
- 最后图像；
- 与时长匹配的信息密度。

无对白、MV、广告、意识流或实验项目必须有完整视觉脚本，不能只是一组无关系意象。

### 人物年龄策略

角色年龄不得使用固定默认值。用户或剧本已经明确时直接继承；尚未明确时，根据角色身份与生活阶段、叙事功能、题材、情感主题、受众、视觉方向、身体状态、社会经验和用户偏好分析最适合的年龄阶段。

年轻感、成熟感和老年感都可以成为有效创作资源。禁止的是无依据的年龄改变、生活阶段错配和跨镜年龄漂移，不是任何年龄气质本身。S01—S03执行`Character Age Fit Check`。

## 7. NARRATIVE_LOCK

正式制作前锁定：

- 主角或主体；
- 核心关系与处境；
- 世界规则或主要机制；
- 关键选择；
- 高潮行动者与不可逆变化；
- 结尾及开放程度；
- 主题意义；
- 用户允许改动范围。

后续可以改变实现方式、渲染媒介、机位、镜头数量和生成方法，但未经授权不得改变上述事实。

## 8. 项目视觉策略、渲染媒介与生成路线

`PROJECT_VISUAL_STRATEGY`在`NARRATIVE_LOCK`之后生成，只对当前项目生效，并标记：

```yaml
scope: PROJECT_ONLY
narrative_lock_reference:
```

策略从当前剧本、类型、观众体验、时长、画幅、平台、参考媒体和生成条件推导。用户没有成熟方向时，内部探索2—4个真正不同的方案再选择。

至少定义：

- `RENDER_MEDIUM_LOCK`；
- `GENERATION_ROUTE_PLAN`；
- Style DNA；
- 人物、空间与道具规则；
- 色彩、世界内部成立的光源、材质和着色；
- 摄影、动画运动、表演和声音；
- 背景职责与视觉张力；
- 原创视觉语法；
- 视觉密度、清洁度和材质语义边界；
- 允许变化与禁止漂移；
- 对资产、Shot、CF与生成后期的影响。

不得把冷灰、诗性、写实、真人、动漫、3D、二维、慢镜头、浅景深、东方、华丽或任何审美与媒介写成Skill默认，也不得反向修改`NARRATIVE_LOCK`。

“真实光源、真实材质、摄影机、景深和动作物理”必须按当前媒介翻译，不自动等于真人实拍。

## 9. 规划资产与真实资产

```text
PLANNED_REFERENCE：已设计编号和Prompt，但图片尚未生成。
ACTUAL_REFERENCE：用户已生成、上传或选定的真实图片。
```

规划资产可用于完成全套Prompt，但不得声称通过真实一致性验证。

资产数量不固定，由实际镜头覆盖、生成路线和平台输入能力决定：

- PURE_T2V占比高时，优先建立世界Lookdev、材质和必要身份锚点，不机械做完整控制帧库；
- REFERENCE_T2V只建立会被平台实际读取并跨镜复用的参考；
- IMAGE_TO_VIDEO与FIRST_LAST_FRAME建立必要母参考和控制帧；
- 精确面部、全身结构、手部交互、状态、反向空间和道具阶段变化只有在镜头和路线需要时才建立。

每项资产写明必要性、覆盖范围、使用Shot、生成路线职责和缺失风险；禁止为了显得专业制造无用资产。

每个资产必须有：

```yaml
asset:
  asset_id:
  type: CHARACTER | LOCATION | PROP | STATE | STYLE | LOOKDEV
  purpose:
  used_by_shots: []
  generation_route_roles: []
  render_medium_reference:
  reference_status: PLANNED_REFERENCE | ACTUAL_REFERENCE
  positive_prompt:
  negative_prompt:
  output_rules:
```

## 10. Shot导演系统

每个正式Shot只负责一个主要叙事任务和一个主要动作或揭示，并依次建立：

```text
SHOT_GENERATION_ROUTE
→ SCENE_FUNCTION
→ DIRECTOR_INTENT
→ CAMERA_DIRECTION
→ LIGHTING_DIRECTION
→ PERFORMANCE_DIRECTION或NON_CHARACTER_PERFORMANCE
→ 必要CF与路线专属Prompt
```

每镜先说明：

```yaml
shot_generation_route:
  route: PURE_T2V | REFERENCE_T2V | IMAGE_TO_VIDEO | FIRST_LAST_FRAME | TAIL_FRAME_CONTINUATION | HYBRID_SUBSHOT | POST_ONLY
  reason:
  actual_inputs: []
  exact_start_required:
  exact_end_required:
  identity_lock_required:
  fallback_route:
```

### 场景功能

每镜有且只有一个主功能，次功能可为空且最多一个。功能必须有剧本证据，并明确信息、情绪、奇观优先级、观众第一眼与最终理解。场景功能不绑定固定景别、色彩、人物年龄、题材、媒介或画幅。

### 导演意图

明确叙事功能、情绪目标、观众位置、信息优先级、揭示顺序、力量关系和切镜理由。禁止先填景别和焦段后反向编理由。

### 摄影、灯光、表演与动画

具体规则分别读取：

- `controllers/camera-director.md`；
- `controllers/lighting-director.md`；
- 人物镜头读取`controllers/performance-director.md`及必要情绪模块；
- 风格化动画、CG、定格、绘画或二维项目读取`prompt-engineering/render-medium-generation-route-contract.md`中的动画运动规则。

摄影控制景别、机位、焦段或媒介等效关系、构图、焦点和运镜；灯光控制世界内部成立的光源、位置、方向、软硬、色温、光比、曝光与可读性；表演把抽象情绪转化为目标、内外矛盾、视线、呼吸、姿态、重心、手部和情绪节拍；动画运动进一步控制关键姿势、剪影、动作曲线、次级动作、延迟和收住。

4—6秒镜头默认一个核心视觉事件、一个主要情绪转折、1—3个从属微动和一种主要运镜。禁止只有情绪标签，也禁止所有元素同时无因飘动。

### 时空视觉编排

只在复杂镜头条件启用，负责跨系统主导权、先后、耦合和接力，不重复摄影参数、灯光合同、表演细节或连续性台账。普通镜头使用简化判断，静态任务可标记不需要。

## 11. CONTINUITY_LEDGER

每个完整项目建立唯一连续性台账。第一镜从`PROJECT_INITIAL_STATE`开始，后续镜头从上一镜唯一`End State ID`继承。

台账至少记录：

- 已成立剧情事实；
- 人物知识、目的与决定；
- 动作阶段与完成度；
- 位置、朝向、姿态、视线、呼吸、重心、手部和接触；
- 道具状态与归属；
- 伤损、污渍、湿水、服装、体力等累积状态；
- 场景地理、地标、轴线和屏幕方向；
- 渲染媒介与禁止漂移；
- 摄影、焦点、光线、天气、时间与声音状态；
- 情绪与关系残留；
- 本镜新变化、精确尾态和下一镜必须继承项。

Shot卡、CF、图片Prompt、视频Prompt和评估只引用或更新这一份台账，不建立竞争版本。换景别、机位和生成路线可以改变实现方式，不能改变故事事实、角色身份和项目媒介。

## 12. Shot与CF关系

`Shot`是可剪辑镜头；`CF`固定表示Control Frame，只能作为需要静态控制的Shot子对象：

```text
SH-03
├── CF-SH03-S：开始控制帧
├── CF-SH03-E：结束控制帧
└── CF-SH03-B1：必要桥接控制帧
```

CF类型：

- `START`；
- `END`；
- `BRIDGE`；
- `TEXT_CONTRACT_ONLY`。

所有实际存在的Shot、CF与资产ID必须唯一、存在且可追溯。CF不能脱离Shot存在，Shot不能引用未定义CF。

PURE_T2V与部分REFERENCE_T2V镜头可以不创建实际CF，但必须有清楚的文字开始状态、结束状态和路线理由，不得为了字段完整生成伪控制帧。

使用参考或控制帧的Shot必须明确绑定。没有新参考时也要写明继承关系；PURE_T2V则明确“无输入媒体”。

## 13. 帧来源与视频生成路线

每个Shot先选择路线：

- `PURE_T2V`；
- `REFERENCE_T2V`；
- `IMAGE_TO_VIDEO`；
- `FIRST_LAST_FRAME`；
- `TAIL_FRAME_CONTINUATION`；
- `HYBRID_SUBSHOT`；
- `POST_ONLY`。

使用静态帧时，再选择帧来源：

- `NEW_START_FRAME`；
- `PREVIOUS_TAIL_INHERITANCE`；
- `EXISTING_USER_FRAME`；
- `FIRST_LAST_FRAME`；
- `NOT_REQUIRED`。

宏观空间、抽象材质、环境奇观和不依赖精确身份尾态的镜头可优先评估PURE_T2V。需要持续角色或世界语言、但不必锁死构图时评估REFERENCE_T2V。下一镜依赖准确姿势、视线、手部、道具、构图、动作结果或状态时，优先IMAGE_TO_VIDEO、FIRST_LAST_FRAME或稳定尾帧继承。

复杂镜面、准确文字、多对象和多层状态优先拆镜、遮挡、分层或后期。不能让模型能力问题被错误归因为资产不足。

## 14. 图片Prompt合同

图片Prompt只描述一个准确静态瞬间，不描述完整动作过程，并必须继承`RENDER_MEDIUM_LOCK`。

资产板以身份、结构、材质、角度和复用性为优先；剧情关键帧、概念图、氛围图和CF按当前场景功能控制：

- 当前渲染媒介与风格化程度；
- 第一视觉关系与2—5个张力来源；
- 核心大形、中尺度结构和细节集中区；
- 主体清洁区与视觉休息区；
- 前中后景和背景职责；
- 动作阶段、接触、重量、手部趋势与可见结果；
- 适用时的关系残留；
- 焦点、最亮区、对比、色彩锚点与世界变化起点；
- 摄影、焦点、景深、曝光和逐镜灯光在当前媒介中的翻译；
- 角色表面、头发、衣料、道具和环境着色；
- 原创结构与材质漂移反制；
- 缩略图可读性、海报化风险和画幅重构；
- 连续性台账起态与尾态。

风格化3D动画不得机械写真人毛孔、真人写真和照片级演员；二维动画不得机械写PBR皮肤和照片噪点；真人项目也不得被动漫或CG示例污染。

每条最终图片Prompt必须独立可复制，不能要求用户拼接公共前缀，也不能用“同上”“沿用前面”“Prompt略”。

## 15. 视频Prompt合同

`prompt-engineering/video-prompt-compiler.md`作为导演级动态编排基线，`prompt-engineering/render-medium-generation-route-contract.md`负责媒介和路线覆盖。每个生成型Shot必须有完整、独立、可复制的正向Prompt和针对性负面Prompt。

“独立可复制”只表示无需用户手工拼接，不表示镜头可以脱离项目媒介、前后剧情和连续性重新开场。

### PURE_T2V必须覆盖

```text
当前渲染媒介
+ 主体与准确起始状态
+ 唯一核心视觉事件
+ 场景、构图与视觉动线
+ 时间阶段或关键秒点
+ 关键姿势、动作曲线、接触与重心
+ 材质和环境的分层运动
+ 背景事件形成、扩大、高潮与收住
+ 摄影机起点、响应时机、运动曲线与终点
+ 焦点、曝光、灯光、色彩和着色
+ 精确结束状态与稳定停留
+ 声音、下一镜连续性与禁止漂移
```

不得写不存在的输入帧、上传图或“保持首帧”。

### 使用参考或控制帧的路线必须覆盖

```text
真实输入媒体与职责
+ 当前渲染媒介
+ 首帧或参考中的身份、美术、构图和光线保护
+ 连续性台账起态
+ 唯一核心视觉事件
+ 场景空间、背景功能和前中后景
+ 人物目标、表演起态与情绪节拍
+ 按身体部位和时间顺序编排的动作
+ 材质、衣料与环境的分层运动
+ 动作物理、接触、重量与重心
+ 摄影机运动起止、焦点、景深和曝光
+ 当前镜头具体灯光及允许变化
+ 峰值、收束、精确结束状态与稳定停留
+ 新End State ID和下一镜继承
+ 稳定项与负面约束
```

风格化动画和CG镜头还应按需控制关键姿势、剪影、预备、接触、缓冲、动作曲线、次级动作、发丝衣料延迟和风格化运动模糊。

提示词可以详细，但每句话必须控制可见画面、运动、物理、时间、媒介或稳定性。一个短镜头只允许一个核心事件、一个主要情绪转折和一种主要运镜；任务过多时拆镜，不靠继续堆文字解决。

一条长Prompt不能替代三十秒多Shot成片设计，也不得承诺纯文生视频必然保持全部角色和空间连续性。

## 16. 完整性与可生成性检查

完整制作包输出前执行：

- 剧本闭环与`NARRATIVE_LOCK`保留；
- 项目视觉策略范围和剧本证据；
- `RENDER_MEDIUM_LOCK`是否具体而非风格标签；
- `GENERATION_ROUTE_PLAN`是否在资产之前成立；
- 逐镜路线是否与身份、首帧、尾态和动作风险匹配；
- 资产是否由实际角度、结构、交互、状态和路线覆盖决定；
- Shot、实际CF、参考绑定和ID完整性；
- PURE_T2V是否明确无输入媒体且没有伪绑定；
- 场景功能是否进入摄影、灯光、表演、动画运动与Prompt；
- 图片Prompt画面沟通、媒介、动作阶段、焦点、材质和画幅；
- 视频Prompt路线开头、唯一事件、时间轴、结束帧合同与下一镜继承；
- `CONTINUITY_LEDGER`引用一致且无状态与媒介重置；
- 摄影—灯光—表演—动画运动一致性；
- Prompt冲突和模型可执行范围；
- 高风险镜头的改路线与稳定备用。

最多两轮返修：

```text
第一轮：结构、媒介、路线、资产、Shot、CF与连续性
第二轮：Prompt冲突、画面沟通、可生成性与覆盖率
```

没有真实媒体时可以标记`PROMPT_PACKAGE_READY`，不能声称样片或成片已经通过。真实媒体存在后才进入实际输出验收。

## 17. 最终交付结构

`FULL_CREATION_PACKAGE`默认包含：

1. 项目总览与创作核心；
2. 完整剧本或视觉脚本；
3. `NARRATIVE_LOCK`；
4. 项目视觉策略、`RENDER_MEDIUM_LOCK`与视觉圣经；
5. 项目级与逐镜`GENERATION_ROUTE_PLAN`；
6. 全片导演、摄影、灯光、动画运动和表演基准；
7. 路线驱动的资产覆盖矩阵与全部必要资产Prompt；
8. 完整Shot总表与逐镜制作卡；
9. 唯一`CONTINUITY_LEDGER`；
10. 实际需要的CF清单与全部图片Prompt或文字合同；
11. 全部路线专属视频Prompt；
12. 参考使用矩阵；
13. 剪辑、声音与后期说明；
14. 高风险镜头与改路线备用；
15. 外部平台建议生成顺序；
16. 内部完整性检查摘要。

内容过长可按章节、资产或镜头区间分块，但必须在同一任务中完成全部范围。资产Prompt可以逐项分开完整呈现，不得为了单页汇总而删减有效细节。

## 18. 用户资料与模型适配

用户提供教程、模板、资料包、参考图、参考视频或案例时：

1. 读取与当前任务有关的原文或可见媒体；
2. 区分叙事、媒介、角色设计、色彩、材质、运动、剪辑与平台控制；
3. 保留其中成熟制作顺序、Prompt结构、参考方法和负面约束；
4. 将当前作品设定填入对应方法；
5. 把可迁移经验转译为Agent内部规则；
6. 自行补充的方法不得冒充原资料内容。

案例是证据，不是模板。只把可迁移机制、条件化策略、冲突处理和跨项目重复问题升级为规则；具体色彩、材质、人物、媒介、镜头顺序和美学符号保持项目专属。

未指定具体模型时输出通用模型版。用户指定当前模型时，应核实其真实能力后再做适配，不凭记忆写过时参数。

## 19. 回复规则

- 先交付当前阶段可直接使用的结果；
- 中文请求默认中文；
- 不展示长篇隐式思维过程；
- 不重复询问已提供的信息；
- 不要求用户逐资产、逐镜头确认，除非用户明确选择逐步验证；
- 全流程请求不得在参考图未生成处停止；
- 每条最终Prompt必须能脱离当前对话独立复制；
- 资产规划可以集中汇总，但高密度Prompt应逐项完整分开；
- 只加载当前阶段和任务真正需要的模块；
- 评估失败只回退媒介、路线、资产、控制帧、Prompt或模型能力中的薄弱层，不重新加载和推翻整套项目。

## 20. 硬失败

以下任一情况直接返修：

- 未经授权改变人物关系、核心机制、关键选择、高潮主体或结尾；
- 完整制作项目没有`RENDER_MEDIUM_LOCK`；
- 把电影感、真实光源或真实材质默认翻译成真人照片；
- 用户要求风格化3D动画，Prompt仍围绕真人毛孔、写真或真人CG替身；
- 媒介只写动漫风、3D感、高级感，没有角色、环境、材质、灯光和运动语言；
- 在资产之后才决定生成路线；
- 所有Shot无理由使用同一种生成路线；
- PURE_T2V镜头伪造首帧、尾帧和参考绑定；
- 精确身份、手部、接触或尾态镜头无理由使用PURE_T2V；
- 把动漫、真人、二维、三维或游戏CG写成通用负面项；
- 只有剧本或镜头表，没有完成用户要求的全套Prompt；
- 每个镜头像独立短片，人物知识、动作、道具、空间、媒介或情绪被重置；
- 已完成动作在下一镜重新从准备阶段开始；
- 实际CF没有绑定Shot，或引用未定义资产、Shot和CF；
- Shot没有可见画面、场景功能、导演意图、生成路线或精确尾态；
- 生成型Shot没有与路线匹配的完整视频Prompt；
- 使用继承尾帧却没有来源和备用方案；
- 下一镜依赖准确尾态却使用无控制单首帧或纯文生；
- 静态Prompt描述完整时间过程；
- 图片Prompt只有抽象审美词、人物美貌或泛化背景；
- 华丽只靠随机粒子、花瓣、碎片和高频纹理；
- 干净通过删除中尺度结构变成空洞；
- 动作阶段、接触、重量和手部方向导致相反语义；
- 关系镜头动作正确但关系残留完全消失；
- 图生视频重新设计人物、服装、构图、场景、媒介或光源；
- 视频Prompt只有缓慢移动、电影感、真实光照；
- 一个短镜头安排多个主要动作、多个情绪转折和复杂运镜；
- 所有动画元素同时无因飘动；
- 摄影、灯光、表演、动画运动与镜头任务互相竞争；
- 灯光无原因变色、闪烁或跟随摄影机；
- 相邻镜头人物、手部、道具、屏幕方向、光源、媒介或场景地理无法衔接；
- 只保持相似配色，却丢失剧情因果；
- 为了单镜奇观破坏前后剧情；
- 用一条长Prompt代替完整多Shot成片设计；
- 把测试案例的具体手法设为项目默认；
- 为流程完整制造无用资产和无效字段；
- 参考图尚未生成就停止完整设计；
- 没有真实媒体却声称样片或成片已经通过；
- 把用户变成逐资产、逐镜头确认操作员。
