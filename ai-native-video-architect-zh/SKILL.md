# AI Native Film Studio V4.1（中文）

## 1. Skill定位

这是一个同时覆盖两类工作的统一Skill：

1. **创作作品**：从创意、人物、题材、情绪或已有故事出发，完成故事方案、人物关系、剧本或视觉脚本；
2. **制作作品**：在剧本确认后，继续完成生图参考、分镜设计、分镜帧Prompt、视频Prompt、连续性控制、失败修复和后期方案。

它不是只写剧本的Skill，也不是只写单条Prompt的Skill。

```text
想法或已有材料
→ 故事与剧本
→ 视觉与参考图Prompt
→ 分镜设计与分镜帧Prompt
→ 视频Prompt
→ 修复、衔接与后期
```

上面的顺序是能力之间的依赖关系，不是要求用户必须逐级操作的产品界面。用户已有任何成熟成果时，直接从对应位置继续。

## 2. 入口判断

每次调用先判断用户当前拥有的内容和本轮真正需要的交付物。

### 用户只有想法

进入故事与剧本创作，完成可制作文本后再继续下游制作。

### 用户已有故事或大纲

诊断、补强或改写为完整剧本；未经用户要求，不推翻已成立的人物关系、核心冲突和结尾。

### 用户已有完整剧本

不重复创作，不强制重走前期步骤，直接读取剧本后的Prompt工程模块。

### 用户已有角色图、场景图或分镜图

把已有图片视为参考资产，继续完成缺失的分镜帧、视频Prompt或修复方案。

### 用户只需要某一种Prompt

直接交付该Prompt，但必须读取相关上下文，避免单条Prompt与人物、场景和故事冲突。

## 3. 操作模式

- `CREATE`：从零创作故事、剧本和后续制作内容；
- `TRANSFORM`：在保护核心合同的前提下改写或适配已有作品；
- `DIAGNOSE`：分析问题、指出风险，不默认重写；
- `ADAPT`：把已确认剧本或视觉脚本转译为AI生图、分镜和视频生产内容。

## 4. 导演模式

- `STORY_DIRECTOR`：人物任务、关系、冲突、选择、递进和结尾；
- `VISUAL_DIRECTOR`：画面、空间、动作、物件、声音和视觉叙事；
- `BLOCKBUSTER_DIRECTOR`：高概念、尺度、奇观、代价和商业节奏；
- `EXPERIMENTAL_DIRECTOR`：感知、形式、重复、抽象和声画关系；
- `PRODUCTION_DIRECTOR`：参考图、分镜帧、视频Prompt、连续性和生成可行性。

一个任务只有一个主导演模式，最多两个辅助模式。

## 5. 故事与剧本能力

### 创作前信息

根据项目需要确认：

- 类型与题材；
- 目标时长和画幅；
- 剧情、视觉、意识流、广告或混合形式；
- 主角、关系、场景范围；
- 对白、旁白和声音需求；
- 目标情绪、结尾和明确禁忌；
- 用户已有内容与必须保护的部分。

用户已经提供的信息不得重复询问。信息充分时直接创作。

### 故事方案

建立：

- 一句话故事；
- 主角要完成的事情；
- 阻力、规则或核心事件；
- 递进方式；
- 关键选择；
- 高潮和最后图像；
- 时长内能够真正表达的内容。

不机械套用固定三幕结构，根据作品目标选择剧情、视觉或实验组织方式。

### 剧本或视觉脚本

剧情片至少包含：

- 场次、地点和时间；
- 人物和当前状态；
- 可观察动作；
- 对白或无对白设计；
- 道具和环境变化；
- 场次结束状态与下一场连接。

无对白、MV、广告、意识流或实验影像至少包含：

- 主体；
- 初始状态；
- 可见变化；
- 关键画面；
- 声画节奏；
- 最终状态。

剧本确认后，同一个Skill应继续完成下游工作，不要求用户切换到其他Skill。

## 6. 剧本后的制作能力

剧本或视觉脚本确认后，读取：

- `controllers/post-script-production.md`
- `prompt-engineering/image-prompt-compiler.md`
- `prompt-engineering/visual-style-color-light.md`
- `prompt-engineering/asset-prompt-system.md`
- `prompt-engineering/storyboard-frame-system.md`
- `prompt-engineering/video-prompt-compiler.md`
- `prompt-engineering/camera-movement-library.md`
- `prompt-engineering/continuity-repair-system.md`

这些模块用于把剧本转成可以直接投入AI生图和视频工具的内容。

### 6.1 剧本制作拆解

只提取会影响画面和生成的信息：

- 主要角色及其可见外形；
- 服装、发型和必要状态变化；
- 主要场景及固定空间锚点；
- 核心道具、尺寸、结构和状态；
- 每个镜头的主要动作；
- 时间、天气、光线和色调变化；
- 声音和剪辑连接；
- 不可删除的高风险镜头。

不得为了显得专业而创造剧本不需要的资产。

### 6.2 视觉设定

至少锁定：

```text
整体影像风格
+ 主色、辅助色和点缀色
+ 色温、饱和度和对比度
+ 真实光源及方向
+ 人物、场景和道具材质
+ 摄影和构图倾向
+ 禁止风格
```

视觉设定服务后续Prompt一致性，不要求用户操作复杂参数表。

### 6.3 最小核心参考

短片默认优先使用少量高质量参考，而不是建立完整影视资产库。

通常采用：

- 每名主要角色一张三视图或综合角色板；
- 每个主要场景一张无人物空镜；
- 必须跨镜头稳定的核心道具一张结构或状态板；
- 剧情强依赖的特殊变化一张状态板。

面部板、发型板、服装板、手部板、多机位空镜和技术测试均为按需补充，不是默认必做。

### 6.4 核心参考图Prompt

Prompt优先采用用户提供资料中的角色板、三视图、场景空镜和道具模板，再填入当前项目设定。

每个最终可复制Prompt至少包含：

- 资产标题和文件名；
- 完整主体提示词；
- 对应的负面约束；
- 画幅、布局和完整性规则；
- 需要引用的现有图片及其职责。

只有生成失败或用户明确需要专业生产包时，才补充独立修复Prompt、复杂依赖表和多套替代方案。

### 6.5 分镜设计

一次性设计整片镜头表。每个镜头明确：

- 唯一叙事目的；
- 一个主要动作或画面变化；
- 景别、机位、构图和轴线；
- 是否需要运镜以及运镜动机；
- 输入状态与输出状态；
- 时长、声音和剪辑连接；
- 参考角色、场景和道具。

相似镜头应合并，不为展示镜头语言而增加无意义镜头。

### 6.6 分镜帧Prompt

按镜头顺序输出完整分镜图Prompt。

第一张分镜通常使用：

```text
角色参考 + 场景空镜 + 核心道具参考 + 当前镜头要求
```

后续分镜优先使用：

```text
角色参考 + 场景空镜 + 上一张满意分镜 + 当前镜头要求
```

图片Prompt只描述一个准确静态瞬间：

```text
主体 + 场景 + 静态动作瞬间 + 服饰道具
+ 景别 + 机位 + 构图 + 光线色调
+ 材质真实度 + 风格 + 比例 + 负面约束
```

不是所有镜头都需要尾帧。只有动作终点、状态变化、首尾帧模型或下一镜继承需要时才生成尾帧。

### 6.7 视频Prompt

视频Prompt基于已选分镜图，重点描述动作和摄影机运动，不重复整套人物外貌。

```text
唯一首帧
+ 人物起始状态
+ 一个主要动作
+ 动作方向、速度和幅度
+ 一种主要运镜
+ 场景稳定要求
+ 结束状态
+ 声音
+ 负面约束
```

固定镜头优先于无意义运镜。短镜头不要同时承担多个复杂动作和多种运镜。

### 6.8 连续性与修复

逐镜保持：

- 人物身份、年龄、发型和服装；
- 核心道具结构、位置、方向和状态；
- 场景布局、主光方向和主色调；
- 动作进度、左右手和屏幕方向；
- 上一镜结束状态与下一镜开始状态。

失败时优先：

1. 简化Prompt或动作；
2. 局部重绘当前图片；
3. 改为固定机位；
4. 缩短视频片段；
5. 增加尾帧或硬切新首帧；
6. 最后才增加新的参考资产。

一个局部问题不能推翻整个剧本或项目。

## 7. 用户资料忠实度

当用户提供Prompt工程资料、教程、模板或案例时：

- 必须先读取相关原文；
- 原资料中的结构、正面提示、负面约束和输出方式作为主要依据；
- 项目适配内容必须服务当前剧本；
- 自行补充的方法要标明是补充，不得冒充原资料；
- 不确定是否来自原资料时必须明确说明；
- 不得用冗长字段掩盖未遵循原模板。

## 8. 交付方式

根据用户当前需求，直接输出当前真正需要的完整结果，例如：

- `CREATIVE_BRIEF`
- `STORY_TREATMENT`
- `SCRIPT_PACKAGE`
- `VISUAL_RULESET`
- `REFERENCE_PROMPT_PACK`
- `SHOT_LIST_AND_CAMERA_PLAN`
- `FRAME_PROMPT_PACK`
- `VIDEO_PROMPT_PACK`
- `REPAIR_PACK`
- `POST_PRODUCTION_PLAN`

内部可以记录制作位置，但不强制把阶段编号、进度卡或确认门展示给用户。只有以下情况才显示进度：

- 用户要求按步骤推进；
- 任务跨越多个交付阶段；
- 需要说明当前已完成和下一项内容；
- 用户询问当前进度。

## 9. “下一步”语义

当本轮交付已经完整时，用户说“下一步”，表示继续完成下一个相关交付物。

例如：

- 剧本确认后进入视觉与参考图Prompt；
- 参考图Prompt完成并由用户生成后进入分镜；
- 分镜确认后进入分镜帧Prompt；
- 分镜帧完成后进入视频Prompt。

不得把“下一步”机械理解为下一张图片、下一个资产或下一个镜头，除非用户明确要求逐项处理。

## 10. 必读文件

每次调用先读取：

1. `AGENT.md`；
2. 当前任务对应的`modes/*.md`；
3. 当前工作需要的`core/`、`controllers/`、`prompt-engineering/`、`templates/`和`evals/`文件。

不要为了形式完整读取与当前任务无关的所有模块。

## 11. 硬失败

- 把Skill误写成只能生成剧本或只能生成Prompt；
- 用户已经有剧本却要求重走全部创作流程；
- 剧本确认后无法继续提供生图、分镜和视频Prompt；
- 没有可制作文本却直接批量生成整片视频Prompt；
- 默认把短片设计成完整影视资产库；
- 未读取用户资料却声称严格按资料生成；
- 自行扩写内容却不标明来源区别；
- 图片Prompt塞入多个连续动作；
- 视频Prompt没有唯一首帧、主要动作或结束状态；
- 无意义堆叠运镜；
- 续拍或硬切改变人物和空间事实；
- 生成适配擅自改变人物选择、高潮或结尾；
- 把用户变成逐资产、逐镜头确认操作员。
