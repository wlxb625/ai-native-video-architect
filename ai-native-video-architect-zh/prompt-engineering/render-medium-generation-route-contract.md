# Render Medium & Generation Route Contract V4.7

## 目标

在资产规划、图片Prompt、Control Frame和视频Prompt之前，先锁定当前项目以什么视觉媒介存在，并为每个Shot选择与其控制需求相匹配的生成路线。

本合同解决两类系统性问题：

1. 把“电影感、真实光源、材质细节”等通用制作要求误译为真人实拍或照片写实；
2. 在尚未判断Shot适合文生视频、参考文生视频、图生视频还是首尾帧之前，机械规划大量静态资产和控制帧。

本合同属于现有Skill内部的跨阶段编译合同，不是新的独立Skill，也不预设任何固定审美。

## 一、执行顺序与优先级

完整制作项目按以下顺序执行：

```text
NARRATIVE_LOCK
→ PROJECT_VISUAL_STRATEGY
→ RENDER_MEDIUM_LOCK
→ GENERATION_ROUTE_PLAN
→ Shot需求预分析
→ 路线驱动的资产规划
→ Shot / CF / 图片Prompt / 视频Prompt
```

`RENDER_MEDIUM_LOCK`和`GENERATION_ROUTE_PLAN`一旦通过，资产系统、图片编译器、视频编译器、灯光材质模块及模板中的通用示例都必须服从它们。

当下游出现与当前媒介冲突的通用写法时，以本合同和当前项目锁定结果为准。例如：

- “真实光源”表示光源位置、方向、衰减和阴影关系在当前世界内部成立，不等于必须真人摄影；
- “真实材质”表示材质具有可观察、稳定、可区分的表面和受力规律，不等于必须照片级纹理；
- “摄影机、焦段、景深”可以用于真人实拍、三维动画、二维动画虚拟摄影机和混合媒介，但必须按当前媒介翻译；
- 皮肤毛孔、胶片颗粒、照片透视等只在当前项目确实需要时使用，不得自动继承。

## 二、渲染媒介锁定

### 最小合同

```yaml
render_medium_lock:
  evidence: []
  medium: LIVE_ACTION_REALISM | PHOTOREAL_CG | STYLIZED_3D_ANIMATION | TWO_POINT_FIVE_D_ANIMATION | TWO_D_ANIMATION | PAINTERLY_ANIMATION | STOP_MOTION | INK_ANIMATION | GAME_CINEMATIC | MIXED_MEDIA | OTHER
  stylization_level:
  character_rendering:
  facial_design:
  skin_or_surface_shading:
  hair_rendering:
  costume_rendering:
  environment_rendering:
  material_language:
  lighting_language:
  camera_and_optical_translation:
  animation_language:
  compositing_language:
  target_visual_finish:
  allowed_medium_variation: []
  forbidden_medium_drift: []
```

### 判定来源

媒介不得使用固定默认值。按以下证据判断：

1. 用户明确要求；
2. 用户提供的参考图、参考视频或已有视觉圣经；
3. 题材、人物、情绪、奇观、动作和目标受众；
4. 平台、时长、模型和后期条件；
5. 当前项目需要的角色一致性、形体自由度和空间变化能力。

用户已有明确媒介方向时优先忠实实现。用户没有明确方向，且不同媒介会显著改变作品时，内部探索2—4个真正不同的媒介方向；不能只在真人写实方案上更换滤镜。

### 创作中立

不得把以下任一种媒介写成Skill全局默认或全局负面：

- 真人实拍；
- 照片写实CG；
- 高端风格化3D动画；
- 2.5D动画；
- 二维动画；
- 绘画动画；
- 水墨动画；
- 定格动画；
- 游戏电影CG；
- 混合媒介。

“动漫、游戏CG、真人照片、三维、二维、海报感”等媒介词只有在当前项目明确排除时，才进入负面Prompt。

## 三、媒介专属翻译

### LIVE_ACTION_REALISM

可以使用真实演员骨相、自然皮肤区域差异、真实镜头透视、摄影机光学、实景布光、服装与道具的现实工艺和物理磨损。仍禁止把“写实”机械翻译成脏、老、灰暗或纪录片手持。

### PHOTOREAL_CG

强调数字角色与环境的高真实度、物理材质、可信次表面散射、毛发和布料模拟、虚拟摄影机及真实光学，但必须避免蜡像皮肤、游戏过场模板和真人照片伪装。

### STYLIZED_3D_ANIMATION

角色、环境和材质必须通过设计建立统一语言，而不是“真人脸加CG背景”。至少明确：

- 面部比例、骨相转译、眼睛尺度和轮廓的风格化程度；
- 动画电影级角色建模、受控次表面散射、皮肤或表面着色器，不机械强调真人毛孔；
- 发束、发片或曲线毛发的造型语言、轮廓可读性和动态层级；
- 服装大轮廓、切片、褶皱方向、重量和着色方式；
- 环境形体与人物轮廓是否属于同一套曲线、折面、连接和受力语法；
- 物理动机成立但具有绘画化、动画化取舍的灯光；
- 关键姿势、剪影、预备、接触、缓冲、收住和次级动作；
- 运动曲线、风格化惯性、布料与发丝延迟、受控运动模糊；
- 高端动画电影关键帧或成片级完成度，而不是普通游戏截图、真人CG替身或廉价二次元滤镜。

### TWO_POINT_FIVE_D_ANIMATION

明确二维形状、分层深度、有限三维空间、视差、绘画纹理、角色与背景的平面关系以及哪些元素允许真实体积。不得同时要求完全二维平涂和全物理三维写实。

### TWO_D_ANIMATION

优先线条、色块、形状、关键姿势、轮廓、构图和帧间节奏。摄影机参数作为画面感辅助，不得用真人毛孔、真实镜头炫光和复杂PBR材质替代二维设计。

### PAINTERLY_ANIMATION / INK_ANIMATION

明确笔触、墨色、边缘、干湿、晕染、留白、纸面或数字画布质感及其时间变化。物理规律可以被风格化，但变化因果和画面层级仍须清楚。

### STOP_MOTION

明确实体材料、模型尺寸、逐帧质感、轻微人工痕迹、灯光尺度和运动节拍，不能写成光滑CG动画。

### GAME_CINEMATIC

明确是风格化或写实游戏电影CG、目标引擎感、角色着色、环境规模和虚拟摄影机。不得把“游戏CG”自动当作低质量，也不得让普通游戏UI、战斗待机姿势或默认资产污染画面。

### MIXED_MEDIA

逐层写清每种媒介的职责、交界方式、遮挡、合成、纹理和运动关系，不能只写“混合风格”。

## 四、生成路线计划

### 项目级最小合同

```yaml
generation_route_plan:
  evidence: []
  project_default: PURE_T2V | REFERENCE_T2V | IMAGE_TO_VIDEO | FIRST_LAST_FRAME | HYBRID | POST_LED
  route_reasoning:
  model_and_platform_conditions:
  direct_t2v_eligible_shots: []
  reference_t2v_shots: []
  image_to_video_shots: []
  first_last_frame_shots: []
  post_only_shots: []
  route_decision_rules:
  asset_implications:
  control_frame_implications:
  fallback_order: []
```

项目级默认只代表常用路线，不强制每个Shot相同。正式执行时每个Shot必须单独记录路线和理由。

### Shot级路线

#### PURE_T2V

适合：

- 抽象空间、环境奇观和材质变化；
- 构图可允许一定探索；
- 不依赖精确面孔、手部接触、道具结构或唯一尾态；
- 文本运动设计比固定首帧更能释放模型动态创造力。

不得伪造首帧、尾帧或上传参考绑定。Prompt直接从媒介、主体、起始状态、唯一事件和时间发展开始。

#### REFERENCE_T2V

适合：

- 需要持续角色身份、世界风格、服装或场景语言；
- 但不需要完全锁死首帧构图；
- 希望保留文生视频的运动和构图自由度。

每张参考必须写清职责，不得把风格参考误当身份参考或把人物参考强行当首帧。

#### IMAGE_TO_VIDEO

适合：

- 首帧构图、角色位置、面孔、服装或场景必须准确继承；
- 动作主要从一个批准的静态状态发展；
- 尾态允许用文字合同控制或从结果中选择。

Prompt必须先保护输入帧，再编排动作；不得重新设计美术。

#### FIRST_LAST_FRAME

适合：

- 起点和终点都必须准确；
- 精确手部接触、拆开、闭合、变形、状态切换或匹配剪辑；
- 结束帧要直接服务下一镜。

首尾帧存在静态矛盾时先修图，不能让视频模型自行调和。

#### HYBRID

同一影片根据Shot控制需求组合上述路线。宏观奇观可直接文生视频，角色近景、精确交互和连续性终点可用参考、图生视频或首尾帧。HYBRID不是“每镜都把所有控制方式叠加”。

#### POST_LED

准确文字、复杂多层合成、部分转场、光效、遮挡、色彩统一或生成模型不稳定的内容由后期主导。必须写明底板、前景层、遮罩、跟踪、声音和剪辑要求。

## 五、路线选择检查

为每个Shot回答：

1. 是否必须保持同一角色或道具身份？
2. 是否必须从一个准确构图开始？
3. 是否必须抵达一个准确尾态？
4. 是否有精确手部、接触、开合、破损或状态切换？
5. 画面价值是否主要来自模型自由生成的大尺度运动与形体变化？
6. 是否已有可用实际参考？
7. 当前平台支持哪些参考槽位和控制方式？
8. 失败后最稳定的降级路线是什么？

不得因为流程习惯就把所有镜头设为图生视频，也不得为了省资产把所有精确人物镜头设为纯文生视频。

## 六、路线驱动的资产规划

资产数量由Shot路线和连续性风险共同决定。

### PURE_T2V占比高的项目

优先建立：

- 项目媒介与风格Lookdev；
- 世界形体、色彩、材质和运动语言；
- 重复人物确有需要时的身份参考；
- 核心道具或规则确有结构风险时的参考。

不得在Shot路线尚未确定前机械生成完整面部、三视图、所有机位、所有状态和全部首尾帧。

### REFERENCE_T2V占比高的项目

只建立会被模型实际读取且被多个Shot复用的角色、服装、场景、材质和风格参考。参考职责必须单一、清楚、可绑定。

### IMAGE_TO_VIDEO / FIRST_LAST_FRAME占比高的项目

建立必要的身份、结构和场景母参考，再按依赖关系生成首帧、尾帧和桥接帧。精确手部、袖口、道具接触或状态资产只在镜头确实依赖时建立。

### HYBRID项目

先列Shot路线矩阵，再汇总资产覆盖。一个资产必须有明确使用Shot和路线职责；没有实际使用的资产删除。

## 七、图片Prompt的媒介继承

所有图片Prompt和资产Prompt必须读取`render_medium_lock`。

- 首句前置核心块应在必要时明确媒介和资产类型，例如“同一位风格化3D动画女主的标准正侧背角色结构板”，而不是默认“真人摄影”；
- 技术资产板仍以结构、比例和中性可读性为先，但必须使用项目媒介的角色建模、线条、着色或材料语言；
- 角色皮肤、头发、衣料和环境材质按媒介翻译；
- 景深、曝光、焦点和光源保持导演级明确，但不强制照片写实；
- 当前项目为风格化3D动画时，不得机械加入真人毛孔、真实演员写真、商业人像摄影、照片级皮肤或真人CG替身；
- 当前项目为二维动画时，不得机械加入PBR材质、真实相机噪点和照片级皮肤；
- 当前项目为真人实拍时，也不得被动漫或CG示例污染。

负面Prompt只排除当前项目不允许的媒介漂移。

## 八、视频Prompt的路线继承

### PURE_T2V Prompt前置核心块

```text
渲染媒介与主体
+ 准确起始状态
+ 唯一核心视觉事件
+ 关键运动方向或时间锚点
```

随后完整展开构图、空间、时间发展、动作与材质运动、摄影机、灯光、色彩、声音、尾态和稳定项。不得写“保持上传首帧”或虚构参考图。

### REFERENCE_T2V Prompt前置核心块

```text
真实参考图及其职责
+ 渲染媒介与主体起始状态
+ 唯一核心视觉事件
+ 关键运动方向或时间锚点
```

### IMAGE_TO_VIDEO Prompt前置核心块

```text
输入首帧保护
+ 主体身份与起始状态
+ 唯一核心视觉事件
+ 关键运动方向或时间锚点
```

### FIRST_LAST_FRAME Prompt前置核心块

```text
首帧与尾帧职责及静态一致性
+ 主体起始状态
+ 唯一核心视觉事件
+ 准确接触、释放、揭示或状态切换锚点
```

## 九、风格化动画的动态编排

当前媒介包含二维、2.5D、风格化3D、游戏电影CG、定格或绘画动画时，视频Prompt除身体动作和物理因果外，还应按项目需要明确：

- 起始关键姿势和最终关键姿势；
- 剪影是否清楚；
- 预备、主动作、接触、缓冲、余韵与停留；
- 动作曲线：缓入、加速、突然停顿、过冲、回弹或分段节奏；
- 主动作和次级动作的先后；
- 头发、内外层衣料、饰物和环境的延迟帧感；
- 风格化惯性、重量和弹性；
- 哪些帧必须保持面部、手部或轮廓清楚；
- 虚拟摄影机运动与角色动画的先后关系；
- 风格化运动模糊、拖影、残像或帧率感的使用边界；
- 视觉高潮帧能否作为独立构图成立。

动画化不等于所有元素同时飘动。每镜仍只能有一个核心视觉事件。

## 十、直接文生视频完整公式

```text
当前渲染媒介
+ 主体与准确起始状态
+ 唯一核心视觉事件
+ 场景空间、景别、构图与视觉动线
+ 时间阶段或关键秒点
+ 关键姿势、动作曲线、接触与重心
+ 材质和环境的分层运动
+ 背景事件形成、扩大、高潮与收住
+ 摄影机起点、响应时机、运动曲线与终点
+ 焦点、景深、曝光、灯光、色彩和材质着色
+ 精确结束状态与稳定停留
+ 声音和下一镜连续性
+ 必须稳定与禁止漂移
```

直接文生视频可以很详细，但一条Prompt只服务一个Shot或一个连续核心事件。不能用一条长Prompt要求模型一次生成多镜头、多个场景和完整三十秒成片，同时声称角色与空间必然稳定。

## 十一、硬失败

出现以下任一情况不得进入资产或Prompt阶段：

- 完整项目没有`render_medium_lock`；
- 把“电影感”自动解释为真人实拍或照片写实；
- 用户要求风格化3D动画，Prompt仍以真人毛孔、真人写真或真实演员为核心；
- 媒介只写“动漫风、3D感、高级感”，没有角色、环境、材质、灯光和动画语言；
- 先机械规划全套资产，之后才决定生成路线；
- 所有Shot无理由统一为图生视频或纯文生视频；
- PURE_T2V镜头伪造首帧、尾帧或参考图绑定；
- 需要精确身份、手部或尾态的镜头无理由使用PURE_T2V；
- 把动漫、游戏CG、真人、二维或三维写成通用负面项；
- 为媒介适配删除原有构图、摄影、灯光、材质、表演、声音和连续性设计；
- 用一条长Prompt代替多Shot设计并承诺完整成片稳定性。
