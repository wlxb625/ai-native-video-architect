# Storyboard Frame Prompt System

## V4.4 Shot–CF绑定前置规则

在编写任何分镜帧Prompt前，先读取`prompt-engineering/shot-cf-binding-system.md`。

- CF固定表示Control Frame，只能属于一个Shot；
- 每个Shot必须有`visual_description`和非空`reference_bindings`；
- 每个需要新控制帧的Shot必须输出完整图片Prompt；
- 继承上一镜尾帧时不得留空，必须写明CF来源、持续使用资产、允许变化和备用首帧Prompt；
- 不预生成尾帧时必须建立`TEXT_CONTRACT_ONLY`结束帧合同；
- 最终Shot表、CF表、图片Prompt和视频Prompt的ID必须完全一致。


## 目标

把确认的镜头表编译为完整分镜帧Prompt包。静态帧不仅负责首帧，还负责锁定视频动作的准确终点和下一镜连续性。

## 前置条件

- 剧本或视觉脚本已确认；
- 视觉规则已建立；
- 核心人物、场景和道具已经以PLANNED_REFERENCE或ACTUAL_REFERENCE注册；
- 镜头表已完成；
- 每镜有唯一主要目的、导演意图、摄影方向、逐镜灯光、表演方向和可见输出状态。

## 分镜帧输入

每镜引用：

```yaml
frame_input:
  character_identity:
  costume_state:
  environment_plate:
  environment_angle_or_layout:
  prop_state:
  pose_or_interaction_reference:
  color_reference:
  previous_shot_output_state:
  next_shot_input_requirement:
```

## 首帧设计

首帧必须说明：

- 人物和道具准确位置；
- 动作尚未完成的起始姿态；
- 重心、朝向和视线；
- 左右手及接触点；
- 前景、中景和背景；
- 景别、机位、焦段和轴线；
- 动作所需空间；
- 起始焦点和景深；
- 当前镜头具体光源、方向、色温、亮区和暗部；
- 上一镜继承内容；
- 当前可见表演基线：视线、眼睑、嘴、呼吸、姿态、重心、手部和情绪强度。
- 当前画面的视觉命题和2—5个主要张力来源；
- 背景承担的情绪或叙事功能；
- 背景大形、近中远层次、方向和局部视觉高潮；
- 衣料、雨雾、水、火、尘等在该静态时点留下的冻结运动痕迹；
- 抽象风格词对应的具体构图、光线、色彩、空间和材质原因。

首帧不能预先完成本镜头主要动作。

## 每镜先完成“结束帧决策”

写视频Prompt前，每镜必须先回答：

1. 本镜头最后0.5秒观众具体看见什么？
2. 人物身体、视线、左右手和道具停在哪里？
3. 人物最终情绪强度、视线、呼吸、嘴、手和重心是什么？
4. 摄影机最终停在哪里，构图变成什么？
5. 焦点最终落在哪里？
6. 光线、高光和阴影是否与开始一致？
7. 下一镜需要继承哪些准确事实？
8. 该尾态能否让视频模型自由生成，还是必须预制尾帧？

没有明确尾态，不得进入视频Prompt。

## 尾帧生成判定

### 必须预制尾帧

出现以下任一情况时必须生成尾帧：

- 下一镜从当前动作结果继续；
- 人物最终姿态、头部朝向、视线或左右手位置需要准确；
- 道具被放置、翻转、打开、关闭、拿起、放下或发生状态变化；
- 人物外貌、服装、面部、情绪可见状态改变；
- 场景、天气、灯光或特效状态改变；
- 摄影机运动形成新的终点构图；
- 焦点转移后的焦点终点承担信息；
- 动作终点是选择、发现、揭示或悬念；
- 单首帧生成容易产生随机尾态。

### 可以不预制尾帧

只有以下情况可以只生成首帧：

- 环境氛围和微小循环运动；
- 人物只呼吸、眨眼或产生不影响下一镜的微动作；
- 下一镜是完全独立的硬切；
- 结尾允许从生成结果中筛选稳定帧；
- 已明确生成后抽取尾帧，并且下一镜使用该尾帧继续。

即使不预制尾帧，也必须编写文字版`END_FRAME_CONTRACT`。

## 尾帧设计

尾帧必须说明：

- 动作完成百分比；
- 人物最终姿态、朝向、视线和呼吸；
- 左右手、接触点和道具位置；
- 摄影机终点、景别和构图；
- 最终焦点、景深和曝光；
- 前中后景关系；
- 光源方向、色温、光比、高光和暗部；
- 允许保留的微动；
- 下一镜继承状态。

尾帧不能为了好看改变人物身份、场景结构或光线事实。

## 图片Prompt公式

调用`image-prompt-compiler.md`：

```text
已注册的规划或真实参考图
+ 当前准确静态瞬间与冻结运动痕迹
+ 视觉命题与主要张力来源
+ 场景空间、背景功能、大形和前中后景
+ 人物姿态、视线、左右手和道具接触
+ 可见微表情、呼吸、身体重心和情绪强度
+ 景别、焦段、机位、构图和轴线
+ 景深、焦点和曝光
+ 主光、辅光、实景光、色温、光比和阴影
+ 色彩与材质
+ 连续性锚点
+ 输出规则
+ 负面约束
```

## 灯光必须进入首尾帧

每张首帧和尾帧都必须写清：

- 主光真实来源；
- 主光屏幕方向和大致高度；
- 软硬程度；
- 色温或冷暖关系；
- 照亮人物和道具的具体区域；
- 阴影落向和暗部可读性；
- 辅光、实景灯和背景光；
- 高光控制；
- 与上一镜、下一镜的连续性。

禁止只写“冷色窗光、电影质感”。

## 同一场景下一镜一致性

使用上一张分镜作为参考时：

- 继承人物、服装、道具和场景事实；
- 继承主光来源、屏幕方向、色温、阴影方向、白平衡和曝光；
- 继承主要材质和镜面高光逻辑；
- 新镜头只改变剧本要求的动作、景别、机位和构图；
- 背景地标必须位于正确方向；
- 上一镜尾帧与下一镜首帧之间的动作进度必须一致。

## 硬切新首帧

硬切允许改变景别和机位，但必须继承：

- 人物身份、发型和服装状态；
- 道具状态、持手、朝向和接触；
- 动作完成百分比；
- 人物站位、视线和屏幕方向；
- 场景布局和背景地标；
- 主光来源、方向、色温、阴影和曝光；
- 前一镜已经建立的可见事实。

新首帧要为下一动作留下空间。

## 多人站位

复杂多人场景先锁定人物位置、朝向、比例、姿态和摄影机。换机位时人物不动，只移动摄影机。所有人物共享同一空间主光，不得各自出现不同方向的面部光。

## 九宫格使用边界

### 可用

- 连续打斗；
- 舞蹈；
- 复杂仪式；
- 物理特效；
- 多阶段动作；
- 多机位预演。

### 不应机械使用

- 普通对话；
- 静态环境；
- 简单拿起、转头、坐下；
- 已经有清楚首尾帧设计的段落。

九宫格是预演工具，不默认作为正式分镜图。

## 每镜完整输出

使用`templates/storyboard-frame-prompt-block.md`，包含：

- 镜头ID和功能；
- 时间和时长；
- 参考图及职责；
- 上一镜输出和下一镜输入要求；
- 生成模式建议；
- 首帧设计与完整Prompt；
- 结束帧合同；
- 尾帧设计与完整Prompt（需要时）；
- 表演时点、情绪强度、焦点、景深、曝光和逐镜灯光；
- 图生图与局部修复；
- 视频动作摘要；
- 连续性锚点和稳定替代。

## 输出批次

默认一次性交付整片分镜帧Prompt。内容过长可以按镜头区间分块，但必须同一轮完整交付，不逐镜等待用户确认。

## 分镜帧硬失败

- 没有结束帧决策就进入视频Prompt；
- 下一镜依赖准确尾态，却只提供无控制的单首帧；
- 首帧已经包含动作终点；
- 尾帧没有人物、手部、道具、摄影机和焦点终点；
- 首尾帧改变身份、场景结构、主光方向、色温或曝光；
- 只写“电影感、冷色窗光”，没有具体灯光；
- 只有情绪标签，没有静态可见表演；
- 微表情在当前景别、焦点或灯光下不可读；
- 静态Prompt描述完整时间过程；
- 多人站位和光线在换机位时漂移；
- 硬切新图与上一镜动作进度不连续；
- 每张图色调、焦点和曝光由模型自由决定。
