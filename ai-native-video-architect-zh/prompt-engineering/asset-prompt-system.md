# Asset Prompt System V4.6

## 规划资产注册

完整制作包允许先建立`PLANNED_REFERENCE`，无需等待图片真实生成。每个资产必须有唯一`asset_id`、用途、`used_by_shots`、项目视觉策略继承、完整正向Prompt、负面Prompt和输出规则。所有Shot引用的资产ID必须在资产表中定义。

## 目标

为S06—S07生成**覆盖实际镜头需求**、能够被外部生图模型直接执行的角色、场景、道具与状态参考。

核心原则：

> 资产不是越少越好，也不是所有项目固定做全套。先读取剧本、项目视觉策略和预期镜头覆盖，再为所有会出现的身份、角度、结构、交互、状态与空间建立充分依据。

缺少某项依据会使正式镜头产生人物、服装、手部、道具、场景或状态漂移时，该资产必须在生成分镜前建立，不能一律等待失败后再补。

本模块同时区分两层：

1. **导演控制层**：Skill内部用于检查项目视觉策略、摄影、光学、灯光、材质、构图和连续性；
2. **模型执行层**：用户直接复制到生图工具的完整正向Prompt。

导演控制层不能代替模型执行层。任何会影响生成结果的摄影、灯光、材质、色彩、空间和构图信息，都必须自然地融合进最终正向Prompt，不能只写在Prompt外面。

## 模型执行Prompt前置语义规则

Prompt的管理信息与模型执行信息必须分离。`asset_id`、作品名、剧名、章节名、场次名、文件名、版本号、内部模块名、制作说明和“用于某项目”等内容保留在Prompt外的资产登记字段中，不得占据正向Prompt开头。除非某个名称本身必须作为画面中可见文字生成，否则不得把名称语义送入模型。

不同模型的具体注意力分配并不完全相同，因此不把“前20—30个词”写成绝对技术定律；实际执行时仍把**首句或前20—30个实义词**视为高优先级语义区。这个区域只能放当前资产最重要、最可见、最不可漂移的信息。

资产正向Prompt的前置核心块按以下顺序组织：

```text
资产类型与输出任务
+ 主体身份或场景/道具本体
+ 必须覆盖的角度、结构、交互或状态
+ 最高优先级一致性锚点
```

随后再自然展开：

```text
构图与布局
+ 摄影机、焦段、角度和景深
+ 真实光源、方向、色温、软硬、亮区和阴影
+ 主色、辅助色、曝光、高光和暗部
+ 皮肤、布料、木材、金属等材质
+ 背景、比例、输出结构和禁止漂移
```

这不是删减Prompt。前置核心块只负责确定模型先理解什么，摄影、视觉、色彩、灯光、材质和输出控制仍必须完整保留。

有效开头示例：

```text
同一位已锁定年龄阶段与身份特征的东亚女性标准正侧背全身结构板，保持同一面孔、发型、服装结构和身体比例……
```

避免：

```text
《某某计划》角色资产CHAR-01，V4.6正式制作版，用于第三场和第五场……
```

真实模型引用令牌例外：当`@Actor_A`、已上传图片引用或平台规定的角色触发词确实承担身份绑定时，可以放在主体身份之前或紧邻主体；它必须是可执行绑定，不得只是内部代号。

## 一、前置条件

正式规划资产前必须具备：

- 已成立的剧本或视觉脚本；
- `NARRATIVE_LOCK`；
- 当前项目专属的`PROJECT_VISUAL_STRATEGY`；
- S04制作拆解；
- 对预期Shot景别、机位、人物角度、身体动作、手部交互、场景方向和状态变化的预分析。

只写剧本、只诊断剧本或单张图片任务，不得机械建立完整资产库。

## 角色年龄判定与连续性

角色年龄不得使用固定默认值，也不得根据“电影感、现实感、高级感、克制、疲惫、极致美学”等抽象气质词直接推定。

当用户、剧本、人物小传或已有设定已经明确年龄或年龄段时，严格继承该设定，不擅自改变人物所处的年龄阶段或生活阶段。

当年龄尚未明确时，必须结合当前项目进行判断，至少分析：

- 角色在故事中的身份与生活阶段；
- 角色承担的叙事功能；
- 故事题材、情感主题与关系结构；
- 项目的受众与传播场景；
- 当前项目的视觉审美与选角方向；
- 角色需要呈现的身体状态、行为方式与社会经验；
- 用户已经表达的审美偏好。

年龄判断必须服务具体故事，不得由通用示例、模型习惯、历史角色或创作者个人惯性代替。

年龄、外貌吸引力与人物气质属于三个不同维度：

- 年轻角色可以深刻、克制、疲惫、清冷、复杂或具有高级电影感；
- 成熟角色可以精致、明亮、灵动、脆弱或具有强烈视觉吸引力；
- “有故事感”不等于年龄较大；
- “极致美学”不等于必须年轻；
- “现实主义”不等于必须显老；
- 校园、青春、成长、初恋、毕业、少年感、少女感等项目，应主动保留与角色阶段相符的年轻感、生命力、青涩感、未完成感与情绪敏锐度；
- 家庭、婚姻、亲子、中年转折、晚年回望等项目，应根据真实人物阶段保留相应阅历、身体状态和生活痕迹。

角色年龄确定后，后续面部资产、全身资产、服装、首尾帧与视频镜头必须保持同一年龄阶段。禁止的是没有剧情依据的年龄漂移、生活阶段变化和身份重设计，不是年轻感或成熟感本身。

年龄判断属于项目专属角色设计，不得从其他项目、通用Prompt示例或历史角色中自动继承。

## 二、双层Prompt合同

### 导演控制层

内部至少检查：

```yaml
asset_director_contract:
  project_visual_strategy_reference:
  subject_identity:
  asset_function:
  covered_shot_requirements:
  composition:
  camera_and_lens:
  optical_behavior:
  lighting:
  color:
  materials:
  continuity_anchors:
  forbidden_drift:
```

这一层用于防遗漏、跨资产统一和后续分镜继承。用户只要求可复制Prompt时，不必把整张字段表展示给用户。

### 模型执行层

最终正向Prompt必须是完整自然语言，并融合：

```text
前置核心块：资产类型与输出任务 + 主体本体 + 角度/结构/交互/状态 + 一致性锚点
+ 项目视觉策略中与当前资产有关的规则
+ 构图和画面布局
+ 摄影机、焦段、角度和景深
+ 光源、方向、色温、软硬、亮区与阴影
+ 色彩、曝光和高光暗部
+ 皮肤、布料、木材、金属等材质
+ 背景、比例和输出目标
```

禁止把最终交付拆成“外貌Prompt＋Prompt外摄影合同＋Prompt外灯光合同”。正向生成需要的信息必须已经融合，用户复制一次即可。

负面Prompt和输出要求可以单独放置，但不能要求用户自行拼接正向内容。

## 三、资产覆盖矩阵

S06先建立覆盖矩阵，再决定资产数量。

### 人物覆盖检查

逐角色检查：

- 是否有中近景、近景或特写，需要独立面部身份依据；
- 是否出现正面、严格侧面、背面、转身或离场背影；
- 是否出现全身、走动、跑动、坐下、俯身、跪姿、躺卧或复杂身体方向；
- 发型、发饰、服装和配饰是否需要前后结构；
- 是否有精确手部、双手配合或手与核心道具的接触；
- 是否有伤损、污染、湿水、变装、衰老、妆容或情绪可见状态累积；
- 是否存在多个时间段或身体状态。

对应规则：

- 重要面部近景存在时，`FACE_IDENTITY`为REQUIRED；
- 正侧背、转身或背影存在时，`CHARACTER_TURNAROUND`或等效多角度结构参考为REQUIRED；
- 全身与复杂姿态反复出现时，`FULL_BODY_COSTUME`为REQUIRED；
- 发髻、服装前后层次或配饰结构重要时，`HAIR_COSTUME_STRUCTURE`为REQUIRED；
- 精确手部承担剧情时，`HAND_PROP_INTERACTION`为REQUIRED；
- 可见状态累积影响连续性时，`CHARACTER_STATE_PROGRESSION`为REQUIRED。

三视图不能单独替代面部近景；面部主参考也不能替代服装背面、发髻后部和全身比例。

### 场景覆盖检查

逐场景检查：

- 主布局、入口、出口、固定家具和地标；
- 主光的世界位置和屏幕方向；
- 是否出现正反打、反向机位、侧向机位、俯拍或低机位；
- 是否有只在某一局部发生的关键动作；
- 是否有白天、夜晚、灾前灾后、花木消失、天气或灯光状态变化；
- 镜头是否需要看见窗外、门外或相邻空间。

对应规则：

- 每个主要场景至少有`ENVIRONMENT_MASTER_PLATE`；
- 反向机位无法从主空镜可靠推断时，`ENVIRONMENT_REVERSE_ANGLE`为REQUIRED；
- 关键局部承担动作时，`ENVIRONMENT_DETAIL_PLATE`为REQUIRED；
- 空间发生连续状态变化时，`ENVIRONMENT_STATE_PROGRESSION`为REQUIRED。

不要求每个场景机械生成多机位；只为实际镜头会看见、且缺少依据容易重设计的方向建立参考。

### 道具覆盖检查

核心道具满足以下任一条件时单独注册：

- 多镜头重复出现；
- 结构容易变形；
- 尺寸影响人物交互；
- 承担剧情证据、规则或反转；
- 有页面、开合、破损、燃烧、污染、内容变化或阶段状态；
- 必须与另一个现实或画中版本精确对应。

道具状态变化影响后续镜头时，建立`PROP_STATE_PROGRESSION`、关键页面板或结构板，而不是让每个CF重新设计。

## 四、资产工作等级

等级用于说明覆盖深度，不预设视觉审美。

### EXPLORATION

仅用于概念试图、情绪测试或用户明确只要快速视觉探索。通常包含角色主参考、场景主参考和核心道具。不能声称足以支持完整成片连续性。

### NARRATIVE_PRODUCTION

用于有完整剧情、多个镜头、跨角度人物、精确交互或状态变化的短片、广告、MV和叙事视频。默认根据覆盖矩阵建立面部、正侧背结构、全身服装、手部交互、场景必要机位和状态资产。

用户要求完整制作包或正式成片时，默认至少评估此等级，不得自动退回EXPLORATION。

### STUDIO

用于长片、系列IP、多人复杂调度、多个场景时间状态、团队协作或可复用资产库。在NARRATIVE_PRODUCTION基础上进一步拆分多套服装、表情、局部结构、多机位空间和版本管理。

工作等级不能替代逐镜头覆盖检查。一个60秒单人短片也可能因手部、背影、状态和道具变化需要NARRATIVE_PRODUCTION；一个10秒纯物件实验可能不需要人物资产。

## 五、角色资产模板

### 面部身份主参考

用于锁定年龄、骨相、眉眼、鼻、嘴、下颌、皮肤、发际线和表情基线。背景低干扰，面部清楚，不承担复杂剧情动作。

### 标准人物三视图

固定结构：

- 左侧正面全身；
- 中间严格90度侧面全身；
- 右侧背面全身；
- 同一人物、同一发型、同一服装和身体比例；
- 自然直立；
- 白色或柔和米白背景；
- 头顶至脚底不裁切。

原生负面约束：不要三个不同人物，不要改变脸型、发型、服装颜色和纹样，不要把侧面变成四分之三角，不要背面回头，不要夸张动作，不要裁切头脚，不要增加场景、乱码和水印。

### 全身服装与发型结构

当三视图无法清楚表现层次时，补充服装前后层次、腰带、衣摆、鞋履、发髻侧背结构、发饰穿入方向和材质磨损位置。

### 手部与核心道具交互

锁定手型、指节、指甲、劳动痕迹、左右手分工、道具尺寸关系、接触点、握持方式和常用动作。它不是普通美手图，必须服务具体镜头动作。

### 人物状态进程

按实际剧情阶段展示污染、伤损、湿水、变装、妆容或其他可见累积。每个阶段写清首次出现、产生变化的镜头、后续继承和禁止回退。

## 六、场景和道具资产模板

### 场景空镜

完整正向Prompt必须融合：

```text
场景资产类型与布局任务
+ 时代与地点
+ 必须锁定的入口、出口、地标和主光世界位置
+ 建筑、地面和固定道具
+ 摄影机与构图
+ 真实主光来源、方向、色温和受光区域
+ 主色、曝光和暗部
+ 材质与使用痕迹
+ 当前项目背景职责
+ 禁止出现内容
```

场景图不出现主体。后续人物分镜同时引用人物参考和空镜。

### 反向或局部场景参考

必须继承主场景建筑、尺寸、地标、主光世界位置、材质和色调，只改变摄影机位置与实际可见区域，不能重新设计一个相似但不同的房间。

### 道具结构或状态板

完整正向Prompt先写道具本体、目标视角/状态和最高优先级结构锚点，再融合时代地域、材质、结构、人体比例、必要视角、摄影与柔和静物灯光、使用痕迹、状态版本和一致性要求。

## 七、最终输出格式

每项核心资产使用：

```yaml
asset:
  asset_id:
  name:
  asset_type:
  reference_status: PLANNED_REFERENCE | ACTUAL_REFERENCE
  project_visual_strategy_reference:
  purpose:
  necessity_evidence:
  covered_shot_requirements: []
  used_by_shots: []
  reference_inputs_and_roles: []
  internal_director_check:
  positive_prompt:
  negative_prompt:
  output_rules: []
```

其中：

- `asset_id`、`name`、项目名和版本名是管理字段，不得自动复制到`positive_prompt`开头；
- `necessity_evidence`说明为什么该资产不能被省略；
- `covered_shot_requirements`写明覆盖的景别、角度、交互、状态或空间方向；
- `positive_prompt`的首句必须是前置核心块，并继续包含全部相关摄影、光学、灯光、色彩和材质；
- `negative_prompt`只写当前资产最容易出现的错误；
- `output_rules`写比例、分辨率、单图或拼板、背景、裁切和文字规则。

以下字段仅在实际需要时增加：repair_prompt、stable_generation_method、detailed_dependencies、state_transition、version_matrix、technical_test。

## 八、后续分镜继承

第一张分镜使用：

```text
项目视觉策略 + 人物身份与结构参考 + 场景对应机位 + 必要道具或状态参考 + 当前镜头描述
```

下一张分镜使用：

```text
项目视觉策略 + 持续使用的身份/结构/场景/道具资产 + 上一张满意分镜 + 当前镜头描述
```

只改变当前动作、景别、拍摄角度和剧情允许变化，不改变身份、服装结构、场景结构、核心道具、主光世界位置、色调和真实材质。

## 九、图生图、局部修复与增强

图片出现局部错误时，优先声明：

> 保持人物身份、服装、场景、构图、摄影机、焦点、光线、白平衡、色调、材质和其他区域完全不变，只修改指定区域。

只有出现明确错误才生成修复Prompt，不为每项资产预写通用修复段落。

4K增强只提升清晰度、材质细节、边缘和动态范围，保持身份、姿势、构图、透视、背景、光线和色调不变，禁止重新布光、改脸和改变形体。

## 十、资产充分性检查

输出S07前必须回答：

1. 全部人物景别是否有足够面部身份依据？
2. 全部正侧背和身体动作是否有结构依据？
3. 全部精确手部动作是否有手型、尺寸和接触依据？
4. 服装、发型和配饰的前后结构是否可见？
5. 污染、伤损、湿水、变装等状态是否有进程依据？
6. 场景正反方向和关键局部是否有布局依据？
7. 道具结构、尺寸、页面和状态变化是否有依据？
8. 每项资产是否有明确使用Shot和必要性证据？
9. 是否存在只为显得专业、实际没有镜头使用的冗余资产？
10. 是否把EXPLORATION参考错误宣称为正式成片资产包？
11. `positive_prompt`是否被剧名、项目名、ID、文件名、版本号或内部说明占据开头？
12. 首句或前20—30个实义词是否已经明确资产本体、目标角度/状态和最高优先级锚点？
13. 角色年龄是否来自当前项目的明确设定或项目分析，而不是通用示例、历史角色或抽象气质词？

只有覆盖全部实际需求且没有明显冗余时，资产计划才可通过。

## 十一、禁止行为

- 将摄影、灯光和材质只写在Prompt外；
- 要求用户自行把多个字段拼成可用Prompt；
- 以“最少”为目标省略实际需要的面部、三视图、手部、状态或反向空间；
- 等实际生成失败后才补充剧本中早已明确需要的控制资产；
- 默认使用密集六宫格或让一张图承担过多不同视角；
- 机械规定每个项目都必须生成完全相同的资产清单；
