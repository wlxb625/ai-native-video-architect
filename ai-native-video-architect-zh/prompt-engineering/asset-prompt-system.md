# Asset Prompt System

## V4.4 规划资产注册

完整制作包允许先建立`PLANNED_REFERENCE`，无需等待图片真实生成。每个资产必须有唯一`asset_id`、用途、`used_by_shots`、完整正向Prompt、负面Prompt和输出规则。所有Shot引用的资产ID必须在资产表中定义。



## 目标

为S07生成最少但足够稳定、能够被外部生图模型直接执行的角色、场景与核心道具参考。

核心原则：

> 先做最少参考，直接进入分镜；只有实际生成失败或镜头确实需要时才增加控制资产。

本模块同时区分两层：

1. **导演控制层**：Skill内部用于检查摄影、光学、灯光、材质、构图和连续性；
2. **模型执行层**：用户直接复制到生图工具的完整正向Prompt。

导演控制层不能代替模型执行层。任何会影响生成结果的摄影、灯光、材质、色彩、空间和构图信息，都必须自然地融合进最终正向Prompt，不能只写在Prompt外面。

## 一、双层Prompt合同

### 1. 导演控制层

内部至少检查：

```yaml
asset_director_contract:
  subject_identity:
  asset_function:
  composition:
  camera_and_lens:
  optical_behavior:
  lighting:
  color:
  materials:
  continuity_anchors:
  forbidden_drift:
```

这一层用于防遗漏、跨资产统一和后续分镜继承。用户只要求可复制Prompt时，不必把整张字段表展示给用户。

### 2. 模型执行层

最终正向Prompt必须是完整自然语言，并融合：

```text
资产功能与主体身份
+ 构图和画面布局
+ 摄影机、焦段、角度和景深
+ 光源、方向、色温、软硬、亮区与阴影
+ 色彩、曝光和高光暗部
+ 皮肤、布料、木材、金属等材质
+ 一致性锚点
+ 背景、比例和输出目标
```

禁止把最终交付拆成：

```text
正向Prompt只有人物外貌
+ Prompt外另列摄影合同
+ Prompt外另列灯光合同
+ Prompt外另列材质要求
```

如果这些信息没有进入完整正向Prompt，模型通常无法稳定执行，直接判定不完整。

负面Prompt和输出要求可以单独放置，因为多数工具将负面词、画幅和分辨率作为独立输入或设置；但正向生成所需信息不得要求用户自行拼接。

## 二、默认资产结构

### 主要角色：默认单张身份锚点

没有指定模型能力或项目需求时，每名主要角色默认先生成**一张独立身份主参考图**，优先锁定：

- 面部身份、年龄和骨相；
- 发型和主要服装；
- 身体比例中当前镜头真正可见的部分；
- 项目统一摄影、光线和材质；
- 可供后续角色参考功能读取的清晰主体。

默认不把六个视图、面部、全身、手部和道具全部塞进一张密集六宫格。多人物拼板经常导致脸型、服装和比例不一致。

按镜头需要再决定是否补充：

- **全身服装参考**：全景、走动、身体比例或服装结构会反复出现；
- **手部与道具交互参考**：精确手部是核心叙事动作且实际生成持续失败；
- **标准人物三视图**：模型明确擅长角色表、后续工作流需要正侧背结构或用户明确要求；
- **综合角色板**：用户资料原生模板适用、模型能够稳定保持同一身份、且一张板确实能减少资产总量；
- **面部特写**：远景主参考无法稳定支持重要近景时。

不得从“默认一张身份主参考”机械升级为“每个角色固定三张”。资产数量仍由镜头需要决定。

### 主要场景

每个主要场景默认只生成一张无人物场景空镜主参考，锁定：

- 建筑和空间布局；
- 门窗、固定家具与背景地标；
- 核心道具位置；
- 主光的世界空间来源与方向；
- 主色、曝光和材质；
- 场景纵深与真实使用痕迹。

后续分镜通过场景空镜、角色参考与上一张满意分镜改变机位，不默认预制多个机位空镜。

### 核心道具

仅当道具满足以下至少一项时单独生成：

- 多镜头重复出现；
- 结构容易变形；
- 尺寸影响人物交互；
- 承担剧情证据或反转；
- 有必须跨镜头保持的连续状态变化。

普通背景工具、一次性小物以及能在场景图中清楚表现的道具，不单独建资产。

### 特殊状态

只有无法通过普通参考和当前镜头控制帧稳定完成的变化，才生成状态板，例如：

- 明确变装；
- 伤损或污染累积；
- 特效前后状态；
- 核心道具逐步变化；
- 角色面部或身体必须跨镜头保持的特殊变化。

状态板是特殊状态参考，不等于每个阶段都要独立生成一张资产。

## 三、复杂度升级

### LEAN（默认）

单张角色身份主参考 + 每个场景一张空镜 + 必要核心道具。

只有镜头实际需要时，才补全身、三视图、综合角色板或特殊状态。

### CONTROLLED（失败后升级）

只针对已经发生的问题增加：

- 面部近景身份参考；
- 全身服装结构；
- 发型结构；
- 手部与核心道具交互；
- 第二场景角度；
- 特殊状态图；
- 局部修复Prompt。

### STUDIO（用户明确要求）

用于系列IP、长片、团队协作、复杂多人动作或可复用资产库。此时才系统拆分角色、服装、表情、手部和多机位场景。

## 四、用户资料包原生模板

用户提供的资料、教程或模板优先于通用经验。以下模板保留为可选能力，不再全部作为默认。

### 艺术性角色身份板

使用16:9横图、大片留白和不对称艺术书式布局，包含大型英雄视图与少量辅助肖像、轮廓或材质研究。仅在模型可稳定保持同一身份时使用。

### 标准人物三视图

固定结构：

- 左侧正面全身；
- 中间严格90度侧面全身；
- 右侧背面全身；
- 同一人物、同一发型、同一服装和身体比例；
- 自然直立；
- 白色或柔和米白背景；
- 头顶至脚底不裁切。

原生负面约束应保留：不要三个不同人物，不要改变脸型、发型、服装颜色和纹样，不要把侧面变成四分之三角，不要背面回头，不要夸张动作，不要裁切头脚，不要增加场景、乱码和水印。

### 面部特写与三视图组合

左半边面部特写，右半边正面、侧面、背面全身。只在用户指定、模型测试可用或工作流明确需要一图多视角时采用。

### 人物细节与道具综合板

大型人物主视图周围加入少量面部、服装材质、手部或核心道具。图像之间必须分离、有留白、不得重叠。它可以替代多个独立资产，但前提是身份一致性测试通过。

### 场景空镜

场景完整正向Prompt必须融合：

```text
时代与地点
+ 场景功能和空间布局
+ 建筑、地面和固定道具
+ 摄影机与构图
+ 真实主光来源、方向、色温和受光区域
+ 主色、曝光和暗部
+ 材质与使用痕迹
+ 禁止出现内容
```

场景图不出现主体。后续人物分镜同时引用人物参考和空镜。

### 道具三视图

完整正向Prompt融合：道具名称、时代地域、材质、结构、人体比例、正侧背或底部视图、摄影与柔和静物灯光、使用痕迹、中性背景和一致性要求。

## 五、最终输出格式

LEAN模式下，每项核心资产使用：

```yaml
asset:
  name:
  file_name:
  purpose:
  reference_inputs_and_roles: []
  internal_director_check:
  positive_prompt:
  negative_prompt:
  output_rules: []
```

其中：

- `internal_director_check`用于Skill自检，可在用户只要Prompt时省略展示；
- `positive_prompt`必须已经包含全部相关摄影、光学、灯光、色彩和材质，用户复制一次即可；
- `negative_prompt`只写当前资产最容易出现的错误；
- `output_rules`写比例、分辨率、单图或拼板、背景、裁切和文字规则。

以下字段仅在实际需要时增加：repair_prompt、stable_generation_method、detailed_dependencies、state_transition、version_matrix、technical_test。

## 六、后续分镜继承

第一张分镜使用：

```text
人物参考 + 场景空镜 + 必要道具参考 + 当前镜头描述
```

下一张分镜使用：

```text
人物参考 + 场景空镜 + 上一张满意分镜 + 当前镜头描述
```

只改变当前动作、景别和拍摄角度，不改变身份、服装、场景结构、核心道具、主光世界位置、色调和真实材质。

## 七、图生图、局部修复与增强

图片出现局部错误时，优先声明：

> 保持人物身份、服装、场景、构图、摄影机、焦点、光线、白平衡、色调、材质和其他区域完全不变，只修改指定区域。

只有出现明确错误才生成修复Prompt，不为每项资产预写通用修复段落。

4K增强只提升清晰度、材质细节、边缘和动态范围，保持身份、姿势、构图、透视、背景、光线和色调不变，禁止重新布光、改脸和改变形体。

## 八、资产数量检查

输出S07前必须回答：

1. 该资产是否会被多个镜头直接引用？
2. 不生成它，是否真的导致一致性失败？
3. 能否合并进现有主参考、场景空镜或道具板？
4. 是不是只为了流程显得专业？
5. 能否等第一次失败后再补？
6. 多视图板是否真的比单张身份参考更稳定？

不满足必要性时，不列为REQUIRED资产。

## 九、禁止行为

- 将摄影、灯光和材质只写在Prompt外，最终正向Prompt不包含；
- 要求用户自行把多个字段拼成可用Prompt；
- 默认使用密集六宫格或让一张图承担过多不同视角；
- 默认把每个角色固定拆成面部、全身和手部三张；
- 将面部、发型、服装、鞋履、手部和动作全部设为必做；
- 每个场景先做多个机位空镜；
- 为普通动作提前生成人体交互测试；
- 资产数量与短片时长、角色数和场景数不成比例；
- 擅自把扩展经验描述成用户资料包原文；
- 用复杂Asset Registry替代实际可用参考图。
