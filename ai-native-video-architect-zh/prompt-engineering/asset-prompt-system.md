# Asset Prompt System

## 目标

为S07生成最少但足够稳定的角色、场景和核心道具参考。默认不建立完整影视资产库，而是服务短片快速生产。

核心原则：

> 先做最少参考，直接进入分镜；只有实际生成失败时才增加控制资产。

## 默认资产结构

### 主要角色

每名主要角色默认只生成以下二选一：

1. 标准人物三视图；或
2. 综合角色板。

综合角色板可在一张16:9横图中同时包含：

- 大型人物全身主视图；
- 面部特写；
- 正面、严格侧面和背面全身；
- 服装与材质细节；
- 手部或核心道具；
- 少量表情或姿态研究。

不得默认再拆分面部身份板、发型板、服装板、手部板、鞋履板和动作板。

### 主要场景

每个主要场景默认只生成一张无人物空镜主参考，锁定：

- 建筑与空间布局；
- 门窗和固定家具；
- 核心道具位置；
- 光源方向；
- 主色调与材质；
- 场景纵深。

后续分镜通过该空镜、人物参考和上一张满意分镜改变机位。不得默认预制多个机位空镜。

### 核心道具

仅当道具满足以下至少一项时单独生成：

- 多镜头重复出现；
- 结构容易变形；
- 尺寸影响人物交互；
- 承担剧情反转；
- 有连续状态变化。

普通背景工具、一次性小物和可在场景图中清楚表现的道具不单独建资产。

### 特殊状态

只有无法通过普通参考图和文字稳定完成的变化才生成状态板，例如：

- 明确变装；
- 伤损累积；
- 特效前后状态；
- 核心道具逐步变化；
- 角色面部或身体必须跨镜头保持的特殊变化。

多状态可以优先放在一张状态板中，不必每个状态生成独立文件。

## 复杂度升级

### LEAN（默认）

角色综合板或三视图 + 场景空镜 + 必要核心道具。

### CONTROLLED（失败后升级）

仅针对已发生的问题增加：

- 面部参考；
- 服装细节；
- 发型结构；
- 手部与道具交互；
- 第二场景角度；
- 特殊状态图；
- 局部修复Prompt。

### STUDIO（用户明确要求）

用于系列项目、长片、团队协作、复杂多人动作或可复用IP资产库。此时才可完整拆分所有角色和场景资产。

## 用户资料包原生模板

### 艺术性角色身份板

使用16:9横图、大片留白、不对称艺术书式布局。包含大型英雄全身视角和少量辅助肖像、轮廓、表情与细节研究。避免标准九宫格、密集表格、人物重叠和裁切。

该模板适合快速确认角色整体气质和作为后续参考。

### 标准人物三视图

固定结构：

- 左侧正面全身；
- 中间严格90度侧面全身；
- 右侧背面全身；
- 同一人物、同一发型、同一服装、同一配饰和身体比例；
- 自然直立；
- 白色或柔和米白背景；
- 头顶至脚底不裁切。

原生负面约束应保留：

- 不要三个不同人物；
- 不要改变脸型、发型、服装颜色和纹样；
- 不要侧面变成四分之三角；
- 不要背面回头；
- 不要夸张动作；
- 不要裁切头脚；
- 不要增加场景和无关道具；
- 不要人物重叠、乱码和水印。

### 面部特写与三视图组合

一张图：左半边面部特写，右半边正面、侧面、背面全身。适合角色数量少、希望一张图同时锁定脸和身体的项目。

### 人物细节与道具综合板

16:9横图，大型人物全身主视图，周围加入面部近景、侧面头像、手部、服装材质、鞋履、核心道具和少量辅助道具。图像之间必须分离、有留白、不得重叠。

该模板优先替代多个独立的服装、手部和道具资产。

### 场景空镜

场景Prompt至少包含：

```text
时代背景
+ 具体地点
+ 场景功能
+ 空间布局
+ 建筑与地面
+ 固定道具
+ 光线方向
+ 主色调
+ 真实使用痕迹
+ 禁止出现内容
```

场景图不出现主体。后续人物分镜同时引用人物参考与空镜。

### 道具三视图

道具名称 + 时代与地域 + 材质 + 结构 + 人体比例 + 正侧背或底部 + 使用痕迹 + 状态变化 + 中性背景 + 负面约束。

## 后续分镜继承

第一张分镜使用：

```text
人物参考 + 场景空镜 + 当前镜头描述
```

下一张分镜使用：

```text
人物参考 + 场景空镜 + 上一张满意分镜 + 当前镜头描述
```

只改变人物动作、景别和拍摄角度，不改变人物身份、服装、场景结构、核心道具、光线方向、主色调和真实摄影质感。

## Prompt输出字段

LEAN模式下，每项核心资产只需要：

```yaml
asset:
  name:
  file_name:
  purpose:
  reference_inputs: []
  prompt:
  negative_constraints:
  output_rules: []
```

以下字段只在实际需要时增加：

- repair_prompt；
- stable_generation_method；
- detailed_dependencies；
- state_transition；
- version_matrix；
- technical_test。

不得为了形式完整，把每个简单资产写成冗长生产合同。

## 图生图与局部修复

图片出现局部错误时，优先声明：

> 保持人物身份、服装、场景、构图、光线、色调和其他区域完全不变，只修改指定区域。

只有出现明确错误才生成修复Prompt，不为每项资产预先附带通用修复段落。

## 4K增强

只提升清晰度、材质细节、边缘和动态范围，保持人物身份、姿势、构图、透视、背景、光线、白平衡和色调不变。禁止重新布光、改脸和改变形体。

## 资产数量检查

在输出S07前必须回答：

1. 该资产是否会被多个镜头直接引用？
2. 不生成它，是否真的会导致一致性失败？
3. 它能否合并进角色综合板、场景空镜或道具状态板？
4. 它是否只是为了让流程显得专业？
5. 它是否可以等第一次失败后再补？

第2项为否，或第3、第4、第5项为是时，默认不作为REQUIRED资产。

## 禁止行为

- 将面部、发型、服装、围裙、手部、动作全部设为必做；
- 每个场景先做多个机位空镜；
- 为普通动作提前生成人体交互测试；
- 为每个资产预写修复Prompt和失败报告；
- 资产数量与短片时长、角色数和场景数不成比例；
- 擅自把扩展经验描述成用户资料包原文；
- 用复杂Asset Registry替代实际可用的参考图。
