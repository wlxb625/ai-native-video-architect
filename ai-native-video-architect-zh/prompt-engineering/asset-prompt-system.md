# Asset Prompt System V4.7

编译前读取：

- `prompt-engineering/render-medium-generation-route-contract.md`；
- 当前项目`RENDER_MEDIUM_LOCK`；
- 项目级和逐镜`GENERATION_ROUTE_PLAN`；
- 当前项目视觉策略；
- 预期Shot的景别、角度、动作、交互、状态和连续性需求。

## 一、目标

为实际会被Shot和生成平台使用的角色、场景、道具、状态、Lookdev与控制帧依据建立完整资产Prompt。

核心原则：

> 资产不是越少越好，也不是越全越专业。先确定作品以什么媒介存在、每个Shot走哪条生成路线，再为身份、结构、交互、状态、空间与媒介一致性建立充分但不冗余的依据。

缺少某项依据会导致正式镜头出现身份、服装、手部、道具、场景、状态或媒介漂移时，该资产属于必要资产。没有实际Shot与路线使用的资产应删除。

## 二、规划资产与真实资产

完整制作包允许先建立`PLANNED_REFERENCE`，无需等待图片真实生成；但不能把规划状态声称为真实可用参考。

```text
PLANNED_REFERENCE：已设计用途、Prompt与输出规则，图片尚未生成或选定。
ACTUAL_REFERENCE：用户已生成、上传、选定并可被后续平台实际读取。
```

每个资产必须有唯一`asset_id`、用途、`used_by_shots`、`generation_route_roles`、渲染媒介继承、完整正向Prompt、负面Prompt和输出规则。

## 三、导演控制层与模型执行层

### 导演控制层

```yaml
asset_director_contract:
  render_medium_reference:
  generation_route_roles: []
  project_visual_strategy_reference:
  subject_identity:
  asset_function:
  necessity_evidence:
  covered_shot_requirements:
  composition:
  camera_or_view_translation:
  lighting:
  color:
  materials_and_shading:
  continuity_anchors:
  forbidden_drift:
```

### 模型执行层

最终正向Prompt必须是完整自然语言，并融合：

```text
当前媒介中的资产类型与输出任务
+ 主体本体
+ 必须覆盖的角度、结构、交互或状态
+ 最高优先级一致性锚点
+ 项目视觉策略与媒介规则
+ 构图和画面布局
+ 摄影机、观察角度或媒介等效关系
+ 光源或明暗来源、方向、色彩和受光区域
+ 色彩、曝光或明度、高光与暗部
+ 角色表面、头发、布料、木材、金属等材质与着色
+ 背景、比例、输出目标和禁止漂移
```

禁止把最终交付拆成“外貌Prompt＋Prompt外摄影合同＋Prompt外灯光合同”。用户复制一次即可执行。

## 四、Prompt前置语义规则

`asset_id`、作品名、剧名、章节名、场次名、文件名、版本号、内部模块名和制作说明属于管理信息，不得占据正向Prompt开头。

实际执行时仍将首句或前20—30个实义词作为高优先级语义区，但不把它写成所有模型一致的硬定律。

前置核心块按以下顺序：

```text
当前渲染媒介中的资产类型与输出任务
+ 主体身份、场景或道具本体
+ 必须覆盖的角度、结构、交互或状态
+ 最高优先级一致性锚点
```

有效示例：

```text
同一位已锁定年龄与身份的风格化3D动画女主标准正侧背全身结构板，保持同一面部设计、发束造型、服装切片和身体比例……
```

避免：

```text
《某某计划》角色资产CHAR-01，V4.7正式制作版，用于第三场和第五场……
```

真实模型引用令牌、上传图引用或平台规定触发词确实承担绑定时，可以前置；内部ID不得伪装为模型绑定。

## 五、媒介继承

资产Prompt必须按`RENDER_MEDIUM_LOCK`翻译。

### 真人实拍或照片写实CG

可以使用现实演员骨相、自然皮肤区域差异、真实服装工艺、现实材质、摄影光学与物理磨损。

### 风格化3D动画

必须明确：

- 角色建模与风格化程度；
- 面部比例、眼睛、骨相平面和轮廓；
- 受控次表面散射或项目表面着色器；
- 发束、发片或曲线毛发造型；
- 服装大轮廓、切片、褶皱、重量和着色；
- 环境形体、材质和人物是否使用同一曲线、折面、连接与受力语法；
- 动画电影灯光与目标完成度。

不得生成真人证件照、真人写真、真人CG替身、蜡像皮肤或普通游戏截图。

### 二维、2.5D、绘画、水墨、定格与其他媒介

按当前项目的线条、色块、笔触、纸面、墨色、实体材料、模型接缝、帧间质感和合成规则翻译。不得机械使用真人毛孔、PBR皮肤和照片噪点。

任何媒介都不能成为通用负面项。只排除当前项目明确禁止的媒介漂移。

## 六、年龄与身份判定

角色年龄不得使用固定默认值，也不得根据电影感、现实感、高级感、克制、疲惫或极致美学等抽象词直接推定。

用户、剧本、人物小传或已有设定已经明确时直接继承。未明确时，根据：

- 身份与生活阶段；
- 叙事功能；
- 题材、情感主题与关系结构；
- 受众与传播场景；
- 项目审美与选角方向；
- 身体状态、行为方式与社会经验；
- 用户偏好。

年轻感、成熟感和老年感都可以成为有效资源。禁止的是没有剧情依据的年龄漂移、生活阶段变化和身份重设计。

## 七、先建立Shot路线覆盖矩阵

正式规划资产前先列：

|Shot|生成路线|精确身份|精确首帧|精确尾帧|手部/接触|场景状态|实际参考需求|
|---|---|---|---|---|---|---|---|
||||||||

根据矩阵决定资产，不得先套固定清单。

### PURE_T2V占比高

优先评估：

- 项目媒介与世界Lookdev；
- 角色反复出现时的身份或造型参考；
- 核心材质与运动语言；
- 结构容易被错误替代的道具或规则。

不机械生成全部面部板、三视图、机位、状态和首尾帧。

### REFERENCE_T2V占比高

建立平台会实际读取并被多个Shot复用的：

- 角色身份或Lookdev；
- 服装结构；
- 场景语言；
- 核心道具；
- 风格、材质和灯光参考。

每张参考职责必须单一清楚，不把参考图自动当首帧。

### IMAGE_TO_VIDEO占比高

建立必要的身份、服装、场景和道具母参考，再按依赖生成准确首帧。尾态允许文字控制时不机械生成尾帧。

### FIRST_LAST_FRAME占比高

建立必要母参考、起点、终点和桥接依据。精确手部、袖口、开合、破损和状态变化按镜头需要补充。

### HYBRID项目

先完成逐镜路线矩阵，再汇总资产。每个资产写清为哪些Shot的哪条路线服务。

## 八、人物覆盖检查

逐角色检查：

- 是否有重要近景，需要独立面部或角色设计依据；
- 是否出现正面、严格侧面、背面、转身或离场背影；
- 是否出现全身、走动、跑动、坐下、俯身、跪姿、躺卧或复杂方向；
- 发型、服装和配饰是否需要前后结构；
- 是否有精确手部、双手配合或核心道具接触；
- 是否有伤损、污染、湿水、变装、衰老、妆容或情绪可见状态累积；
- 是否存在多个时间段或身体状态；
- 当前媒介是否需要角色Lookdev、表面着色、发束和服装材质板；
- 这些信息是否已经由真实参考覆盖。

对应资产按需选择：

- `FACE_IDENTITY`；
- `CHARACTER_LOOKDEV`；
- `CHARACTER_TURNAROUND`；
- `FULL_BODY_COSTUME`；
- `HAIR_COSTUME_STRUCTURE`；
- `HAND_PROP_INTERACTION`；
- `CHARACTER_STATE_PROGRESSION`。

三视图不能替代重要面部近景；面部主参考也不能替代服装背面、发型后部和全身比例。Lookdev母图不能替代精确结构板，结构板也不能替代最终审美母图。

## 九、场景覆盖检查

逐场景检查：

- 主布局、入口、出口、固定物件和地标；
- 主光或主明暗世界位置；
- 是否出现正反打、反向机位、俯拍或低机位；
- 是否有关键局部动作；
- 是否有白天、夜晚、灾前灾后、天气、灯光或空间状态变化；
- 是否需要看见窗外、门外或相邻空间；
- 当前媒介中的环境建模、线条、笔触、材质和着色是否需要独立Lookdev；
- 宏观变化是否由PURE_T2V承担，是否真的需要固定母场景。

按需选择：

- `ENVIRONMENT_LOOKDEV`；
- `ENVIRONMENT_MASTER_PLATE`；
- `ENVIRONMENT_REVERSE_ANGLE`；
- `ENVIRONMENT_DETAIL_PLATE`；
- `ENVIRONMENT_STATE_PROGRESSION`。

不要求每个场景机械生成多机位；只为实际会看见且缺少依据容易重设计的方向建立参考。

## 十、道具与规则覆盖检查

核心道具满足以下任一条件时单独注册：

- 多镜头重复出现；
- 结构容易变形；
- 尺寸影响人物交互；
- 承担剧情证据、规则或反转；
- 有页面、开合、破损、燃烧、污染、内容或阶段变化；
- 必须与另一个版本精确对应；
- 材质容易被模型替代为光束、液体、塑料、金属或其他错误类型。

按需选择结构、材质、交互和状态资产。道具状态变化影响后续镜头时，建立`PROP_STATE_PROGRESSION`或关键状态板。

## 十一、资产工作等级

### EXPLORATION

用于概念试图、媒介测试、情绪测试或快速视觉探索。通常只包含角色Lookdev、场景Lookdev和核心道具。不能声称足以支持完整成片连续性。

### NARRATIVE_PRODUCTION

用于完整剧情、多个镜头、跨角度人物、精确交互或状态变化。根据路线矩阵建立足够的身份、结构、交互、场景和状态依据。

### STUDIO

用于长片、系列IP、多人复杂调度、多个场景状态、团队协作或可复用资产库。在生产级基础上进一步拆分多套服装、表情、局部结构、多机位空间、材质Lookdev和版本管理。

工作等级不能替代逐镜覆盖检查。

## 十二、角色资产模板

### 面部身份主参考

锁定年龄、面部设计、眉眼、鼻、嘴、下颌、皮肤或表面着色、发际线和表情基线。背景低干扰，不承担复杂动作。

### 角色Lookdev母图

锁定角色在项目世界中的最终审美：面部、头发、服装、表面着色、光线、姿态、与环境共同设计语言及目标完成度。它不替代结构板。

### 标准人物三视图

- 正面全身；
- 严格90度侧面全身；
- 背面全身；
- 同一人物、同一媒介、同一面部设计、发型、服装和比例；
- 自然直立；
- 低干扰背景；
- 头顶至脚底不裁切。

禁止三个不同人物、侧面变四分之三、背面回头、服装和媒介改变、裁切和乱码。

### 全身服装与发型结构

补充服装前后层次、袖管、衣摆、鞋履、发型侧背结构、配饰穿入方向、材质和受力大形。

### 手部与核心道具交互

锁定手型、指节、指甲或风格化手部设计、左右手分工、道具尺寸、接触点、握持方式和具体动作。必须服务真实Shot。

### 人物状态进程

展示污染、伤损、湿水、变装、妆容或其他可见累积。每阶段写清首次出现、产生变化的镜头、后续继承和禁止回退。

## 十三、场景、材质与道具资产模板

### 场景Lookdev

锁定当前媒介中的空间形体、色彩、材质、着色、光影、空气、人物尺度和目标完成度。不是泛化概念图。

### 场景空镜

完整Prompt融合：

```text
当前媒介中的场景资产类型与布局任务
+ 时代与地点
+ 入口、出口、地标和主光位置
+ 建筑、地面和固定道具
+ 摄影机或观察构图
+ 光源或主明暗、方向、色彩和受光区
+ 主色、明度、高光与暗部
+ 材质与当前媒介着色
+ 背景职责
+ 禁止内容与媒介漂移
```

场景图不出现主体。后续人物分镜同时引用人物和场景参考。

### 反向或局部场景参考

继承主场景建筑、尺寸、地标、主光、材质、色调和媒介，只改变观察位置和可见区域。

### 材质与运动语言板

当核心材质会跨镜运动或容易被错误替代时，展示自然、受力、松弛、破损、流动或其他实际状态，并锁定当前媒介中的表面与动态语言。

### 道具结构或状态板

先写道具本体、目标视角或状态和结构锚点，再融合尺寸、材料、工艺、摄影或媒介等效灯光、使用痕迹、状态版本和一致性要求。

## 十四、最终输出格式

每项资产使用：

```yaml
asset:
  asset_id:
  name:
  asset_type:
  reference_status: PLANNED_REFERENCE | ACTUAL_REFERENCE
  render_medium_reference:
  project_visual_strategy_reference:
  purpose:
  necessity_evidence:
  generation_route_roles: []
  covered_shot_requirements: []
  used_by_shots: []
  reference_inputs_and_roles: []
  internal_director_check:
  positive_prompt:
  negative_prompt:
  output_rules: []
```

其中：

- 管理字段不得复制到正向Prompt开头；
- `necessity_evidence`说明为什么不能省略；
- `generation_route_roles`说明服务参考文生、图生、首尾帧、后期还是独立图片；
- `positive_prompt`必须完整包含媒介、构图、光线、色彩、材质和输出控制；
- `negative_prompt`只写当前资产最容易出现的错误和项目明确禁止的媒介漂移；
- `output_rules`写比例、分辨率、单图或拼板、背景、裁切和文字规则。

只有实际需要时增加修复Prompt、稳定生成方法、状态转移、版本矩阵或技术测试。

## 十五、后续分镜继承

使用参考的分镜：

```text
项目媒介与视觉策略
+ 人物身份或Lookdev
+ 场景对应机位
+ 必要道具或状态参考
+ 当前镜头静态状态
```

下一张控制帧再加入上一张已选定控制帧。只改变当前动作、景别、角度和剧情允许变化，不改变身份、服装、场景、道具、主光、色彩、材质和媒介。

PURE_T2V镜头不应为了继承公式而伪造分镜帧。

## 十六、图生图、修复与增强

局部错误优先声明：

> 保持人物身份、渲染媒介、角色设计、服装、场景、构图、摄影机、光线、色彩、材质、着色和其他区域完全不变，只修改指定区域。

只有出现明确错误才生成修复Prompt。增强只提升清晰度、纹理连续性、边缘、暗部和压缩质量，禁止改脸、改形体、改媒介和重新布光。

## 十七、资产充分性检查

输出资产Prompt前回答：

1. 每个资产是否有实际Shot和生成路线用途？
2. PURE_T2V镜头是否被错误强迫生成控制资产？
3. 重要人物景别是否有足够身份或角色设计依据？
4. 正侧背和身体动作是否有必要结构依据？
5. 精确手部是否有手型、尺寸和接触依据？
6. 服装、发型和配饰前后结构是否可见？
7. 状态累积是否有进程依据？
8. 场景必要方向和关键局部是否有布局依据？
9. 道具结构、尺寸和状态是否有依据？
10. 角色、服装和环境是否继承同一渲染媒介？
11. 是否存在只为显得专业的冗余资产？
12. 是否把EXPLORATION参考错误宣称为正式资产包？
13. Prompt是否被剧名、项目名、ID和内部说明占据开头？
14. 每个完整Prompt是否因汇总而被缩减？

## 十八、禁止行为

- 在`RENDER_MEDIUM_LOCK`和`GENERATION_ROUTE_PLAN`之前规划固定全套资产；
- 把真人、动漫、3D、二维或游戏CG设为默认或通用负面；
- 风格化3D角色生成真人写真和真人CG替身；
- 角色与环境使用不同媒介语言；
- 将摄影、灯光、材质和着色只写在Prompt外；
- 要求用户自行拼接多个字段；
- 以最少为目标省略实际需要的身份、结构、手部、状态和空间；
- 等失败后才补剧本早已明确需要的控制资产；
- 默认密集六宫格或让一张图承担过多视角；
- 机械规定每个项目相同资产清单；
- 用面部图代替服装背面和全身结构；
- 用三视图代替重要面部和最终Lookdev；
- 为没有人物的项目创建人物资产；
- 为普通一次性物件创建冗余资产；
- 资产数量与Shot路线没有关系；
- 把作品名、ID、版本号和说明放在Prompt开头；
- 为前置权重删除摄影、构图、灯光、色彩、材质、着色、背景和输出控制；
- 为方便批量执行而缩短每个资产完整Prompt。
