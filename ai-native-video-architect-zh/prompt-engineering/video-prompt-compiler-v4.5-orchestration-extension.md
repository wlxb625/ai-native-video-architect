# Video Prompt Compiler V4.5 Orchestration Extension

## 作用

本文件是`video-prompt-compiler.md`的增量扩展。原编译器关于首帧保护、唯一核心事件、人物身体部位动作、材质分层、背景事件、摄影机运动、灯光、表演、时间轴和结束帧合同全部保留。

本扩展解决的问题是：这些系统虽然分别写得详细，却仍可能无意各动各的。它增加的是关系选择、时序统筹和跨镜头感知接力，不规定固定的运动顺序。

## 必读

适用镜头编译前读取：

- `references/test-learning-abstraction-protocol.md`；
- `controllers/temporal-visual-orchestration.md`；
- `templates/temporal-visual-orchestration-block.md`；
- `evals/temporal-visual-orchestration-check.md`。

## 一、先选择关系，再写动作

编译前必须决定：

1. 当前镜头由人物、环境、摄影机、灯光、声音、道具、群体还是形式规则主导；
2. 其他系统是响应、同步、预示、延迟、对位、抵抗、部分脱节还是独立；
3. 摄影机、灯光、环境与声音各自承担什么时序角色；
4. 镜头如何从初始关系发展到峰值或揭示；
5. 精确结束时这些系统处于什么关系；
6. 哪些感知通道交给下一镜，或者为何有意断裂。

不得默认：

- 人物先动；
- 背景响应人物；
- 摄影机随后跟随；
- 灯光依附动作变化；
- 声音必须卡点；
- 相邻镜头必须形状匹配。

## 二、关系编译公式

在原视频Prompt公式中加入：

```text
导演形式与场景功能
+ 主导系统和参与系统
+ 耦合方式与项目证据
+ 初始关系
+ 领先、响应、保持、对抗或脱节的时间顺序
+ 摄影机时序角色
+ 灯光事件关系
+ 环境关系
+ 声音时序角色
+ 能量、信息或注意力传递
+ 发展、峰值、收束与精确结束关系
+ 跨镜头感知连续通道或有意断裂
```

## 三、不同关系的自然语言编译

### 因果

写清触发、延迟、响应对象和结果。不能只写“背景随人物变化”。

### 同步

写清多个系统共同服从的拍点、机械规则、空间规律、群体纪律或形式模式。不能让所有元素同幅度一起摇动。

### 预示

写清哪个系统提前多少、透露什么、不透露什么，以及人物何时察觉。

### 延迟

写清响应滞后的时间、原因和效果。延迟可以表达重量、规模、迟来的情绪或喜剧节拍。

### 对位

写清两个系统在方向、节奏、情绪或语义上的差异，以及观众应感到的冲突。

### 抵抗

写清摄影机、环境、光线或道具如何拒绝顺从主体，以及主体如何受阻。

### 部分脱节

写清哪些通道仍连续、哪些通道故意错位，以及稳定形式规则。

### 独立

写清各系统独立运行的原因和边界。无理由独立通常属于随机漂移。

## 四、摄影机编译补充

原规则“摄影机只响应主事件”应理解为摄影机必须服务主事件，而不是固定在事件之后运动。

根据当前项目可编译为：

- 摄影机先运动并发现信息；
- 摄影机与人物同步；
- 人物运动而摄影机保持；
- 摄影机随后跟随；
- 摄影机与主体反向或保持距离；
- 摄影机故意失稳；
- 摄影机运动本身完成揭示。

必须写开始时间、先后关系、停止条件和竞争运动控制。

## 五、灯光编译补充

灯光变化可由真实光源、空间遮挡、道具状态、天气、故事规则、音乐形式或其他明确机制触发，也可以保持不变。

编译时选择：

- 揭示；
- 跟随；
- 预示；
- 反差；
- 隔离；
- 忽视；
- 稳定；
- 与形式同步；
- 项目专属规则。

“灯光不变化”可以是重要导演选择。禁止为了让视频更丰富而无原因闪烁、变色或移动。

## 六、环境编译补充

环境不是默认第二主角，也不是默认响应人物。根据项目选择：

- 支持；
- 响应；
- 发起；
- 对抗；
- 忽视；
- 容纳；
- 延迟；
- 镜像；
- 误导；
- 崩塌；
- 保持中性；
- 项目专属。

环境保持稳定时，Prompt也应明确哪些区域绝对不动，避免模型自动增加漂浮、光粒和背景呼吸。

## 七、材质与运动关系

材质不必每次转化，也不必都服从人物动作。编译前判断材质承担：

- 真实物理运动；
- 情绪放大；
- 空间阻力；
- 形式节奏；
- 注意力引导；
- 状态变化；
- 中性背景；
- 有意错位。

发生转化时，选择一个或多个感知连续通道：形状、运动、节奏、颜色、亮度、材质、位置、尺度、语义、声音或情绪能量。也可以明确使用有意断裂。

不得把“形状、方向或速度必须继承”写成所有转化的固定门槛。

## 八、声音与剪辑关系

声音可以：

- 领先画面；
- 跟随动作；
- 同步峰值；
- 与画面形成对位；
- 跨镜头桥接；
- 在关键处撤去形成空白。

剪辑可以通过形状、运动、节奏、色彩、亮度、材质、位置、尺度、语义、视线、声音或情绪能量建立连续，也可以使用有意断裂。

不得把卡点、形态匹配和运动遮挡写成所有项目默认。

## 九、Prompt结构建议

适用镜头的最终正向Prompt按以下顺序组织：

```text
首帧保护与输入模式
→ 镜头任务、导演形式与主场景功能
→ 当前主导系统、参与系统和耦合关系
→ 初始关系
→ 人物、道具、环境、摄影机、灯光和声音的先后与保持项
→ 核心动作或事件的发展
→ 峰值、揭示或关系破裂
→ 收束、冻结或运动中切断
→ 精确结束关系
→ 下一镜连续通道或有意断裂
→ 稳定项和针对性负面约束
```

枚举名不能直接作为最终Prompt主体，必须转译成当前镜头可见和可听的描述。

## 十、负面Prompt补充

针对当前关系防止：

- 所有元素同时无差别运动；
- 摄影机自动跟随或自动环绕；
- 背景自动回应人物；
- 灯光自动闪烁、变色或跟随摄影机；
- 声音与动作机械卡点；
- 材质无原因转化；
- 有意静止区域产生随机漂浮；
- 对位、抵抗或脱节被模型自动修成同步；
- 需要连续时出现无原因跳变；
- 需要断裂时被平滑变形连接。

## 十一、单镜与序列检查

编译后执行：

- 单镜：`temporal-visual-orchestration-check.md`；
- 完整序列：检查关系变化、密度呼吸、连续通道和机械重复；
- 参考案例学习：检查是否把具体手法错误升级为默认。

## 十二、硬失败

- 在Prompt中默认复刻参考视频的运动顺序；
- 只把人物、背景、摄影机和灯光动作并列罗列；
- 未定义主导权或共享规则；
- 耦合方式与项目证据无关；
- 摄影机、灯光和环境关系互相冲突；
- 每镜机械重复同一种响应链；
- 枚举字段存在于制作卡，但最终Prompt没有可执行体现；
- 有意断裂或静止被自动当成错误修复。
