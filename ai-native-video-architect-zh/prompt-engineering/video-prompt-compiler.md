# Video Prompt Compiler V4.6

V4.6编译前同时读取`controllers/camera-director.md`、`controllers/lighting-director.md`、`controllers/performance-director.md`、`references/emotion-library.md`和`prompt-engineering/performance-prompt-compiler.md`。

## Prompt覆盖前置规则

在编译视频Prompt前读取`prompt-engineering/shot-cf-binding-system.md`。

每个生成型Shot必须同时具备：可见画面描述、参考绑定、图像来源、Start CF或继承帧、结束帧合同、生成模式和一条独立可复制的视频Prompt。

`POST_ONLY`镜头不写伪视频Prompt，但必须写明素材来源、后期操作、时长、剪辑点和连续性。

禁止因为镜头是过渡、空镜或继承上一镜而省略Prompt块。

## 目标

把已批准的分镜帧、镜头设计、灯光设计和连续性计划编译成可直接用于图生视频软件的导演级Prompt。

动态时间控制只负责让既有导演设计在正确时点发生、形成明确因果并准确收住，不得把完整镜头设计压缩成纯时间表。

## 模型执行Prompt前置语义规则

Shot ID、Scene ID、CF ID、作品名、剧名、章节名、场次标题、镜头标题、文件名、版本号、导演解释、剧情主题和“用于某项目”等内容属于管理信息，必须留在视频Prompt块之外。除非某段文字必须实际出现在画面中，否则不得让这些语义占据模型执行Prompt开头。

不同视频模型的具体注意力分配和指令解析方式并不完全相同，因此不把“前20—30个词权重最高”写成所有模型一致的硬定律；实际编译时仍把**首句或前20—30个实义词**作为高优先级执行区。此区域只放当前镜头最关键、最可执行、最不可漂移的信息。

图生视频Prompt的前置核心块按以下顺序组织：

```text
真实模型引用令牌或输入帧锁定
+ 主体身份与起始状态
+ 唯一核心视觉事件
+ 最重要的时间锚点或运动方向
```

随后继续完整展开：

```text
首帧身份、美术、构图与场景保护
+ 分秒动作、身体部位顺序与动作物理
+ 道具、环境和材质响应
+ 景别、机位、运镜、焦点、景深与曝光
+ 主光、阴影、色彩和材质
+ 表演、声音、结束帧和下一镜连续性
```

普通`RELATIVE_PHASE`镜头不必在第一句堆秒数，但仍应先写主体、起始状态和唯一变化。`ABSOLUTE_EVENT_ANCHOR`镜头应把最关键锚点尽早写入，例如“第1.5秒右拳接触桌面”；次要延迟、衰减和收住过程再在后文展开。

有效开头示例：

```text
保持@Actor_A面孔、深灰衬衫和固定中景不变；第1.5秒右拳重击木桌，拳桌接触清晰，茶杯同步小幅震起……
```

避免：

```text
《某某计划》第三场的情绪高潮镜头，4秒电影级写实视频，表现人物压抑已久的愤怒……
```

真实模型引用令牌例外：`@Actor_A`、上传图片引用、首帧引用或平台规定的触发词若确实承担身份/素材绑定，可以放在最前；仅供内部管理的角色名、资产ID或文件名不能伪装成模型绑定词。

前置权重优化不是缩短Prompt。时间、镜头、视觉、色彩、灯光、材质、表演、环境、声音、首尾帧和连续性设计仍必须完整保留。

## 默认图生视频细化规则

本节直接属于视频Prompt编译，不作为用户需要选择的新模块。只要输入是已有图片、Start CF、上一镜尾帧或用户上传首帧，就默认按图生视频规则编译。

图生视频不是重新描述首帧有多美，而是回答：首帧中的哪些元素先动、为什么动、按什么顺序动、各层速度如何不同、背景如何发展、摄影机如何响应，以及最后停在哪个可见状态。

### 1. 首帧保护优先

Prompt开头必须明确保持：人物面部、年龄、骨相、发型和发饰、人体比例、服装结构、主体位置、初始构图、场景结构、主色调和真实光源。只允许剧本要求的动作、材质、环境和摄影机变化。

禁止在图生视频Prompt中重新设计角色、服装、背景或镜头美术。静态身份和美术描述只保留用于锁定，不得挤占运动编排。

### 2. 每镜只有一个核心视觉事件

每条4—8秒图生视频Prompt先确定唯一核心视觉事件，例如：

- 人物从压抑静止到抬眼确认；
- 后方浪幕逐渐升起形成穹顶；
- 红色丝带横穿冷色空间；
- 门外光线逐渐切开黑暗；
- 雾墙从走廊尽头压近；
- 手指触碰道具并让其发生一次状态变化。

人物动作、衣料、头发、环境、灯光和运镜都应服务该主事件。允许1—3个从属微动，不得同时争夺视觉中心。

### 3. 人物动作必须按身体部位编排

禁止“人物缓慢起舞、人物转身、人物抬手”这类摘要。必须写清：

- 哪个部位先动；
- 起势的呼吸、视线、手指或重心准备；
- 动作方向、角度、距离和速度曲线；
- 哪些部位保持克制；
- 动作如何收住；
- 最终姿态和稳定停留。

例如：指尖先舒展，手腕随后外翻，手臂只延展少量，肩部最后轻微后带，身体重心不离开原支撑点。

### 4. 材质运动必须分层编舞

不能把头发、内层衣料、外层衣料、丝带、水、雾、火和尘统一写成“随风飘动”。分别说明：

- 动力来源；
- 开始时间和延迟；
- 方向和轨迹；
- 速度和幅度；
- 重量、阻力、惯性或流体连续性；
- 前景、中景、远景的速度差；
- 哪些允许运动模糊，哪些必须保持清晰。

靠近身体的内层通常更稳定，外层可以有更大弧线；近景元素可以更快并短暂虚化，远景大形通常更慢、更重。

### 5. 背景必须发生可见事件

背景不能只“有海浪、有雾、有雨”。必须写成时间过程：

```text
初始状态
→ 背景力量开始形成
→ 中段结构或运动扩大
→ 接近高潮时出现局部爆发或揭示
→ 停在落下、闭合、熄灭、揭开或压近之前/之后的准确状态
```

背景事件需要有大形、层次和尺度，并与主体动作同向、对抗或包围。背景可以成为第二视觉主体，但不能遮住关键面部、手部和叙事信息。

### 6. 时间轴必须有发展和高潮

短镜头不能平均地“漂”完整段。默认按实际时长划分为：

- 起始稳定与微小起势；
- 主动作或主环境事件形成；
- 画面关系发生明显变化；
- 最后1—2秒达到视觉峰值并收住。

峰值可以是动作停住、背景大形完成、光线穿透、遮挡形成、道具接触或观众终于看清信息。必须写清结尾画面，而不是只写“逐渐结束”。

### 7. 摄影机只响应主事件

一个短镜头采用一种主要运镜。图生视频优先小幅、可控的推进、横移、升降或环绕，并写清开始时间、结束时间、幅度和终点。环境已经宏大运动时，摄影机应更加克制；人物微动作很小时，摄影机可以承担少量情绪靠近。

### 8. 细节必须可执行而非无差别堆积

Prompt可以很长，但每句话必须控制画面、运动、物理、时间或稳定性。禁止重复同义形容词。若一条Prompt包含多个宏大环境事件、复杂舞蹈、快速运镜、面部变化和道具状态变化，应拆成多个Shot、首尾帧或分层生成，而不是继续增加文字。

视频Prompt不能只是动作摘要。它必须同时控制：

- 从什么画面开始；
- 最终必须抵达什么画面；
- 人物、道具和环境在时间轴中如何变化；
- 摄影机从哪里开始、何时运动、移动多远、在哪里停止；
- 光从哪里来、以什么色温和软硬度照亮什么区域；
- 焦点、景深、曝光、高光和暗部如何保持；
- 哪些内容允许运动，哪些内容必须绝对稳定；
- 当前镜头如何为下一镜提供准确的连续性尾态。

## 视频Prompt完整公式

```text
前置核心块：模型绑定/输入帧 + 主体与起始状态 + 唯一核心事件 + 最高优先级时间锚点或运动方向
+ 首帧必须保持的身份、美术、构图与光线
+ 视频类型与时长
+ 场景空间、背景功能和前中后景
+ 导演意图、观众位置与揭示顺序
+ 主体人物、目标、内外情绪与起始表演状态
+ 按身体部位编排的时间轴动作与情绪节拍
+ 内层/外层材质、前中远景环境的分层运动
+ 背景事件的形成、扩大、高潮与结束状态
+ 动作物理、接触和重心
+ 摄影机参数与运动时间轴
+ 焦点、景深和曝光
+ 逐镜灯光合同及情绪功能
+ 微表情、呼吸、身体语言与表演强度
+ 色彩与材质
+ 环境动态
+ 关键事件时间锚点与跨系统因果同步
+ 结束帧合同
+ 下一镜连续性
+ 声音
+ 稳定项
+ 负面约束
```

禁止将“电影感、真实光照、缓慢推进”当成完整描述。

## 完整导演设计继承合同

动态时间控制是视频Prompt的执行叠加层，不是新的简化版Prompt，也不得替代已经批准的导演完整设计。每条最终Prompt在加入秒点、时间窗和同步事件前，必须继续保留并执行：

- 景别、机位、焦段感、构图、前中后景、主体位置、留白、轴线和屏幕方向；
- 摄影机起点、运镜类型、方向、幅度、速度曲线、终点和叙事动机；
- 焦点、景深、曝光、白平衡、高光保护、暗部层次和运动模糊；
- 主光真实来源、世界位置、方向、软硬、色温、强度、光比、受光区和阴影区；
- 主色、辅助色、点缀色、饱和度、对比度、黑位、高光与光色连续性；
- 人物身份、服装、表演、微表情、呼吸、重心、手部、动作物理和情绪曲线；
- 场景结构、背景职责、环境事件、材质分层运动、声音、首尾帧和跨镜连续性。

时间轴只回答这些既有设计在什么时候开始、何时发生关键变化、哪些系统同步响应、运动如何衰减以及最终在哪里收住。

时间容量不足或执行冲突时，优先调整时间分配、减少并发、拆镜、使用首尾帧、抽尾帧续拍或分层生成；不得通过删除镜头、视觉、色彩、灯光、材质、表演、环境、声音或连续性信息解决。

## 一、先决定生成模式

### A. 单首帧图生视频

只有同时满足以下条件时才能使用：

1. 主要动作是呼吸、眨眼、轻微抬手、布料微动、雨水、水波等低幅度运动；
2. 道具不发生关键状态变化；
3. 人物姿势、手部位置和视线终点不需要被下一镜精确继承；
4. 摄影机固定或运动幅度极小；
5. 结尾允许从生成结果中选择稳定尾帧；
6. 下一镜为独立硬切，或可以使用抽取尾帧继续。

单首帧不等于不控制结尾。必须同时编写完整的`END_FRAME_CONTRACT`，生成后抽取满足合同的稳定尾帧。

### B. 首尾帧视频

出现以下任一情况时默认使用首尾帧：

- 下一镜需要继承人物准确姿势、视线、手部、道具位置或屏幕方向；
- 人物外貌、服装、情绪可见状态、面部状态发生变化；
- 道具被拿起、放下、打开、关闭、翻转、破坏、清理或移动到固定位置；
- 镜头运动改变最终构图、景别或焦点；
- 人物必须最终停在一个明确表演姿态；
- 动作终点承担叙事信息；
- 单首帧容易产生随机尾态或与下一镜不连续。

首尾帧不是额外角色资产，而是当前镜头的起终控制帧。

### C. 抽尾帧续拍

当一段动作需要分成两段连续视频时：

1. 第一段生成后抽取最后一个身份、手部、道具、背景和光线稳定的帧；
2. 将其作为下一段唯一首帧；
3. 下一段只继续尚未完成的动作；
4. 不重新设计人物、场景和构图。

### D. 两段生成后硬切

出现以下情况时，不强迫单次模型连续生成：

- 构图或机位变化较大；
- 同时存在人物状态变化、道具变化和特效变化；
- 遮挡前后需要切换稳定状态；
- 多人交互或精确手部持续失败；
- 首尾帧之间需要不自然的变形才能连接。

分别生成两段，再在动作节点、遮挡、声音或视线处硬切。

### E. 分层合成

镜面人物、倒影、雾气、火花、粒子、屏幕内容、精确文字和复杂状态变化，优先拆为底板、主体层、效果层和遮罩层。不要让一个视频模型同时承担全部图层。

## 二、结束帧合同

每一个镜头都必须设计结束帧，即使没有预先生成尾帧。

```yaml
end_frame_contract:
  exact_time:
  character_pose:
  face_and_gaze:
  hands_and_contact:
  prop_position_and_state:
  camera_position_and_framing:
  focus_target:
  foreground_midground_background:
  lighting_state:
  color_and_material_state:
  allowed_residual_motion:
  stable_hold_frames:
  next_shot_inheritance:
```

要求：

- 结束状态必须可见、可截图、可验证；
- 明确人物手脚、道具和视线位置；
- 明确镜头终点和焦点终点；
- 明确尾态的构图、灯光、色彩与材质状态；
- 结尾至少稳定停留12至24帧，除非明确要在运动中切断；
- 下一镜依赖该尾态时，必须预制尾帧或抽取稳定尾帧，不能让模型自由结束。

## 三、动态时间控制等级

不是所有镜头都强制逐秒工程化。先根据镜头风险选择一种控制模式。

### RELATIVE_PHASE

使用“前段稳定—中段发展—后段收住”的相对阶段。适用于呼吸、抬眼、轻微转头、缓慢走动、衣料与环境微动等低风险镜头。

仍需写清顺序、幅度、因果和尾态，但不机械设置多个绝对秒点，避免时间格式挤压表演与画面表达。

### ABSOLUTE_EVENT_ANCHOR

关键接触、冲击、揭示、转身、道具状态改变、焦点切换，或摄影机与人物需要同步响应时，使用绝对时间锚点。

锚点需要绑定同一因果事件中的人物、道具、环境、材质、摄影机、焦点、灯光、曝光和声音，防止提前、滞后、重复或无因运动。

```yaml
timing_control:
  mode: ABSOLUTE_EVENT_ANCHOR
  duration:
  pre_event_hold:
  event_anchors:
    - event_id:
      exact_time_or_window:
      preparation_start:
      trigger_action:
      exact_contact_or_change:
      actor_response:
      prop_response:
      environment_and_material_response:
      camera_response:
      focus_response:
      lighting_and_exposure_response:
      sound_sync_point:
      response_delay:
      amplitude_numeric:
      amplitude_visible_result:
      decay_or_rebound:
      settle_time:
      forbidden_desynchronization: []
  final_hold:
```

数值必须和可见结果同时出现。例如：

```text
茶杯震起约2厘米，杯底清楚离开桌面但不倾倒、不破裂；
摄影机下沉约10厘米，只改变一个手掌宽度的观察高度，不形成大幅俯冲。
```

模型无法精确执行数值时，可见结果仍能约束运动幅度。

### SPLIT_EXECUTION

当同一镜头需要多人精确交互、复杂手部接触、多个道具连锁反应、人物与摄影机同时大幅运动，或多个绝对锚点互相争夺执行能力时，不继续增加Prompt长度。

改用首尾帧、Bridge CF、两段生成、抽尾帧续拍、遮挡切换或分层合成。

## 四、时间轴动作编译

动作必须按镜头时长写成可执行时间段。示例：

```text
0.0—0.8秒：保持首帧姿势，只有呼吸和衣料微动；
0.8—3.4秒：右手以匀速移动8厘米，手腕保持水平；
3.4—4.2秒：道具落入支架，产生一次轻微承重震动；
4.2—5.0秒：双手松开并停住，保持尾帧不少于0.5秒。
```

### 起始状态

写清：

- 身体姿态；
- 头部朝向；
- 视线落点；
- 左右手位置；
- 道具接触点；
- 重心和脚部；
- 当前呼吸和停顿。

### 起势

写清动作前的微小准备：视线、呼吸、手指收紧、重心转移或肩部发力。普通动作不需要夸张蓄力。

### 过程

按时间顺序写1至3个动作节点，量化方向、距离、角度、速度和接触。

### 收住

写清最终姿态、手的位置、道具状态、视线、呼吸和稳定停留。不能在动作中间随机结束。

### 关键事件因果同步

绝对事件锚点不能只给人物动作标时间，还要把事件的因果响应绑定在同一时点或明确延迟：

```text
人物起势
→ 接触或状态变化
→ 道具受力或改变
→ 环境与材质响应
→ 摄影机、焦点、灯光或声音按导演设计响应
→ 惯性、余震或情绪残留逐渐衰减
→ 停在结束帧合同
```

必须明确哪些响应“同时发生”、哪些“延迟__秒”，以及哪些元素保持静止。

禁止摄影机提前震动、物体无接触自行运动、冲击后持续漂浮、动作自动重复或灯光无动机闪烁。

## 五、动作物理

- 重物明确重量感、双手分工、肩臂受力和重心；
- 手与道具写明接触点、握持位置和移动路径；
- 脚部真实接地，禁止滑行和漂浮；
- 布料、头发和饰物只产生由动作或环境引起的合理运动；
- 动作速度使用“匀速、缓入缓出、先慢后停”等具体节奏；
- 动作幅度尽量量化为厘米、角度或画面比例；
- 每个数值同时说明观众可见的结果，不能只给模型一个抽象数字。

## 六、人物表演合同

人物镜头必须建立：

```yaml
performance_contract:
  scene_objective:
  immediate_intention:
  inner_emotion:
  outer_strategy:
  emotional_contradiction:
  intensity_start:
  intensity_end:
  gaze_and_eyelids:
  eyebrows_and_forehead:
  mouth_jaw_and_swallow:
  breathing:
  posture_and_weight:
  hands_and_fingers:
  emotion_beats: []
  forbidden_overacting: []
  end_performance_state:
```

要求：

- 情绪必须转化成可见线索，不得只写标签；
- 4—6秒镜头默认只有一个主要情绪转折、1—3个微动作和一次呼吸变化；
- 眼、嘴、肩、手和头部不同时进行高幅度动作；
- 镜头距离、焦点和灯光必须让关键表演可读；
- 结束表演状态必须进入End CF和下一镜继承。

## 七、摄影机合同

每镜必须写明：

```yaml
camera_contract:
  lens_or_equivalent:
  camera_height:
  camera_distance:
  shot_size:
  angle:
  axis_and_screen_direction:
  start_position:
  movement_type:
  movement_start_time:
  movement_end_time:
  event_sync_relation:
  direction:
  speed_curve:
  amplitude:
  amplitude_visible_result:
  endpoint:
  movement_motivation:
  stabilization:
```

要求：

- 固定镜头也要写“摄影机锁定，无平移、摇镜、旋转和数字变焦”；
- 推进、横移和升降尽量量化，例如推进画面宽度5%、横移40厘米、环绕12度；
- 写明运动在第几秒开始和结束；
- 关键事件镜头写清摄影机是提前蓄势、同时响应、延迟跟随还是始终静止；
- 一个短镜头只使用一种主要运镜；
- 运镜必须服务揭示、压迫、空间确认、动作跟随或情绪距离；
- 没有叙事理由时使用固定镜头。

## 八、焦点、景深和曝光合同

每镜必须写明：

```yaml
optical_contract:
  depth_of_field:
  focus_at_start:
  focus_transition:
  focus_event_sync:
  focus_at_end:
  lens_breathing:
  exposure:
  white_balance:
  highlight_protection:
  shadow_detail:
  motion_blur:
```

要求：

- 焦点必须落在具体对象，例如近侧眼睛、刀尖、镜面清洁区、纸张栏目；
- 发生焦点转移时写清起点、终点、开始和结束时间；
- 关键揭示中写清焦点与事件锚点的同步或延迟关系；
- 不用“浅景深”掩盖身份和手部错误；
- 曝光写明正常、略欠曝或高光保护；
- 高光不能掩盖镜面、皮肤和关键道具；
- 暗部必须保留空间和材质层次；
- 镜头呼吸只能轻微自然。

## 九、逐镜灯光合同

每条最终视频Prompt都必须包含当前镜头具体灯光，不能只引用全局视觉圣经。

```yaml
lighting_contract:
  key_source:
  key_direction:
  key_height:
  key_softness:
  key_color_temperature:
  key_intensity:
  fill_source:
  fill_intensity:
  practical_lights:
  rim_or_separation_light:
  background_light:
  lighting_ratio:
  illuminated_areas:
  shadow_areas:
  shadow_direction:
  highlight_control:
  atmospheric_light:
  motivated_change_time:
  motivated_change_trigger:
  continuity_with_previous_and_next:
  forbidden_light_changes:
```

最低要求：

1. 写清主光是什么真实光源；
2. 写清来自画面哪一侧、人物前后关系和大致高度；
3. 写清冷暖或具体开尔文数值；
4. 写清光线软硬和强弱；
5. 写清照亮人物或道具的哪些区域；
6. 写清哪一侧保持阴影以及阴影不能死黑；
7. 写清辅光、实景灯和背景光；
8. 写清大致光比，例如1:2、1:4；
9. 写清高光和暗部策略；
10. 写清整段视频中光源位置、方向、色温和曝光不得闪烁或漂移；
11. 光线确实需要变化时，写明发生时间、触发原因、变化幅度和最终状态。

示例：

```text
主光是画面左侧木格窗外的5600K阴天漫射光，从人物左前上方约35度进入，
形成柔和但方向明确的窗口侧光，照亮左侧额头、手背、铜镜左缘和工作台纹理；
人物右侧脸和作坊后部保持约1:4的自然阴影，暗部仍能辨认皮肤、旧木和工具轮廓。
工作台油灯为约2800K极弱实景光，只在刀柄和铜粉上形成小面积暖色高光，不照亮整张脸。
整个镜头中窗光方向、鼻影方向、镜面高光和油灯亮度固定，不闪烁、不改变色温。
```

## 十、画面空间与材质

最终Prompt必须形成明确画面，而不是只列动作：

- 前景是什么，是否遮挡；
- 中景主体位于画面哪个区域；
- 背景地标和空间纵深；
- 构图重心、留白和视线方向；
- 皮肤、布料、木材、金属、纸张、水面等关键材质；
- 空气中雨雾、尘埃、烟和体积光的范围与强度；
- 哪些固定元素完全不动。

## 十一、光线和颜色连续性

必须继承同一场景的：

- 主光来源和屏幕方向；
- 主光色温；
- 阴影方向；
- 白平衡；
- 光比和曝光倾向；
- 镜面及道具高光位置；
- 主色、辅助色和点缀色；
- 饱和度与对比度；
- 黑位和高光策略；
- 关键人物、服装、道具与背景的色彩关系。

时间变化必须在剧本中有依据，并写清开始时间、变化幅度和结束状态。禁止模型自行变亮、变暗、闪烁、偏黄、偏蓝、改变主色关系或增加无来源轮廓光。

## 十二、声音字段

按工具能力写环境音、呼吸、衣料、道具接触、台词、音乐和沉默。关键动作需要声音同步时，写明发生秒点以及与接触、摄影机和环境响应的同步关系。

不支持原生声音时明确转入后期，不假装视频模型一定生成。

## 十三、最终Prompt写作标准

最终可复制Prompt必须是完整、具体、具有画面顺序的自然语言，不得只输出字段清单。

每镜至少写清：

- 首句前置核心块：真实模型绑定或输入帧、主体起始状态、唯一核心事件和最高优先级时间锚点/运动方向；
- 输入模式与首尾帧；
- 画面空间和构图；
- 导演意图、观众位置和揭示顺序；
- 起始姿态与表演基线；
- 人物目标、内外矛盾和分秒情绪节拍；
- 可见微表情、呼吸、身体语言和手部变化；
- 时间控制模式；
- 分秒动作过程或相对阶段；
- 关键事件锚点、因果同步、延迟、幅度与衰减；
- 动作物理；
- 摄影机参数、事件同步关系和运动终点；
- 焦点、景深和曝光；
- 逐镜灯光及有动机变化时间；
- 色彩、材质和环境动态；
- 精确尾帧；
- 下一镜继承；
- 声音和负面约束。

不得为了“方便复制”压缩成几句通用话，也不得为了突出时间轴或前置权重而删除完整画面、镜头、灯光、色彩和材质设计。

## 十四、输出格式

每镜使用`templates/video-shot-prompt-block.md`。完整正向Prompt、负面Prompt、输出规则、尾帧控制、衔接和失败修复必须位于同一镜头块。

Prompt块可以先展示Shot ID、剧情作用和导演说明，但用户复制到模型的内容必须仅取`【视频正向Prompt】`字段；该字段自身不得以项目名、剧名、Shot标题、版本号或解释性语句开头。

## 视频Prompt硬失败

以下任一情况直接判定FAIL：

- 只写动作和运镜，没有画面、光线、焦点和尾帧；
- 只有情绪标签，没有人物目标、内外矛盾和可见表演；
- 五秒内安排多个主要情绪转折或无事件强度跳级；
- 微表情在当前景别、焦点、遮挡或灯光下不可读；
- 无台词人物嘴部持续说话或出现随机夸张表情；
- 使用单首帧，但下一镜依赖精确尾态且未提供尾帧或抽尾帧方案；
- 每镜没有结束帧合同；
- 只写“真实光照、电影感、冷色调”；
- 未写主光来源、方向、照亮区域和暗部；
- 光源方向和色温在同一镜头或相邻镜头中漂移；
- 未写景深和焦点；
- 运镜没有开始时间、结束时间、方向、幅度和终点；
- 一个五秒镜头包含过多动作与运镜；
- 没有可见的结尾状态或稳定停留；
- 视频Prompt重新设计人物、服装或场景；
- 首尾帧构图差异过大却强迫平滑变换；
- 声音要求与工具能力不匹配且未转入后期；
- 图生视频Prompt没有明确首帧保护，导致人物、服装、构图或场景被重新设计；
- 只重复描述静态画面，没有说明接下来按时间发生什么；
- 只写“人物起舞、衣袂飘动、海浪翻涌、镜头推进”等摘要，没有身体部位顺序、材质速度差、背景过程和终点；
- 一个短镜头没有唯一核心视觉事件，人物、材质、背景、灯光和摄影机同时无差别抢动；
- 背景只有环境名词，没有初始状态、形成过程、视觉高潮和结束状态；
- 头发、内外层衣料、丝带、水、雾等全部以相同方向、速度和幅度运动；
- 时间轴从头到尾均匀漂动，没有最后1—2秒的视觉峰值和收住；
- 用增加形容词代替运动因果，或因Prompt过载而应拆镜却仍强迫单次生成；
- 为加入绝对秒点而删除原有景别、构图、镜头、焦点、灯光、色彩、材质、表演、环境、声音、首尾帧或连续性设计；
- 关键接触或冲击没有统一事件锚点，导致人物、道具、环境、摄影机、焦点、灯光或声音提前、滞后、重复或无因响应；
- 只给厘米、角度和秒数，不说明观众在画面中应看到的幅度与结果；
- 普通低风险镜头被机械拆成过多绝对秒点，时间格式挤压了表演和画面表达；
- 复杂事件已经超过单次模型稳定能力，却不拆段、不使用首尾帧或分层生成；
- 把作品名、剧名、章节名、场次名、Shot ID、CF ID、文件名、版本号、导演解释或主题说明放在模型执行Prompt开头；
- 前置核心块只有“电影感、震撼、治愈、史诗”等抽象风格词，没有输入绑定、主体、起始状态、核心事件或时间锚点；
- 为追求前置权重而删除后续运镜、焦点、灯光、色彩、材质、表演、环境、声音、尾帧和连续性设计。
