# Image Prompt Compiler

## 目标

把剧本拆解、视觉圣经、资产台账和镜头静态状态编译为可直接复制的AI生图Prompt。图片Prompt负责锁定一个静态瞬间，不负责描述完整时间过程。

## 图片Prompt基础公式

```text
固定视觉基准
+ 参考资产及其职责
+ 主体身份
+ 场景与时代
+ 一个静态瞬间
+ 服装和道具状态
+ 景别和拍摄角度
+ 构图与空间层次
+ 真实光源、方向和色调
+ 材质、皮肤和影像质感
+ 画幅与输出结构
+ 必须保持一致
+ 针对性负面约束
```

简化理解：谁、在哪里、此刻停在什么姿态、摄影机从哪里看、画面如何组织、光从哪里来、什么必须保持、什么绝对不能发生。

## 编译顺序

### 1. 先确认图片类型

不同任务不能共用一个万能Prompt：

- 面部身份板；
- 生产三视图；
- 发型结构板；
- 服装层次或状态板；
- 手部与道具交互板；
- 姿态或动作故事板；
- 场景主布局；
- 无人物空镜；
- 多机位场景板；
- 道具结构或状态板；
- 分镜首帧；
- 分镜尾帧；
- 图生图修改；
- 局部修复；
- 降噪和4K增强。

### 2. 写清参考图职责

不能只写“参考上传图片”。每张参考图必须标注职责：

- 身份参考：锁定面孔、年龄、骨相和身体比例；
- 服装参考：锁定层次、颜色、污渍和穿戴结构；
- 场景参考：锁定建筑、布局、地标和主光；
- 道具参考：锁定尺寸、结构、材料和独特标记；
- 姿态参考：只借用动作与身体方向，不改变人物身份；
- 色调参考：只借用色温、饱和度、对比度和光影关系。

同一参考图承担多个职责时逐项说明。没有参考图时明确写“首次生成，无参考”，并降低一次生成多视图的预期。

### 3. 主体身份

角色至少写清：

- 年龄段、地域或族群特征；
- 脸型、骨相、眉眼、鼻、嘴、皮肤和发际线；
- 身高、体型、姿态和劳动或生活痕迹；
- 稳定身份标记；
- 表情温度；
- 禁止美化、年轻化或类型化的方向。

场景至少写清：时代、地点、功能、布局、入口、固定地标、主要材质、天气、主光来源和禁止时代错误。

道具至少写清：尺寸、人体比例、正侧背结构、材料、工艺、磨损、独特标记、持有方式、默认位置和状态版本。

### 4. 一个静态瞬间

图片Prompt只能描述可以在单帧中确认的状态，例如：

- 手刚刚触碰门把；
- 刀尖停在铜锈上方；
- 人物回头前的侧脸；
- 雨水正从屋檐滴落；
- 道具已经断裂并落地。

不要把“起身、跑到门口、推门、回头、说话”全部写入一张图片Prompt。连续过程拆成首帧、尾帧或动作故事板。

### 5. 景别、角度和构图

写清：

- 画幅和横竖方向；
- 景别：大全景、全景、中景、中近景、近景、特写或极特写；
- 角度：平视、低机位、俯拍、正侧、四分之三、肩后或主观；
- 摄影机相对主体的位置；
- 前景、中景、背景；
- 主体占比、留白和视线空间；
- 地平线、轴线和屏幕方向；
- 是否需要为后续动作预留空间。

相机或镜头名称只能作为辅助，不得代替构图、光线和空间说明。

### 6. 光线与色调

调用`visual-style-color-light.md`，至少继承：

- 主色、辅助色和点缀色；
- 色温、饱和度和对比度；
- 白平衡、黑位和高光策略；
- 真实主光来源、方向、颜色和照亮对象；
- 暗部保留程度；
- 人物肤色、服装和背景的关系；
- 禁止颜色和无来源光。

### 7. 材质和真实度

使用可观察材质，而不是只写“超写实”：

- 皮肤毛孔、轻微不对称、细纹和区域色差；
- 布料纤维、缝线、折痕、磨损和湿度；
- 木材刀痕、油污和边缘磨损；
- 金属氧化、划痕、包浆和反射粗糙度；
- 纸张纤维、折痕、水渍和墨迹；
- 建筑灰尘、潮气、裂纹和使用痕迹。

所有磨损必须有来源，不能随机做旧。

## 正向Prompt结构

每个最终Prompt应自然写成完整段落，并覆盖：

1. 任务类型与用途；
2. 参考图职责；
3. 主体身份和固定标记；
4. 场景和当前状态；
5. 一个准确静态瞬间；
6. 景别、角度和构图；
7. 光线和色调；
8. 材质和真实度；
9. 输出结构与比例；
10. 必须保持一致。

全局视觉基准必须直接继承到每个可复制Prompt，不能让用户另外拼接“全局前缀”。

## 负面Prompt结构

负面Prompt按实际风险编写，不机械粘贴万能词。按需覆盖：

- 身份错误：换脸、年龄漂移、骨相变化、随机美化；
- 人体错误：多指、少指、融合肢体、关节反向、滑行；
- 服装错误：结构变化、颜色跳变、污渍和破损漂移；
- 道具错误：尺寸变化、结构变化、独特标记消失、穿模；
- 场景错误：建筑重建、门窗换位、地标消失、时代错误；
- 光色错误：无来源光、肤色跳变、滤镜变化、暗部死黑；
- 输出错误：裁头裁脚、视图数量错误、多格不同人物、乱码文字、水印；
- 类型错误：动漫、游戏CG、海报、商业写真或项目明确禁止风格。

## 输出规则

每个Prompt块必须写明：

- 比例和方向；
- 单图或多格；
- 视图数量与排布；
- 背景；
- 是否允许文字；
- 不可裁切区域；
- 身份、结构、构图和氛围的优先级；
- 长边或清晰度要求；
- 文件命名建议。

## 多视图稳定策略

### 理想方案

模型支持多参考和高一致性时，一次生成标准板。

### 稳定方案

1. 先生成单张正面身份图；
2. 以批准正面图生成左右四分之三和侧面；
3. 以身份图生成全身正面；
4. 再生成严格侧面和背面；
5. 最后人工排版为身份板或三视图。

不得假设所有图片模型都能一次稳定生成六视图。

## 图生图修改

图生图Prompt必须写：

```text
保持人物身份、构图、场景、服装、道具、光线和未指定区域完全不变，
只修改：……
修改后应达到：……
禁止连带改变：……
```

## 局部修改与修复

局部修改必须先圈定区域，再写：

- 保留什么；
- 只修什么；
- 修复后的结构和材质；
- 边缘如何与原图融合；
- 禁止改变的邻近区域。

优先局部修复手指、嘴形、衣服标记、道具缺口、文字区和背景小穿帮，不为小错误重生成整张图。

## 降噪和4K增强

增强Prompt只允许提升：

- 分辨率；
- 纹理连续性；
- 夜景噪点；
- 压缩伪影；
- 边缘细节；
- 暗部可读性。

不得重绘脸、改变表情、重构衣服、增加锐化光晕或让皮肤塑料化。

## 硬失败

- 未写参考图职责；
- 用一张图片承担多个连续动作；
- 正向Prompt、负面Prompt和输出规则分散，无法一次复制；
- 只写“电影感、高清、真实”而没有具体光线和材质；
- 每个镜头重新发明角色、场景和道具；
- 多视图明显不是同一人物却仍标记可生产；
- 让用户自己拼接全局风格前缀；
- 小范围错误不提供图生图或局部修复方案。
