# Image Prompt Compiler V4.7

编译前读取：

- `prompt-engineering/render-medium-generation-route-contract.md`；
- 当前项目`RENDER_MEDIUM_LOCK`；
- 当前Shot生成路线；
- 当前视觉策略、资产台账和连续性台账；
- 需要时读取`controllers/frame-clarity-density-controller.md`、`controllers/performance-director.md`与灯光模块。

## 一、目标

把资产需求、视觉圣经、镜头静态状态和当前渲染媒介编译为可直接复制的AI生图Prompt。

图片Prompt只负责锁定一个静态瞬间或技术结构，不负责描述完整时间过程。

图片并非所有视频镜头的强制前置物。只有以下情况才生成：

- 作为必要角色、场景、道具、状态或Lookdev资产；
- 当前Shot路线为IMAGE_TO_VIDEO、FIRST_LAST_FRAME或需要实际控制帧；
- REFERENCE_T2V需要真实可复用参考；
- 海报、封面、概念图、修复或用户明确要求图片；
- PURE_T2V镜头确有身份、风格或结构参考需求。

不得为PURE_T2V镜头机械生成伪首帧。

## 二、媒介继承合同

所有图片Prompt必须先读取：

```yaml
image_medium_contract:
  render_medium_reference:
  image_type:
  character_rendering:
  environment_rendering:
  surface_and_material_language:
  lighting_language:
  camera_or_composition_translation:
  target_finish:
  forbidden_medium_drift: []
```

关键原则：

- 电影感不自动等于真人摄影；
- 真实光源表示世界内部方向、位置、遮挡与阴影成立；
- 真实材质表示材料类别、表面、受力和使用规律可辨认；
- 真人毛孔、摄影颗粒、照片透视只在当前媒介需要时使用；
- 风格化3D动画应明确角色建模、面部比例、眼睛、表面着色、发束、服装轮廓、环境形体和动画电影灯光；
- 二维、2.5D、绘画、水墨、定格和游戏电影CG按当前媒介翻译；
- 角色、服装与背景必须属于同一媒介语言；
- 不得把动漫、真人、二维、三维或游戏CG写成通用负面项。

## 三、模型执行Prompt前置语义规则

Shot ID、Scene ID、CF ID、Asset ID、作品名、剧名、章节名、场次标题、文件名、版本名、导演解释和用途说明属于管理信息，必须保留在正向Prompt之外。

实际编译时仍将首句或前20—30个实义词作为高优先级语义区，但不把它写成所有模型一致的硬定律。

### 资产Prompt前置核心块

```text
当前媒介中的资产类型与输出任务
+ 主体身份、场景或道具本体
+ 必须覆盖的角度、结构、状态或交互
+ 最高优先级一致性锚点
```

### 剧情首帧、尾帧和关键帧前置核心块

```text
当前媒介中的主体身份或核心对象
+ 准确静态状态与动作阶段
+ 景别、机位或构图核心关系
+ 场景锚点与最高优先级连续性约束
```

随后完整展开：

```text
参考图职责
+ 前中后景、背景功能与大形
+ 视觉张力、冻结运动痕迹与表演
+ 摄影机或媒介等效关系、焦点、层级与曝光
+ 主光或主明暗、阴影、色彩、材质和着色
+ 画幅、输出结构和禁止漂移
```

这不是删减Prompt。前置核心块只负责确定模型先理解什么，后续导演和视觉细节必须完整保留。

## 四、先确认图片类型与路线职责

不同任务不能共用一个万能Prompt：

- 面部身份板；
- 角色Lookdev母图；
- 生产三视图；
- 发型结构板；
- 服装层次或状态板；
- 手部与道具交互板；
- 姿态或动作故事板；
- 场景主布局；
- 无人物空镜；
- 多机位场景板；
- 道具结构或状态板；
- 风格、材质或灯光Lookdev；
- 分镜首帧；
- 分镜尾帧；
- 图生图修改；
- 局部修复；
- 降噪和增强。

同时写清它服务哪条生成路线：

```yaml
route_role:
  shot_ids: []
  route: REFERENCE_T2V | IMAGE_TO_VIDEO | FIRST_LAST_FRAME | TAIL_FRAME_CONTINUATION | POST_LAYER | STANDALONE_IMAGE
  responsibility:
  why_text_only_is_insufficient:
```

没有实际Shot、路线或独立图片用途的资产不得生成。

## 五、默认视觉强化规则

用户要求剧情关键帧、首尾帧、氛围概念图、视觉海报或叙事场景时，默认执行视觉强化。技术型资产板以身份、结构、比例、中性可读性和可复用性优先，不得为了震撼破坏生产清晰度。

### 视觉强化不是堆形容词

“唯美、空灵、史诗、神性、宿命、电影感、高级感、动漫感、3D感、压迫感”都必须落地为可见原因：

- 构图关系；
- 空间压迫或留白；
- 主体姿态、重心和关键剪影；
- 前景、中景、背景层次；
- 光源方向、边缘与明暗节奏；
- 主色、辅助色与强调色；
- 材质、着色、线条、笔触、雾、水、尘、布料或环境结构；
- 大形、动线和冻结运动痕迹；
- 角色与环境共享的设计语言。

### 主体必须有视觉状态

不能只写身份和服装，还要写主体以什么状态出现，例如被托举、被包围、即将坠落、强行站立、压住恐惧、处于仪式中心、被环境吞没或正完成不可逆选择。状态必须来自剧本时点。

### 先确定视觉张力来源

叙事型图片内部先确定2—5个主要张力来源，例如：

- 人物姿态失衡与环境力量对抗；
- 巨大背景结构压迫小人物；
- 冷色主体中的单一强调色；
- 前景遮挡与远景大形形成纵深；
- 柔软材质与粗粝环境对撞；
- 静止表情与剧烈运动痕迹反差；
- 风格化角色轮廓与环境曲线、折面或纹理互相呼应。

## 六、背景是第二视觉主体

剧情关键帧、氛围图、视觉概念图和世界Lookdev中，背景不能只写地点名或泛化雾气。必须明确：

1. 背景功能：压迫、包围、托举、吞没、隔离、揭示、延伸、喜剧反应或中性支撑；
2. 背景大形；
3. 近中远空间层次；
4. 线条、结构、雾、水、光或纹理的方向；
5. 局部高潮；
6. 与主体姿态、服装、动作和色彩的呼应；
7. 当前媒介中的环境建模、线条、笔触、材料和着色方式。

背景允许柔化，但关键大形、层次和情绪功能必须可读。角色与环境不能像两张不同风格素材拼贴。

## 七、参考图职责

每张参考图标明：

- 身份参考：锁定面孔、年龄、骨相、身体比例或角色设计；
- 服装参考：锁定层次、颜色、材质与穿戴结构；
- 场景参考：锁定布局、地标、空间规则和主光；
- 道具参考：锁定尺寸、结构、材料和标记；
- 姿态参考：只借用动作与身体方向；
- 色调参考：只借用色彩和明暗；
- 媒介或Lookdev参考：锁定建模、线条、着色、材质、灯光和完成度。

同一参考图承担多个职责时逐项说明。没有参考图时，“首次生成，无参考”属于管理说明，不占据正向Prompt开头。

## 八、角色年龄与身份

角色年龄不得使用固定默认值。用户或剧本明确时直接继承；未明确时，根据身份与生活阶段、叙事功能、题材、情感主题、关系结构、受众、视觉审美、身体状态、社会经验和用户偏好判断。

年轻感、成熟感和老年感都可以成为项目审美资源。禁止的是无依据改变已锁定年龄、跨镜漂移、生活阶段错配和身份重设计。

角色至少写清：

- 当前项目确定的年龄阶段、地域或族群特征；
- 当前媒介中的面部比例、骨相转译、眉眼、鼻、嘴、皮肤或表面着色、发际线；
- 身高、体型、姿态和生活痕迹；
- 发型的结构与当前媒介表现；
- 稳定身份标记；
- 表情温度；
- 禁止的身份、年龄和媒介漂移。

风格化3D动画不得只写“漂亮动漫女性”。必须明确设计化程度、角色建模、眼睛尺度、面部平面、表面着色器、发束和服装轮廓；也不得回退为真人脸加CG背景。

## 九、一个静态瞬间

图片Prompt只能描述可在单帧确认的状态，例如：

- 手刚刚触碰门把；
- 刀尖停在铜锈上方；
- 人物回头前的侧脸；
- 第一针已经被挑开，线形成短小松弛弧线；
- 道具已经断裂并落地。

不要把起身、跑到门口、推门、回头和说话全部写进一张图片。连续过程拆成首帧、尾帧、桥接帧或视频Prompt。

## 十、景别、角度和构图

写清：

- 画幅和方向；
- 景别；
- 平视、低机位、俯拍、正侧、四分之三、肩后或主观角度；
- 摄影机或媒介等效观察位置；
- 前景、中景、背景；
- 主体占比、留白和视线空间；
- 地平线、轴线和屏幕方向；
- 后续动作预留空间；
- 主大形、视觉动线和关键剪影。

相机或镜头名称只能辅助，不得替代构图、光线和空间说明。二维、绘画和定格项目按分层、视差、线条与画面压缩关系翻译。

## 十一、静态表演与情绪时点

图片Prompt捕捉一个可见表演时点：

- 人物当下想隐藏、确认、拒绝或完成什么；
- 视线、眼睑、眉、嘴或下颌中的少量关键线索；
- 呼吸通过胸腔、肩部或嘴部静态结果表达；
- 姿态、重心、左右手和手指张力；
- 情绪强度和下一动作准备；
- 风格化动画中的关键姿势、剪影和表情设计；
- 禁止夸张表演。

微表情必须与景别、焦点、灯光和媒介可读性一致。

## 十二、光线、色调与材质

调用`visual-style-color-light.md`，至少继承：

- 当前渲染媒介；
- 主色、辅助色和点缀色；
- 色温或颜色关系、饱和度和对比度；
- 白平衡或媒介等效基准、黑位和高光；
- 主光或主明暗来源、方向和照亮对象；
- 暗部保留程度；
- 人物、服装和背景关系；
- 材质与着色方式；
- 禁止颜色、无来源光和媒介漂移。

### 真人实拍或照片写实CG

按需使用自然皮肤区域差异、细小纹理、真实服装工艺、现实材料和摄影光学。

### 风格化3D动画

按需使用动画电影级角色建模、受控次表面散射、设计化皮肤或表面着色、发束分组、服装大形、环境形体、绘画化但有动机的灯光、PBR与艺术化取舍。禁止真人写真、真人CG替身、蜡像、塑料皮肤和普通游戏截图感。

### 二维、2.5D、绘画与水墨

使用线条、色块、笔触、边缘、纸面、墨色、晕染、分层和图形阴影，不机械加入真人毛孔、PBR皮肤和照片噪点。

### 定格

使用实体材料、模型接缝、纤维、纸、黏土、木、金属和逐帧人工痕迹。

所有磨损和纹理必须有来源，不能随机做旧。

## 十三、正向Prompt结构

每个最终Prompt写成完整自然语言，并覆盖：

1. 当前媒介中的前置核心块；
2. 路线职责和参考图职责；
3. 主体身份、设计、固定标记和当前视觉状态；
4. 场景、背景功能和当前状态；
5. 2—5个视觉张力来源与一个准确静态瞬间；
6. 冻结运动痕迹、人物表演、视线、姿态和情绪强度；
7. 景别、角度、大形、视觉动线和前中后景；
8. 背景的大形、方向、空间层次、局部高潮及与主体呼应；
9. 光线、明暗节奏和色彩策略；
10. 当前媒介中的表面、材质和着色；
11. 输出结构与比例；
12. 必须保持一致与禁止媒介漂移。

全局视觉基准必须继承到每个可复制Prompt，不能让用户另拼公共前缀。详细不等于同义反复，每句话都应控制可见结果。

## 十四、负面Prompt结构

按实际风险编写：

- 身份错误：换脸、年龄漂移、骨相或角色设计变化；
- 媒介错误：只列当前项目明确禁止的真人化、二维化、三维化、游戏截图化等；
- 人体错误：多指、少指、融合肢体、关节反向；
- 服装错误：结构、颜色、材质与状态跳变；
- 道具错误：尺寸、结构和标记变化；
- 场景错误：布局重建、地标消失和时代错误；
- 光色错误：无来源光、角色表面污染、暗部死黑；
- 输出错误：裁切、多格不同人物、乱码和水印。

不得机械粘贴万能负面词，不得把任何媒介写成全局错误。

## 十五、输出规则

每个Prompt块写明：

- 比例和方向；
- 单图或多格；
- 视图数量与排布；
- 背景；
- 是否允许文字；
- 不可裁切区域；
- 身份、结构、媒介、构图和氛围优先级；
- 长边或清晰度要求；
- 文件命名建议；
- 服务的Shot和生成路线。

## 十六、多视图稳定策略

### 理想方案

模型支持多参考和高一致性时，一次生成标准板。

### 稳定方案

1. 先生成单张身份或Lookdev主参考；
2. 以批准主参考生成左右四分之三和侧面；
3. 以身份与服装参考生成全身正面；
4. 再生成严格侧面和背面；
5. 最后人工排版。

技术板必须继承当前媒介。例如风格化3D项目生成角色模型结构板，不得退回真人证件照。

## 十七、图生图修改与局部修复

图生图Prompt以保留合同开始：

```text
保持人物身份、渲染媒介、角色设计、构图、场景、服装、道具、光线、色彩、材质和未指定区域完全不变，
只修改：……
修改后应达到：……
禁止连带改变：……
```

局部修改先圈定区域，再写保留、修改、融合边缘和禁止改变的邻近区域。

增强只提升分辨率、纹理连续性、噪点、压缩伪影、边缘和暗部可读性，不得重绘脸、改变表情、重构衣服、改变媒介或让表面塑料化。

## 十八、硬失败

- 未读取`RENDER_MEDIUM_LOCK`；
- 在路线判断前机械生成控制帧；
- PURE_T2V无实际需要却生成伪首帧；
- 用一张图片承担多个连续动作；
- 正向Prompt被剧名、ID和说明占据开头；
- 只写电影感、动漫感、3D感、高清和真实，没有具体可见原因；
- 风格化3D角色仍按真人毛孔、真人写真和现实演员生成；
- 角色与背景不属于同一媒介语言；
- 把动漫、真人、二维、三维或游戏CG写成通用负面项；
- 每个镜头重新发明角色、场景和道具；
- 多视图明显不是同一人物却标记可生产；
- 让用户自行拼接全局前缀；
- 叙事型图片只有主体，背景泛化或空洞；
- 抽象审美词没有构图、光线、色彩、空间、材质或着色原因；
- 没有大形、视觉动线和张力来源；
- 背景没有功能、层次、方向和局部事件；
- 为视觉强化破坏身份板和结构板的可读性；
- 为前置权重删减后续摄影、视觉、色彩、灯光、材质、表演、背景和连续性控制；
- 为了汇总资产而缩短每一项完整Prompt。
