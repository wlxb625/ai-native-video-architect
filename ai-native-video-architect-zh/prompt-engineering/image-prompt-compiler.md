# Image Prompt Compiler V4.6

## 目标

把剧本拆解、视觉圣经、资产台账和镜头静态状态编译为可直接复制的AI生图Prompt。图片Prompt负责锁定一个静态瞬间，不负责描述完整时间过程。

## 模型执行Prompt前置语义规则

Prompt块中的Shot ID、Scene ID、CF ID、作品名、剧名、章节名、场次标题、文件名、版本名、导演解释和用途说明属于管理信息，必须保留在正向Prompt之外。除非某个名称必须作为画面中真实可见文字生成，否则不得让这些词占据模型执行Prompt开头。

不同图片模型对长Prompt的注意力分配不同，因此不把“前20—30个词权重最高”写成所有模型都一致的硬定律；实际编译时仍将**首句或前20—30个实义词**作为高优先级语义区。此区域只放本帧最重要、最可见、最不可漂移的信息。

剧情首帧、尾帧和关键帧的前置核心块按以下顺序组织：

```text
主体身份或核心对象
+ 当前准确静态状态与动作阶段
+ 景别、机位或构图核心关系
+ 场景锚点与最高优先级连续性约束
```

随后继续完整展开：

```text
参考图职责
+ 前中后景、背景功能与大形
+ 视觉张力、冻结运动痕迹与表演
+ 摄影机、焦点、景深与曝光
+ 主光、阴影、色彩与材质
+ 画幅、输出结构和禁止漂移
```

前置权重优化不能成为删减后续镜头、视觉、色彩、灯光、材质、表演、背景和连续性控制的理由。

有效开头示例：

```text
@Actor_A右拳刚接触木桌的中近景，身体重心前压，右拳与桌面接触清晰，茶杯仍贴桌等待受力反应……
```

避免：

```text
《某某计划》第三场SH-03的高潮首帧，用于表现压抑情绪和命运转折……
```

真实模型引用令牌例外：`@Actor_A`、已上传图片引用或平台规定的角色触发词若确实承担身份绑定，可以置于主体前方；内部角色编号和资产编号若模型无法识别，则只能留在Prompt外。

## 默认视觉强化规则

本节直接属于图片Prompt编译，不是需要用户另行选择的新模块。用户要求分镜首尾帧、剧情关键帧、氛围概念图、视觉海报或叙事场景时，默认执行视觉强化；用户不需要说“强化”“电影版”或选择额外模式。

技术型资产板例外：人物身份主参考、标准三视图、道具结构板、服装层次板和场景布局板以身份、结构、比例、光线中性和可复用性优先，不得为了震撼而破坏生产清晰度。

### 视觉强化不是堆形容词

禁止只写“唯美、空灵、史诗、神性、宿命、电影感、高级感、压迫感”。每个抽象审美词都必须至少落地为一种可见原因：

- 构图关系；
- 空间压迫或留白；
- 主体姿态与重心；
- 前景、中景、背景的层次；
- 光源方向和明暗节奏；
- 主色、辅助色与唯一强调色；
- 材质、雾、水、尘、火、布料或环境结构；
- 画面中的大形、动线和冻结运动痕迹。

### 主体必须有“视觉状态”

不能只写人物身份和服装，还要写主体以什么状态出现在画面中，例如被托举、被包围、即将坠落、强行站立、压住恐惧、处于仪式中心、被环境吞没或正完成不可逆选择。主体状态必须来自剧本时点，不得擅自制造与剧情无关的奇观。

### 先确定视觉张力来源

叙事型图片在写最终Prompt前，内部先确定2—5个主要张力来源，例如：

- 人物姿态的失衡与环境力量的对抗；
- 巨大背景结构对小人物的压迫；
- 冷色主体中的单一高饱和刺点；
- 前景遮挡与远景大形形成的纵深；
- 柔软材质与粗粝环境的对撞；
- 静止表情与剧烈环境运动痕迹的反差。

最终Prompt必须让这些张力来源真实进入构图、光线、材质和空间，不能只在Prompt外解释。

### 背景是第二视觉主体

对于剧情关键帧、氛围图和视觉概念图，背景不能只写“海边、树林、房间、街道、雾气”。必须根据镜头目的明确：

1. **背景功能**：压迫、包围、托举、吞没、隔离、揭示、延伸或制造神圣空间；
2. **背景大形**：浪幕、雾墙、倾斜建筑、放射光带、山体黑影、走廊透视、云层旋涡等；
3. **空间分层**：近层附着物，中层主要结构，远层氛围与尺度；
4. **方向与动势**：背景的线条、雾、水、光或结构朝哪里汇聚、压下或裂开；
5. **局部高潮**：浪花爆裂、光穿雾、门缝高光、火焰翻起、背景人群突然留空等；
6. **与主体呼应**：背景形状、运动痕迹和色彩如何加强人物状态。

背景不得因景深而完全失去结构；允许柔化，但关键大形、层次和情绪功能必须可读。

### 静态帧要冻结“运动痕迹”

图片只描述一个瞬间，但可以写清动作留下的静态结果：衣料正被拉成哪条弧线、雨水从何处斜切、烟雾向哪侧卷动、飞沫停在哪个层次、人物重心正偏向哪里。禁止把运动痕迹写成多个连续动作。

### 默认只交付一版完整Prompt

除非用户明确要求短版、平台限字版或多个候选，默认直接交付一条高密度、可复制的完整Prompt，不要求用户在“简洁版、强化版、结构化版”之间选择。

## 图片Prompt基础公式

```text
前置核心块：主体/对象 + 准确静态状态与动作阶段 + 景别/机位/构图核心 + 场景与连续性锚点
+ 固定视觉基准
+ 导演意图与当前情绪时点
+ 参考资产及其职责
+ 2—5个主要视觉张力来源
+ 一个静态瞬间及其冻结运动痕迹
+ 背景功能、大形、空间分层、方向和局部高潮
+ 服装和道具状态
+ 构图与空间层次
+ 可见微表情、视线、呼吸提示、姿态、重心和手部状态
+ 真实光源、方向、情绪功能和色调
+ 材质、皮肤和影像质感
+ 画幅与输出结构
+ 必须保持一致
+ 针对性负面约束
```

简化理解：先让模型立即知道“谁、停在哪个可见状态、从哪里看、什么绝对不能漂”，再展开画面如何组织、光从哪里来、颜色和材质如何呈现。

## 编译顺序

### 1. 先确认图片类型

不同任务不能共用一个万能Prompt：

- 面部身份板；
- 生产三视图；
- 发型结构板；
- 服装层次或状态板；
- 手部与道具交互板；
- 姿态或动作故事板；
- 场景主布局；
- 无人物空镜；
- 多机位场景板；
- 道具结构或状态板；
- 分镜首帧；
- 分镜尾帧；
- 图生图修改；
- 局部修复；
- 降噪和4K增强。

### 2. 写清参考图职责

不能只写“参考上传图片”。每张参考图必须标注职责：

- 身份参考：锁定面孔、年龄、骨相和身体比例；
- 服装参考：锁定层次、颜色、污渍和穿戴结构；
- 场景参考：锁定建筑、布局、地标和主光；
- 道具参考：锁定尺寸、结构、材料和独特标记；
- 姿态参考：只借用动作与身体方向，不改变人物身份；
- 色调参考：只借用色温、饱和度、对比度和光影关系。

同一参考图承担多个职责时逐项说明。没有参考图时明确写“首次生成，无参考”，但这句属于管理说明，不得自动放在正向Prompt最前面；正向Prompt仍先写主体和目标画面。没有参考图时降低一次生成多视图的预期。

### 3. 主体身份

角色年龄不得使用固定默认值。用户、剧本、人物小传或已有设定已经明确年龄或年龄段时，直接继承；尚未明确时，先根据角色身份与生活阶段、叙事功能、故事题材、情感主题、关系结构、受众与传播场景、项目视觉审美、身体状态、社会经验和用户偏好判断最适合的年龄阶段，再进入外貌设计。

“电影感、现实感、高级感、克制、疲惫、极致美学”等抽象气质词不能直接推出年龄。年轻感、成熟感都可以成为符合项目的审美资源；禁止的是无依据改变已锁定年龄阶段、跨镜头年龄漂移、生活阶段变化和身份重设计。

角色至少写清：

- 由当前项目确定的年龄段、地域或族群特征；
- 脸型、骨相、眉眼、鼻、嘴、皮肤和发际线；
- 身高、体型、姿态和劳动或生活痕迹；
- 稳定身份标记；
- 表情温度；
- 禁止无依据改变已锁定年龄阶段、骨相、生活状态和角色类型的方向；项目需要年轻感、成熟感或其他年龄气质时，应准确保留与角色阶段相符的面部、身体、服装和表演特征。

场景至少写清：时代、地点、功能、布局、入口、固定地标、主要材质、天气、主光来源和禁止时代错误。

道具至少写清：尺寸、人体比例、正侧背结构、材料、工艺、磨损、独特标记、持有方式、默认位置和状态版本。

### 4. 一个静态瞬间

图片Prompt只能描述可以在单帧中确认的状态，例如：

- 手刚刚触碰门把；
- 刀尖停在铜锈上方；
- 人物回头前的侧脸；
- 雨水正从屋檐滴落；
- 道具已经断裂并落地。

不要把“起身、跑到门口、推门、回头、说话”全部写入一张图片Prompt。连续过程拆成首帧、尾帧或动作故事板。

### 5. 景别、角度和构图

写清：

- 画幅和横竖方向；
- 景别：大全景、全景、中景、中近景、近景、特写或极特写；
- 角度：平视、低机位、俯拍、正侧、四分之三、肩后或主观；
- 摄影机相对主体的位置；
- 前景、中景、背景；
- 主体占比、留白和视线空间；
- 地平线、轴线和屏幕方向；
- 是否需要为后续动作预留空间。

相机或镜头名称只能作为辅助，不得代替构图、光线和空间说明。

### 6. 静态表演与情绪时点

调用`controllers/performance-director.md`、`references/emotion-library.md`和`prompt-engineering/performance-prompt-compiler.md`。图片Prompt只能捕捉一个可见表演时点：

- 人物当下想隐藏、确认、拒绝或完成什么；
- 视线落点、眼睑、眉、嘴或下颌中的少量关键线索；
- 呼吸只能通过胸腔、肩部或嘴部状态的静态结果表达；
- 姿态、重心、左右手和手指张力；
- 情绪强度0—5和下一动作前的准备；
- 禁止夸张表演。

禁止只写“悲伤、恐惧、复杂情绪”。微表情必须与景别、焦点和灯光可读性一致。

### 7. 光线与色调

调用`visual-style-color-light.md`，至少继承：

- 主色、辅助色和点缀色；
- 色温、饱和度和对比度；
- 白平衡、黑位和高光策略；
- 真实主光来源、方向、颜色和照亮对象；
- 暗部保留程度；
- 人物肤色、服装和背景的关系；
- 禁止颜色和无来源光。

### 8. 材质和真实度

使用可观察材质，而不是只写“超写实”：

- 皮肤毛孔、轻微不对称、细纹和区域色差；
- 布料纤维、缝线、折痕、磨损和湿度；
- 木材刀痕、油污和边缘磨损；
- 金属氧化、划痕、包浆和反射粗糙度；
- 纸张纤维、折痕、水渍和墨迹；
- 建筑灰尘、潮气、裂纹和使用痕迹。

所有磨损必须有来源，不能随机做旧。

## 正向Prompt结构

每个最终Prompt应自然写成完整段落，并覆盖：

1. 首句前置核心块：主体/对象、准确静态状态、动作阶段、景别/机位/构图核心和连续性锚点；
2. 参考图职责；
3. 主体身份、固定标记和当前视觉状态；
4. 场景、背景功能和当前状态；
5. 2—5个视觉张力来源与一个准确静态瞬间；
6. 冻结运动痕迹、人物可见表演、视线、姿态和情绪强度；
7. 景别、角度、画面大形、视觉动线和前中后景构图；
8. 背景的大形、方向、空间层次、局部高潮及其与主体的呼应；
9. 光线、情绪功能、明暗节奏和色彩策略；
10. 材质和真实度；
11. 输出结构与比例；
12. 必须保持一致。

全局视觉基准必须直接继承到每个可复制Prompt，不能让用户另外拼接“全局前缀”。前置核心块不等于公共风格前缀，它必须针对当前这一帧写具体可见内容。

## 负面Prompt结构

负面Prompt按实际风险编写，不机械粘贴万能词。按需覆盖：

- 身份错误：换脸、年龄漂移、骨相变化、随机美化；
- 人体错误：多指、少指、融合肢体、关节反向、滑行；
- 服装错误：结构变化、颜色跳变、污渍和破损漂移；
- 道具错误：尺寸变化、结构变化、独特标记消失、穿模；
- 场景错误：建筑重建、门窗换位、地标消失、时代错误；
- 光色错误：无来源光、肤色跳变、滤镜变化、暗部死黑；
- 输出错误：裁头裁脚、视图数量错误、多格不同人物、乱码文字、水印；
- 类型错误：动漫、游戏CG、海报、商业写真或项目明确禁止风格。

## 输出规则

每个Prompt块必须写明：

- 比例和方向；
- 单图或多格；
- 视图数量与排布；
- 背景；
- 是否允许文字；
- 不可裁切区域；
- 身份、结构、构图和氛围的优先级；
- 长边或清晰度要求；
- 文件命名建议。

## 多视图稳定策略

### 理想方案

模型支持多参考和高一致性时，一次生成标准板。

### 稳定方案

1. 先生成单张正面身份图；
2. 以批准正面图生成左右四分之三和侧面；
3. 以身份图生成全身正面；
4. 再生成严格侧面和背面；
5. 最后人工排版为身份板或三视图。

不得假设所有图片模型都能一次稳定生成六视图。

## 图生图修改

图生图Prompt必须以前置保留合同开始：

```text
保持人物身份、构图、场景、服装、道具、光线和未指定区域完全不变，
只修改：……
修改后应达到：……
禁止连带改变：……
```

此类任务中“保持什么、只改什么”本身就是最高优先级执行语义，可以占据Prompt首句；作品名、镜头名和修改原因仍留在Prompt外。

## 局部修改与修复

局部修改必须先圈定区域，再写：

- 保留什么；
- 只修什么；
- 修复后的结构和材质；
- 边缘如何与原图融合；
- 禁止改变的邻近区域。

优先局部修复手指、嘴形、衣服标记、道具缺口、文字区和背景小穿帮，不为小错误重生成整张图。

## 降噪和4K增强

增强Prompt只允许提升：

- 分辨率；
- 纹理连续性；
- 夜景噪点；
- 压缩伪影；
- 边缘细节；
- 暗部可读性。

不得重绘脸、改变表情、重构衣服、增加锐化光晕或让皮肤塑料化。

## 硬失败

- 未写参考图职责；
- 用一张图片承担多个连续动作；
- 正向Prompt、负面Prompt和输出规则分散，无法一次复制；
- 只写“电影感、高清、真实”而没有具体光线和材质；
- 每个镜头重新发明角色、场景和道具；
- 多视图明显不是同一人物却仍标记可生产；
- 让用户自己拼接全局风格前缀；
- 小范围错误不提供图生图或局部修复方案；
- 叙事型图片只有主体细节，背景仍是泛化环境或空洞虚化；
- 使用“唯美、史诗、电影感、神性、压迫感”等抽象词，却没有对应的构图、光线、色彩、空间或材质原因；
- 没有明确画面大形、主要视觉动线或视觉张力来源；
- 背景没有功能、层次、方向和局部视觉事件，无法与主体共同制造情绪；
- 为了视觉强化破坏身份板、三视图或道具结构板的中性和清晰度；
- 把作品名、剧名、章节名、场次标题、Shot ID、CF ID、文件名、版本号或解释性导演文字放在模型执行Prompt开头；
