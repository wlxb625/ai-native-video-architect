# Post-Script Production Orchestrator

## 目标

本控制器负责剧本或视觉脚本确认后的全部生产流程，把S03之后的内容转译为：

```text
剧本拆解
→ 视觉圣经
→ 资产计划
→ 整批资产Prompt
→ 用户生成与自审
→ 分镜设计
→ 整批分镜帧Prompt
→ 核心样片视频Prompt
→ 整批视频Prompt
→ 续拍、硬切、修复、剪辑、声音、调色与交付
```

本控制器不是零散Prompt合集。它必须读取用户提供的Prompt工程资料所提炼出的图片、视频、运镜、连续性和修复规则，并根据项目剧本编译成可直接使用的生产包。

## 触发条件

当项目已存在已确认的剧本或视觉脚本，且用户要求资产、分镜图、生图Prompt、视频Prompt、图生视频、首尾帧、批量制作或完整生产流程时，必须读取：

- `prompt-engineering/image-prompt-compiler.md`
- `prompt-engineering/visual-style-color-light.md`
- `prompt-engineering/asset-prompt-system.md`
- `prompt-engineering/storyboard-frame-system.md`
- `prompt-engineering/video-prompt-compiler.md`

- `templates/asset-prompt-block.md`
- `templates/storyboard-frame-prompt-block.md`
- `templates/video-shot-prompt-block.md`
- `evals/prompt-production-readiness-score.md`

## 剧本后硬顺序

### S04 剧本拆解

从剧本逐场提取：

- 角色身份、年龄、外貌、身体和情绪状态；
- 发型、妆造、服装层次与变化点；
- 场景时代、地点、功能、布局、出入口和状态；
- 道具尺寸、材质、持有者、左右手、交互和状态链；
- 每项资产首次出现、最后出现和镜头依赖；
- 连续动作、特效和高风险生成点。

不得凭审美额外创造与剧本无关的资产。新增资产必须标明导演原因。

### S05 视觉圣经

除原有视觉规则外，必须完成六维色调合同：

```yaml
color_contract:
  primary_colors: []
  secondary_colors: []
  accent_colors: []
  color_temperature:
  saturation:
  contrast:
  white_balance:
  black_level:
  highlight_policy:
  skin_tone_relation:
  forbidden_colors: []
```

并完成光影合同：真实光源、方向、颜色、照亮对象、暗部层次、情绪目的和禁止无来源光。

### S06 资产计划

除Asset Registry外，为每项资产选择正确Prompt类型：

- 面部身份板；
- 生产三视图；
- 发型结构板；
- 服装层次与状态板；
- 手部与道具交互板；
- 连续动作故事板；
- 场景主布局；
- 无人物空镜；
- 多机位场景板；
- 道具结构与状态板；
- 图生图修改；
- 局部修复；
- 降噪或4K增强。

每项资产记录参考图职责：身份参考、场景参考、色调参考、结构参考或姿态参考，禁止模糊写“参考上传图片”。

### S07 资产制作Prompt

本阶段交付的是**完整整批资产Prompt包**，不是一次只给一项。

硬规则：

1. 一次性覆盖当前项目Asset Registry中所有待生成资产；
2. 每个资产使用独立完整复制块；
3. 每块必须同时包含正向Prompt、负面Prompt和输出规则；
4. 详细程度不得因“方便复制”而压缩；
5. 允许分章节，但不能让用户自行拼接全局前缀；
6. 全局视觉规则必须在每个最终可复制Prompt中被正确继承；
7. 角色、场景和道具Prompt分别调用专用公式，不能使用同一万能句式；
8. 复杂多视图可提出“稳定方案”和“单图模型失败时的分步方案”。

默认输出字段见`templates/asset-prompt-block.md`。

### S08 用户自审与资产确认

默认模式为`USER_SELF_AUDIT`：

- 用户在外部生图软件中批量生成、筛选和修改；
- 用户不需要逐张返回汇报；
- 用户回复“下一步”“资产通过”“已经选好了”等明确表达时，视为`ASSET_CONFIRMATION = PASSED`；
- 助手记录资产已由用户批准并进入S09；
- 不擅自要求用户上传候选图；
- 不把每个资产当成独立确认门。

可选模式为`ASSISTED_AUDIT`：只有用户明确说“帮我审核”“检查这张图”“找穿帮”时，才调用资产评分器逐项检查。

用户尚未生成资产，只是索要下一项Prompt时，不能误判为整个阶段完成。

### S09 分镜设计

一次性完成整片镜头表，不逐镜等待确认。每镜先设计动作，再设计景别、角度和运镜。

每镜只承担一个主要重点：

- 环境建立；
- 人物动作；
- 情绪反应；
- 关键细节；
- 信息揭示；
- 转场连接；
- 结果定格。

运镜必须有叙事动机。没有动机时优先固定镜头。

### S10 分镜帧Prompt

一次性交付整片所有镜头的分镜帧Prompt包。

每镜按需包含：

- 参考资产；
- 首帧静态设计；
- 尾帧静态设计；
- 正向Prompt；
- 负面Prompt；
- 输出规则；
- 图生图修改Prompt；
- 局部修复Prompt；
- 视频动作摘要；
- 连续性锚点；
- 稳定替代。

图片Prompt不得承担完整动作过程，只描述一个准确瞬间。首尾帧用于锁定动作起点和终点。

### S11 核心样片

选择3至5个最能验证项目的镜头，而不是按剧情顺序选择：

- 核心角色跨角度；
- 主场景跨机位；
- 核心道具交互；
- 高风险状态变化；
- 一次抽尾帧续拍或硬切；
- 一种主要运镜。

为这些镜头输出完整视频Prompt，用户自行生成并决定是否通过。用户回复“下一步”表示`CORE_SAMPLE_GATE = PASSED`。

### S12 批量视频制作

一次性交付整片视频生产包：

- 每镜完整图生视频或首尾帧Prompt；
- 运镜起点、方向、速度、幅度和终点；
- 动作起势、过程和收住；
- 允许动态环境元素；
- 禁止变化项；
- 抽尾帧续拍方案；
- 硬切新镜头首帧方案；
- 多角度防穿帮锚点；
- 失败修复策略；
- 镜头版本命名；
- 剪辑、声音、音乐、字幕和调色。

### S13 导演审查

审查的是成片或生产包是否完成原剧本，不是重新发明故事。只修复薄弱层。

## “下一步”语义合同

当当前阶段已经整批交付，用户说“下一步”，默认含义为：

> 当前阶段由用户自行执行或确认完成，直接进入下一个S阶段。

不得解释为：

- 下一个资产；
- 下一张图；
- 下一个镜头；
- 当前阶段中的下一条Prompt。

只有用户明确说“下一个资产”“继续下一张”“逐项来”时，才在同一阶段内部推进。

## 批量输出合同

默认批次单位是“阶段”，不是“单个资产”或“单个镜头”。

- S07：完整资产Prompt包；
- S09：完整镜头表；
- S10：完整分镜帧Prompt包；
- S11：完整核心样片测试包；
- S12：完整批量视频生产包。

若输出过长，可按角色、场景、道具或镜头区间分成多个连续区块，但必须在同一轮交付完整，不得把用户变成逐条确认操作员。

## 禁止行为

- 未读取Prompt工程模块就凭经验自由写生图或视频Prompt；
- 用“电影感、高清、真实”代替光源、方向、色彩和材质；
- 每个镜头重新定义角色和场景；
- 将多个连续动作塞进一张静态图片Prompt；
- 视频Prompt重复大段人物外貌，却不写动作和运镜终点；
- 要求用户每生成一张图就回来确认；
- 用户说“下一步”却只推进到同阶段下一项；
- 默认由助手审核用户所有候选图；
- 资产未由用户确认却虚假标记通过；
- Core Sample未确认却批量生产。
