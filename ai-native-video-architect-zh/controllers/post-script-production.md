# Post-Script Production Orchestrator

## 目标

本控制器负责剧本或视觉脚本确认后的生产流程。默认目标不是建立庞大的资产库，而是用最少的稳定参考完成可发布视频：

```text
剧本确认
→ 最小人物与场景设定
→ 按镜头顺序生成分镜图
→ 图生视频
→ 衔接、修复、剪辑、声音与交付
```

必须优先遵循用户提供的AIGC视频制作资料中的主流程：

1. 剧本与音乐节奏确认；
2. 每个主要人物先生成一张可用的人物三视图或综合角色板；
3. 每个主要场景先生成一张无人物空镜；
4. 使用人物参考图与场景空镜生成第一张分镜图；
5. 后续分镜优先继承上一张满意分镜，只改变动作、景别和机位；
6. 分镜图作为视频首帧，视频Prompt重点描述人物动作、运镜、稳定项和结尾；
7. 复杂动作才按需增加尾帧、道具结构图、局部修复或技术测试。

## 市场适配原则

当前参考图模型已经可以通过一张或少量角色、场景和道具参考维持跨镜头一致性。因此：

- 不把面部板、发型板、服装板、手部板、动作板和多机位场景板设为默认必做；
- 不为短片预先生成每个可能用到的机位空镜；
- 不在正式分镜之前完成所有技术测试；
- 不把专业影视资产管理强加给个人创作者和短视频项目；
- 先完成最小可用参考，再由实际失败决定是否升级控制。

## 生产复杂度分级

### LEAN（默认）

适用：15秒至90秒短片、1至3名主要角色、1至3个主要场景、个人创作者和快速商业交付。

每个主要角色默认只需要以下二选一：

- 一张人物三视图；或
- 一张包含面部特写、正侧背全身、服装与核心道具的综合角色板。

每个主要场景默认只需要：

- 一张无人物空镜主参考。

核心道具只有在以下情况才单独生成：

- 多镜头重复出现；
- 形态和尺寸必须严格一致；
- 承担剧情反转；
- 与人物发生高风险交互；
- 存在明确状态变化。

### CONTROLLED（按失败升级）

当实际生成出现持续换脸、服装漂移、空间穿帮、道具变形或特殊状态无法控制时，才增加：

- 独立面部参考；
- 服装或发型细节板；
- 核心道具结构图；
- 特殊状态板；
- 一个高风险手部或交互参考；
- 需要复用的第二场景角度。

### STUDIO（用户明确要求）

只有用户明确需要长片、系列化角色库、团队协作、复杂动作、商业角色资产沉淀或严格版本管理时，才使用完整的面部、发型、服装、手部、动作、多机位和状态链系统。

不得把STUDIO方案默认用于普通60秒短片。

## S04 剧本拆解

只提取会直接影响生成和剪辑的信息：

- 主要人物及其可见造型；
- 主要场景及固定空间锚点；
- 重复出现或推动剧情的核心道具；
- 每个镜头的一个主要动作；
- 光线、色调和时间变化；
- 必须提前控制的特殊状态；
- 高风险但不可删除的镜头。

不得为了显示专业而额外创造资产。

## S05 视觉圣经

对外输出保持简洁，至少锁定：

```text
整体风格
+ 主色调与辅助色
+ 真实光源方向
+ 人物与场景材质
+ 摄影和构图倾向
+ 禁止风格
```

详细色彩参数可以作为内部控制，不要求用户逐项操作。

## S06 最小资产计划

默认按以下公式计算：

```text
每名主要角色：1张综合角色参考
每个主要场景：1张无人物空镜
每件必须稳定的核心道具：0至1张结构或状态参考
每种不可通过普通Prompt完成的特殊变化：0至1张状态板
```

60秒、双角色、单场景项目通常应控制在4至7项核心资产内。该数字是生产规划参考，不是硬性配额；应尽可能减少，而不是凑足。

资产计划必须区分：

- `REQUIRED`：没有它无法稳定开始分镜；
- `ON_DEMAND`：出现失败后再生成；
- `POST_ONLY`：后期完成，不交给生图模型。

## S07 核心资产Prompt

一次性交付当前项目的全部`REQUIRED`资产Prompt，但数量必须服从最小资产原则。

默认使用用户资料包中的原生模板：

- 艺术性16:9角色身份板；
- 标准正面、90度侧面、背面人物三视图；
- 左侧面部特写加右侧正侧背全身组合；
- 人物细节与核心道具综合展示板；
- 场景空镜Prompt；
- 道具三视图Prompt。

每个Prompt可保留：

- 主体提示词；
- 原资料风格的负面约束；
- 必要的项目固定信息；
- 输出比例与文件名。

以下内容不再默认强制为每项资产提供：

- 独立修复Prompt；
- 独立风险报告；
- 独立依赖关系长表；
- 多套稳定替代方案；
- 单独发型、服装、手部和动作资产。

只有用户要求专业生产包或某项生成失败时才补充。

## S08 用户自审

用户可在外部软件中自行生成与筛选。用户回复“下一步”时表示核心参考已经可用，进入分镜。

不要求用户逐资产汇报，也不把候选图审核设为默认步骤。

## S09 分镜设计

一次性完成整片镜头表，每镜只承担一个主要任务和一个主要动作。

镜头数量以故事节奏为准。相似镜头必须合并，不能为了展示镜头语言而增加镜头。

## S10 按镜头顺序生成分镜图

Prompt可以一次性交付，但实际生产顺序必须是：

```text
第一张分镜：角色参考 + 场景空镜 + 当前镜头要求
后续分镜：角色参考 + 场景空镜 + 上一张满意分镜 + 当前镜头要求
```

后续镜头只改变：

- 动作；
- 景别；
- 摄影角度；
- 必要构图。

必须保持：

- 人物身份；
- 发型与服装；
- 场景结构；
- 核心道具；
- 光源方向；
- 主色调；
- 真实摄影质感。

不是每个镜头都需要尾帧。只有以下情况增加尾帧：

- 一个镜头包含明确起点和终点；
- 动作幅度较大；
- 状态发生改变；
- 需要首尾帧模型；
- 下一镜头必须继承准确终点。

## S11 首镜头与高风险样片

默认先测试1个普通镜头和最多1个高风险镜头，而不是固定选择3至5个镜头。

普通镜头用于确认：

- 人物和场景能否保持；
- 图像转视频是否稳定；
- Prompt长度是否适合所用模型。

高风险镜头只有项目确实存在特殊动作、变形、多人交互或复杂运镜时才测试。

## S12 视频生成与后期

每个镜头的视频Prompt遵循：

```text
唯一首帧
+ 人物起始状态
+ 一个主要动作
+ 动作速度
+ 一种主要运镜
+ 场景稳定要求
+ 结尾画面
+ 声音要求
+ 负面约束
```

固定镜头优先于无意义运镜。图片决定画面，视频Prompt主要决定人物怎么动和镜头怎么动。

片段失败时按最小修复顺序处理：

1. 简化动作；
2. 改为固定机位；
3. 缩短片段；
4. 使用尾帧；
5. 硬切新镜头；
6. 最后才增加新的资产参考。

## “下一步”语义

当一个阶段的必要内容已经完整交付，用户说“下一步”，表示进入下一个阶段，而不是让用户逐张回报。

但Skill不得把“阶段批量交付”误解为“必须批量制造大量资产”。批量指一次给完必要内容，不代表提高资产数量。

## 禁止行为

- 把短片默认设计成完整影视资产库项目；
- 为一个单场景短片预制多个无人物机位；
- 把发型、服装、手部、鞋履、动作分别拆成必做资产；
- 在没有发生失败前生成大量技术测试图；
- 声称内容来自用户资料，但实际主要来自自由扩写；
- 用冗长字段掩盖没有遵循原模板；
- 每镜强制首帧和尾帧；
- 每个镜头使用复杂运镜；
- 为了流程完整牺牲创作效率和实际可用性。
