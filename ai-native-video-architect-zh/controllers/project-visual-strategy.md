# Project Visual Strategy Controller

## 目标

在剧本或视觉脚本已经成立并进入制作阶段后，根据**当前项目自身**的主题、人物、空间、动作、时长、画幅、平台与生成条件，推导项目专属的视觉制作策略。

本模块只统一当前项目的资产、Shot、CF、图片Prompt和视频Prompt，不为整个Skill预设固定审美，也不得反向限制故事阶段的类型、结构和表达多样性。

## 一、启用边界

### 启用完整项目视觉策略

仅在以下任务进入制作阶段时启用：

- `ADAPT`：把已经成立的故事、剧本或视觉脚本转为制作提示词包；
- `FULL_CREATION_PACKAGE`：`CREATE`或`TRANSFORM`完成剧本并通过剧本门禁后继续制作；
- 用户明确要求视觉圣经、资产、Shot、CF、生图Prompt、视频Prompt或完整制作包。

### 不启用完整项目视觉策略

以下任务不得被强制进入完整视觉锁定：

- `SCRIPT_ONLY`：只创作故事、剧本或视觉脚本；
- `DIAGNOSE_SCRIPT`：只诊断剧本；
- `TRANSFORM_SCRIPT_ONLY`：只改写剧本，不要求制作包；
- 纯概念讨论、题材探索或多候选故事方向。

这些任务可以包含必要的可视动作和空间信息，但不得提前锁死全片色彩、摄影、灯光和资产体系。

### 局部视觉合同

以下任务只建立局部合同，不生成整部作品的视觉圣经：

- `SINGLE_IMAGE_PROMPT`：为当前图片任务建立`LOCAL_IMAGE_VISUAL_CONTRACT`；
- `IMAGE_TO_VIDEO`或`SINGLE_VIDEO_PROMPT`：从用户图片、Start CF或当前镜头事实提取`LOCAL_SHOT_VISUAL_CONTRACT`；
- 单镜头诊断、局部修复、图生图和视频续拍。

局部合同只约束当前图片或当前Shot，不能伪称已经锁定整部作品。

## 二、NARRATIVE_LOCK

完整项目视觉策略只能在`NARRATIVE_LOCK`之后生成。

`NARRATIVE_LOCK`至少确认：

- 主角或主体；
- 人物关系与核心处境；
- 世界规则或主要表达机制；
- 关键选择；
- 高潮行动者与不可逆变化；
- 结尾及开放程度；
- 必须保留的主题意义；
- 已获得用户授权的改动范围。

视觉制作可以改变实现方式、机位、镜头数量、资产方案和生成方法，但不得为了追求风格任意改变上述叙事事实。

## 三、创作中立原则

Skill统一的是推导方法和制作质量，不统一视觉结果。

禁止把以下内容写成所有项目默认值：

- 固定使用冷灰、低饱和或暖金色；
- 固定使用写实、诗性、克制或宏大风格；
- 固定使用浅景深、慢推镜头、对称构图或手持摄影；
- 固定让背景压迫人物；
- 固定使用青年主角、古典服装、雾、水、废墟或花瓣；
- 固定禁止喜剧化、明亮色彩、夸张表演或快速剪辑。

这些都必须由当前剧本、类型和观众体验推导。

同一个Skill应当能够产生彼此显著不同的现实主义、喜剧、恐怖、广告、MV、古典、科幻、无厘头和形式实验项目。

## 四、从剧本推导，而不是给剧本套滤镜

视觉策略必须引用当前剧本中的证据：

1. 人物在什么处境中行动；
2. 观众需要靠近、疏离、误判还是见证；
3. 核心冲突通过人物、空间、物件、时间还是形式发生；
4. 高潮依赖什么可见行动与状态变化；
5. 结尾需要留下什么视觉余波；
6. 哪些元素承担主题，哪些只是表面装饰；
7. 当前平台、时长、画幅和模型允许怎样的生产复杂度。

每条视觉规则都要回答“为什么适合这一个剧本”。不能只写“电影感、高级感、东方美学、赛博朋克、治愈、压迫”。

## 五、视觉方向探索与锁定

### 内部探索

在用户没有明确指定成熟视觉方向时，先内部探索2—4个真正不同的方向。差异必须来自：

- 空间与人物尺度；
- 写实程度和媒介感；
- 摄影距离与运动方式；
- 色彩和真实光源；
- 材质系统；
- 表演温度；
- 背景承担的功能；
- 生成与后期实现方法。

不得只生成同一方案的轻微配色变化。

### 选择

根据以下条件选择一个主方向：

- 对主题和人物选择的支持程度；
- 观众体验是否清楚；
- 是否保留项目原创性；
- 是否适合目标时长和画幅；
- 是否适合当前生成模型与后期条件；
- 是否能够形成稳定资产与镜头连续性。

用户已明确视觉要求时，优先忠实实现；只有要求内部冲突、不可生成或会破坏叙事时才提出修正。

### 锁定范围

视觉方向确定后写入`PROJECT_VISUAL_STRATEGY`，只对当前项目制作阶段生效。新项目必须重新推导，不得继承上一项目的审美值。

## 七、背景策略按项目决定

背景不是固定必须“压迫”或“第二主角”，但每个剧情项目必须明确背景在当前作品中的职责。

可选职责包括：

- 提供真实空间与行动条件；
- 与人物对抗或压迫人物；
- 托举、隔离、吞没或揭示人物；
- 通过状态变化承担叙事；
- 作为喜剧反应空间；
- 保持克制中性，避免抢夺主体；
- 作为形式节奏、图形或声音结构。

对于剧情关键帧和背景承担叙事变化的项目，必须进一步定义背景大形、近中远层次、方向、局部高潮和与主体的关系。对于技术资产板、商品结构图、纯角色身份图，背景应当低干扰，不得机械影视化。

## 八、资产规划接口

`PROJECT_VISUAL_STRATEGY`完成后，先进行镜头需求预分析，再规划资产。

资产数量不得由“越少越好”或“全部都做”决定，而由所有实际镜头中的以下覆盖需求决定：

- 人物会出现哪些景别、正侧背角度和身体动作；
- 是否存在重要面部近景；
- 是否存在全身、转身、背影、俯身、跪姿或复杂姿态；
- 服装、发型和配饰是否需要展示前后结构；
- 是否存在精确手部与道具交互；
- 是否存在污染、伤损、湿水、变装或其他状态累积；
- 场景是否出现正反打、反向机位、局部区域或多种时间状态；
- 道具是否存在结构、尺寸、页面、开合、破损或阶段变化；
- 哪些视觉规则必须跨镜头保持。

凡是缺少视觉依据会导致镜头身份、结构、交互、状态或空间漂移的资产，都属于必要资产。

## 九、制作阶段一致性

从S05开始，资产、Shot、CF、图片Prompt和视频Prompt必须引用当前项目的`PROJECT_VISUAL_STRATEGY`。

检查重点：

- 是否仍然服务已经锁定的剧本，而不是为了画面改写故事；
- 是否继承当前项目的视觉论点、Style DNA和连续性锚点；
- 是否在允许变化范围内产生镜头差异；
- 是否出现上一项目或模型默认风格的污染；
- 是否把项目策略误写成所有作品通用规则。

一致性不是要求每个镜头构图、色彩和景别相同，而是要求变化有叙事原因，并且仍属于同一个项目世界。

## 十、硬失败

出现以下任一情况，项目视觉策略不得通过：

- 在剧本完成前用固定视觉模板限制故事探索；
- `SCRIPT_ONLY`任务被强制生成资产和完整视觉圣经；
- 没有`NARRATIVE_LOCK`就进入项目视觉锁定；
- 视觉策略没有引用当前剧本证据；
- 只写风格名、导演名、滤镜或抽象形容词；
- 为追求风格擅自改变人物关系、核心机制、关键选择、高潮或结尾；
- 所有项目默认同一种色彩、摄影、表演温度或背景功能；
- 资产规划没有覆盖实际镜头角度、交互和状态；
- 局部图片或单镜头任务伪称已经建立全片风格。

# V4.5 场景功能与画面沟通增量整合

本节是增量规则，不删除或替代以上任何字段。进入Shot、CF、图片Prompt或单图局部视觉合同阶段时，必须额外读取：

- `references/scene-function-taxonomy.md`；
- `controllers/scene-function-router.md`；
- `controllers/frame-clarity-density-controller.md`；
- `prompt-engineering/image-prompt-compiler-v4.5-extension.md`；
- `templates/scene-function-frame-control-block.md`；
- `evals/frame-communication-check.md`。

## 十一、Shot级场景功能路由

项目视觉策略决定整部作品的视觉世界，场景功能路由决定单个Shot此刻主要给观众什么体验。两者不得混为一谈。

每个正式Shot必须有：

```yaml
scene_function:
  primary:
  secondary:
  script_evidence: []
  audience_immediate_effect:
  audience_delayed_effect:
  information_emotion_spectacle_priority:
  first_read:
  second_read:
  final_reveal:
  execution_bias:
  must_not_sacrifice: []
  conflict_and_split_decision:
```

主功能必须且只能一个；次功能可为空且最多一个。标签不得成为新的顶层模式，不得绑定固定色彩、景别、题材、年龄、画幅或审美。

功能路由发生在Shot拆解之后、导演意图与摄影灯光表演设计之前：

```text
PROJECT_VISUAL_STRATEGY
→ Shot拆解
→ SCENE_FUNCTION_ROUTING
→ DIRECTOR_INTENT
→ CAMERA / LIGHTING / PERFORMANCE
→ CF与Prompt
```

## 十二、强制视觉层级与密度控制

剧情关键帧、分镜CF、氛围图和视觉概念图必须定义：

- 1—4个核心大形；
- 承担结构、秩序或叙事的中尺度结构；
- 微小细节集中区域；
- 主体清洁轮廓区；
- 视觉休息区；
- 前中远景细节、锐度、对比与装饰衰减；
- 一个主要流动元素和最多一个辅助环境元素；
- 微粒、数字噪点和胶片颗粒策略。

华丽不能自动等于密集金粉、花瓣、羽毛、裂纹、珠链和碎片；干净也不能删除中尺度结构而变成空洞极简。视觉丰富度必须由当前项目和镜头功能推导。

## 十三、动作阶段与关系残留

关键静态动作必须标记：

```text
PREPARATION / CONTACT / TRANSITION / COMPLETION / AFTERMATH_RESIDUE
```

不能只描述“手在哪里”，还必须写清：

- 接触是否存在；
- 重量或力量由谁承担；
- 手掌、手指、手腕、肘部和身体趋势；
- 动作已产生的可见结果；
- 最可能被误读成什么；
- 防误读的正向可见线索。

人物关系镜头还必须检查动作结束后的关系残留：距离、触感余温、未完成手势、视线停留、呼吸、嘴唇、吞咽、道具褶皱和至少一个非自愿情绪泄漏。不得为了让动作语义准确而把关系彻底切断。

## 十四、焦点与缩略图可读性

叙事动作区、局部最亮区、最高局部对比区、主要高饱和色区、最高锐度区和世界变化起点默认应共同服务主场景功能。故意错开时必须有揭示、误导或观看关系理由。

短视频、封面和移动端画面必须检查缩略图可读性。第一眼至少能读出主大形、主体或关系、关键动作、核心道具和基本因果。不得依赖放大后的小字、细线、裂纹或极小表情才能理解镜头任务。

## 十五、原创结构、道具自然化与材质漂移

避免常见模板不能只写“不要莲花、光环、仙山、传送门、帆片或工业装置”，必须建立正向替代语法：

- 大形为何存在；
- 如何连接、受力或变化；
- 重复结构如何产生差异；
- 如何与人物行动形成因果；
- 为什么属于当前项目而不是通用AI素材库。

关键道具必须明确持有者、承重者、接触、重力、褶皱、变形和使用痕迹，防止过度居中、端正、完整、鲜亮而变成商品广告或公益宣传符号。

重要材质必须预判模型替代倾向，并写可观察属性：哑光程度、反射粗糙度、透明度、重量、厚度、边缘、受力、重力、折痕、磨损与真实光照响应。负面词只能辅助，不能代替正向材质定义。

## 十六、画幅是任务参数，不是默认美学

当前项目或本轮测试指定16:9、9:16、1:1或其他比例时，必须重新设计：

- 人物占比；
- 视线空间；
- 负空间功能；
- 主要运动方向；
- 大形超框方式；
- 缩略图与观看距离；
- 不可裁切区域。

不得只替换Prompt中的比例文字。最终输出还必须提醒：外部平台的实际宽高比参数通常高于文本Prompt中的比例说明。

## 十七、模板与检查挂接

- 每个Shot在原`shot-production-card.md`的导演意图之后，追加`templates/scene-function-frame-control-block.md`中的Shot级块；
- 每个生成CF在原`storyboard-frame-prompt-block.md`的前中后景之后，追加同一模板的CF级块；
- 原模板字段不得删除、折叠或用本增量块替代；
- 最终正向Prompt必须直接吸收增量块结论，不能只留在制作卡中；
- 完整制作包与单图任务除原检查外，还必须通过`evals/frame-communication-check.md`。

## 十八、真实生成图实测边界

真实图片用于发现跨场景共性缺口、平台参数错误、模型能力问题和适合局部修复的缺陷。不得把一次整体Skill完善任务无限拖入同一张图片的局部微调。

当用户要求先完善整个Skill时，应当：

1. 停止围绕单图反复改手势、距离或小道具；
2. 收束跨类型共性规则；
3. 完成模块、模板和检查的整体挂接；
4. 再使用不同场景功能进行横向压力测试。

## 十九、V4.5新增硬失败

出现以下任一情况必须`REPAIR`：

- Shot没有主场景功能或没有剧本证据；
- 功能标签没有进入摄影、灯光、表演和Prompt；
- 一个短Shot存在三个以上同权功能却未拆镜；
- 第一视觉关系无法一句话说明；
- 所有区域同等复杂、锐利或装饰密集；
- 华丽主要依靠随机粒子和碎屑；
- 为了干净删除中尺度结构导致画面空洞；
- 关键动作在静态帧中被误读为相反动作；
- 动作阶段正确但人物关系残留完全消失；
- 最亮处、唯一高饱和色和叙事动作互相分离且没有意图；
- 核心动作在缩略图中不可读；
- 只删除常见符号，没有建立替代结构；
- 道具变成商品陈列或宣传符号；
- 目标材质被常见模型材质替代且未反制；
- 剧情帧无意回落成角色海报、公益广告或摆拍；
- 横竖比例改变后仍沿用原构图；
- 用户要求整体完善时仍无限围绕同一张图局部修改。
