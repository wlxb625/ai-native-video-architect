# Production Execution Controller V4.2

## 目标

本模块负责把已经完成的参考图Prompt、分镜帧Prompt和导演级视频Prompt转成可执行的生产顺序、样片门槛、镜头台账、失败修复和剪辑交付方案。

核心原则：

> Prompt完成不等于参考图完成，参考图完成不等于样片通过，样片通过不等于整片可剪，整片可剪也不等于最终交付完成。

Skill必须明确当前证据支持到哪一层，禁止把`PROMPT_READY`描述成`PRODUCTION_READY`或`DELIVERY_READY`。

## 一、生产状态协议

项目状态只能使用以下层级：

```text
DESIGN_READY
PROMPT_READY
REFERENCE_READY
SAMPLE_VALIDATED
BATCH_GENERATION_READY
EDIT_READY
DELIVERY_READY
```

### DESIGN_READY

剧本、视觉规则、镜头表或控制架构已经成立，但可执行Prompt尚未完整。

### PROMPT_READY

必要资产、首尾帧和视频Prompt已经完整编译并通过静态检查，但尚未证明外部模型能够稳定生成。

### REFERENCE_READY

主要角色、主要场景和必要核心道具已经各自选定唯一母参考。只有实际选定图存在时才能进入该状态。

### SAMPLE_VALIDATED

至少一个普通镜头的真实生成结果通过；项目存在镜面、变形、复杂手部、多人交互或高难状态时，最多再验证一个高风险镜头。只有看到实际图片或视频结果并完成验收才能进入该状态。

### BATCH_GENERATION_READY

代表性样片通过，失败修复策略明确，控制帧依赖关系和镜头生成队列已经建立。

### EDIT_READY

所有必要镜头至少有一个通过验收、可进入剪辑的版本，硬切、遮挡切、续拍和分层合成所需素材齐全。

### DELIVERY_READY

画面、剪辑、声音、文字、调色、字幕和最终质量检查全部完成。

## 二、唯一母参考选择

每个需要长期继承的对象只保留一个当前主版本：

```yaml
canonical_reference:
  id:
  type: CHARACTER | ENVIRONMENT | PROP | SPECIAL_STATE
  selected_file:
  source_prompt_version:
  locked_features: []
  approved_uses: []
  known_limitations: []
  supersedes:
```

### 候选数量

外部生成成本允许时，每项核心参考建议先生成2至4个候选。该数量是实践建议，不是硬性要求；模型费用高、用户已经有可用参考或一次生成即稳定时可以减少。

### 选择标准

角色母参考优先检查：

- 面部身份是否清楚且容易被参考功能读取；
- 年龄、骨相、发型、主要服装和固定标记是否正确；
- 手、脸、衣物是否没有明显结构错误；
- 是否能覆盖计划中的主要景别；
- 摄影、灯光和材质是否符合项目视觉规则。

场景母参考优先检查：

- 空间布局、门窗、固定家具和背景地标是否清楚；
- 主光世界位置是否明确；
- 是否有足够纵深和可改变机位的空间；
- 是否包含不应存在的人物、文字或时代错误。

道具母参考优先检查：

- 尺寸、厚度、结构和独特标记是否稳定；
- 是否能支持人物交互和必要角度；
- 材质是否真实；
- 状态版本是否清楚。

### 唯一版本规则

- 不得在后续镜头中混用多个相似角色候选；
- 不得因为某张候选单帧更漂亮就替换已经锁定的身份；
- 新版本只有明确解决旧版本限制时才替代，并记录`s​​upersedes`；
- 局部错误优先图生图或局部修复，不默认重新抽整张母参考。

## 三、代表性样片门槛

### 普通镜头

普通镜头用于验证基础生产链：

- 角色身份能否保持；
- 场景和道具是否漂移；
- 动作物理是否可信；
- 摄影机是否遵守合同；
- 焦点、曝光和灯光是否稳定；
- 是否准确抵达结束帧；
- 尾帧是否能与下一镜连接。

普通镜头应来自正片，而不是另写一个无关测试动作。

### 高风险镜头

只有项目确实包含以下风险时，再增加最多一个高风险样片：

- 镜面、倒影或多层合成；
- 面部、服装或道具状态变化；
- 精确双手交互；
- 遮挡切换；
- 多人同步动作；
- 复杂运镜或长动作续拍。

高风险样片必须测试真实生产方案，包括实际首帧、尾帧、桥接帧、遮挡点或分层方法，不能用简化替代镜头假装通过。

### 样片通过条件

普通样片和必要的高风险样片必须使用`evals/shot-output-acceptance-score.md`审核。存在硬失败时不得进入批量生成。

未看到实际生成结果时，只能标记：

```text
SAMPLE_PLAN_READY
```

不得标记`SAMPLE_VALIDATED`。

## 四、失败分层诊断

片段失败后先判断问题属于哪一层：

### REFERENCE_FAILURE

表现：持续换脸、服装基础结构错误、场景母布局本身不清楚、道具结构缺失。

处理：修复或替换母参考；只有问题确实无法由原参考解决时增加细分资产。

### CONTROL_FRAME_FAILURE

表现：首帧或尾帧已经存在错误、手部接触不可能、尾态构图与下一镜冲突、状态图本身不稳定。

处理：先修首帧、尾帧或桥接帧，不继续调视频Prompt掩盖错误控制图。

### PROMPT_FAILURE

表现：动作过多、时间轴冲突、摄像机指令互相矛盾、灯光描述不足、结束状态不清楚。

处理：简化动作、减少运镜、量化时间与距离、明确稳定尾态。

### MODEL_CAPABILITY_FAILURE

表现：模型无法可靠完成镜面、多状态同时变化、精确手部、长动作或复杂拉焦。

处理：改变生成模式，使用首尾帧、缩短片段、续拍、两段硬切、遮挡切换或分层合成。不能把模型能力问题错误归因于资产不足。

### POST_PRODUCTION_FAILURE

表现：准确文字、薄雾、镜面层、声音、遮挡切点或颜色统一更适合后期完成。

处理：将该部分明确转入后期，不继续要求生成模型一次完成。

## 五、失败触发资产升级

新增资产必须对应已经观察到的失败：

- 重要近景持续换脸：补面部身份参考；
- 全景身体比例或服装层次持续变化：补全身服装参考；
- 核心手部与道具接触反复失败：补一张准确交互参考；
- 同一场景的必要第二机位持续重建空间：从母场景派生第二角度；
- 特殊状态无法跨镜保持：补特殊状态参考；
- 核心道具厚度、缺口或纹样漂移：补结构视图或局部结构参考。

以下情况不得新增资产：

- 只是想让流程显得更专业；
- 单次随机失败尚未复现；
- 调整生成模式即可解决；
- 后期更稳定；
- 资产不会被多个镜头引用。

## 六、依赖顺序

默认生产依赖顺序：

```text
唯一母参考
→ 代表性镜头的首帧、尾帧和桥接帧
→ 普通样片与必要高风险样片
→ 修复暴露出的薄弱层
→ 按依赖生成剩余控制帧
→ 按叙事连续性生成主要镜头
→ 生成独立空镜、插入镜头和结尾镜头
→ 分层合成、文字、声音、调色和剪辑
```

不得在代表性样片尚未通过时，无差别批量生成整片所有镜头。

### 控制帧依赖

下一张控制帧优先使用：

```text
唯一角色母参考
+ 唯一场景母参考
+ 必要道具母参考
+ 上一张已选定控制帧
+ 当前静态状态Prompt
```

不得仅用文字Prompt重新抽卡，导致身份和空间断裂。

## 七、镜头生成队列

生产队列不是简单镜头编号顺序，而是依据：

1. 共享同一状态和空间的连续镜头优先；
2. 后续镜头依赖上一镜尾帧时必须连续生产；
3. 高风险镜头通过后再展开相似镜头；
4. 独立空镜、登记纸、片尾和转场镜头可以后补；
5. 后期专用层与底板分开排队。

每个镜头必须记录：

```yaml
shot_run:
  shot_id:
  narrative_order:
  production_order:
  status: NOT_STARTED | GENERATING | REVIEW | PASS | CONDITIONAL | FAIL
  mode:
  canonical_references: []
  start_frame:
  end_frame:
  bridge_or_layers: []
  prompt_version:
  generated_candidates: []
  selected_candidate:
  acceptance_score:
  failed_dimensions: []
  repair_action:
  edit_connection:
```

## 八、候选版本和选择

每个镜头建议先生成2至4个候选版本，具体数量由费用、速度和模型稳定性决定。

选择镜头版本时优先级：

```text
叙事和结束状态正确
> 人物、场景和道具连续
> 手部和物理可信
> 摄影机、焦点、灯光稳定
> 可剪辑性
> 单帧美观
```

不得只因某个版本“最漂亮”就选择一个无法接入下一镜的片段。

版本命名建议：

```text
SHOT_01_V01.mp4
SHOT_01_V02.mp4
SHOT_01_PASS_A.mp4
SHOT_11A_PASS_A.mp4
SHOT_11B_PASS_A.mp4
```

## 九、镜头验收

每个片段至少检查：

- 首帧是否被模型擅自重绘；
- 人物身份、发型和服装是否稳定；
- 核心道具结构与状态是否正确；
- 左右手、接触点、重心和动作物理是否可信；
- 摄影机是否出现额外推拉、摇移、旋转或数字变焦；
- 焦点、景深、曝光和白平衡是否符合合同；
- 主光世界位置、色温、亮区和阴影是否稳定；
- 是否抵达可截图验证的结束帧；
- 结束帧是否稳定停留；
- 是否能与下一镜通过硬切、动作、视线、声音或遮挡连接。

只有通过验收的版本才能进入剪辑时间线。

## 十、剪辑与后期

生产包必须明确：

- 每个镜头使用哪个通过版本；
- 实际入点和出点；
- 硬切、动作匹配、视线匹配、声音桥、遮挡切换或切黑方式；
- 哪些镜面、倒影、雾气、文字和特效使用分层合成；
- 哪些声音由后期添加；
- 全片曝光、白平衡、对比度、饱和度和颗粒统一方式；
- 后期文字的透视、景深、运动跟踪和材质融合；
- 最终时长和节奏复核。

## 十一、最终交付检查

进入`DELIVERY_READY`前必须确认：

- 故事、关键选择、高潮和结尾未因生成失败被改变；
- 不存在明显换脸、服装漂移、空间跳变和道具变形；
- 灯光方向、曝光和白平衡连续；
- 镜头连接可理解且没有意外黑帧或跳帧；
- 精确文字由可靠后期完成；
- 声音、音乐和静默关系符合剧本；
- 画幅、分辨率、帧率和最终文件设置正确；
- 片头、片尾、字幕和版权信息按项目需要完成。

## 十二、硬失败

- 没有实际生成结果却声称样片已经通过；
- 只有Prompt包却声称项目已经可剪或完成；
- 未选定唯一母参考就混用多个角色候选；
- 代表性样片失败后仍直接批量生成整片；
- 把模型能力问题错误地通过无限增加资产解决；
- 镜头选择只看单帧美观，不检查尾帧与下一镜；
- 未建立镜头版本和通过状态记录；
- 未通过验收的片段直接进入最终时间线；
- 精确文字、复杂镜面和雾气明知不稳定仍强迫单模型一次完成；
- 为了省事改变已确认的关键选择、高潮或结尾。
