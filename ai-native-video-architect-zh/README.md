# AI Native Film Studio V4.2

一套覆盖**创意、故事、剧本、生图、分镜、生视频、实际生产、镜头验收、剪辑与交付**的中文AI视频创作Skill。

它不是单独的剧本工具、图片Prompt工具或视频Prompt工具，而是把整条创作链连接在同一个项目中：

```text
想法或已有作品
→ 创意方向
→ 故事方案
→ 剧本或视觉脚本
→ 剧本制作拆解
→ 视觉设定
→ 核心参考图
→ 唯一母参考
→ 镜头设计
→ 首尾帧与控制帧
→ 代表性样片
→ 导演级视频Prompt与生产队列
→ 实际镜头验收、剪辑和交付
```

用户已经拥有剧本、参考图、分镜或生成片段时，可以直接从对应阶段继续，不必强制从头开始。

## 调用方式

```text
$ai-native-video-architect-zh
```

也可以直接提出当前需求：

```text
我只有一个60秒悬疑短片想法，帮我从创意方向开始完成剧本。
```

```text
这是我的故事梗概，帮我扩展成可制作的正式剧本，并继续做视觉设定。
```

```text
这是已经确认的剧本，不要改剧情，直接进入角色场景参考图和分镜制作。
```

```text
我已经有角色图、场景图和镜头表，直接生成首尾帧Prompt和视频Prompt。
```

```text
这是实际生成的视频，帮我检查换脸、灯光、手部、尾帧和剪辑连接问题。
```

## 适合的项目

- AI短片、微电影和剧情短视频；
- 无对白视觉叙事；
- 悬疑、恐怖、科幻、现实主义、喜剧和实验影像；
- 高概念短片；
- 品牌故事、广告和商业视觉内容；
- MV、意识流和形式化影像；
- 小说、文章、大纲或现有剧本的视频化改编；
- 已有参考图、分镜、视频Prompt或生成片段的继续制作；
- 对已有作品进行诊断、改写或制作适配。

## 四种操作模式

### CREATE｜从零创作

从一个想法、人物、题材、情绪或视觉画面开始，逐步完成故事、剧本和完整制作链。

适用于：

- 只有模糊灵感；
- 已有明确题材但没有故事；
- 已有故事但没有正式剧本；
- 希望从剧本一路做到生图、生视频和后期。

### TRANSFORM｜修改已有作品

修改已有故事、剧本或导演方案，并先建立保护合同，明确哪些内容必须保留、哪些内容允许改变。

支持五级改写：

- `LEVEL_0`：校对与错误修正；
- `LEVEL_1`：轻度优化，不改变人物、关系、高潮和结尾；
- `LEVEL_2`：结构、场景、视觉表达和镜头功能优化；
- `LEVEL_3`：商业、文学、实验、类型、高概念或视觉导演方向增强；
- `LEVEL_4`：获得明确授权后的深度改编。

### DIAGNOSE｜只诊断，不默认重写

分析故事、剧本、分镜、Prompt或生成片段为什么成立或失效，并区分：

- `BUG`：明确错误；
- `RISK`：目前可用但存在风险；
- `CHOICE`：作者有意设计，应当保护；
- `OPPORTUNITY`：可选增强方向；
- `PREFERENCE`：审美或市场偏好，而不是客观错误。

诊断可以覆盖故事、人物、结构、对白、视觉叙事、镜头语言、声音、生成稳定性和剪辑可行性。

### ADAPT｜把已有作品转成可执行AI生产方案

尽量不改变已经成立的故事，而是把它转译为可生成的参考图、分镜、控制帧、视频Prompt和生产流程。

适用于：

- 已有完整剧本；
- 已有参考图或分镜；
- 已有视频Prompt但缺少生产架构；
- 已有失败片段，需要改变实现方式而不是重写故事。

## 导演模式与创作路径

Skill可以根据任务选择一个主导演模式，并最多配合两个辅助模式：

- `STORY_DIRECTOR`：故事、人物、关系、结构、高潮和结尾；
- `VISUAL_DIRECTOR`：视觉叙事、母题、空间、色彩和画面表达；
- `BLOCKBUSTER_DIRECTOR`：高概念、奇观因果和大场面组织；
- `EXPERIMENTAL_DIRECTOR`：意识流、形式规则和非传统叙事；
- `PRODUCTION_DIRECTOR`：参考资产、分镜、生成稳定性、剪辑和交付。

主要创作路径包括：

- `COMMERCIAL`：信息清晰、节奏有效、传播和观看留存明确；
- `LITERARY`：人物关系、情绪、余韵和开放表达；
- `EXPERIMENTAL`：形式规则、视觉推断和非传统因果；
- `HYBRID`：在商业清晰度、文学性和实验表达之间组合。

# 剧本功能完整说明

## 1. 从模糊想法建立创作需求

当用户只有题材、情绪或一个画面时，Skill会补齐真正影响创作的条件：

- 类型或内容领域；
- 目标情绪和观众体验；
- 剧情、视觉叙事、广告、MV或实验形式；
- 主角或主要主体；
- 人物关系；
- 场景规模；
- 目标时长和画幅；
- 平台或观看场景；
- 对白、旁白、音乐和声音倾向；
- 必须保留和禁止出现的内容。

用户已经提供的信息不会被重复询问。

## 2. 提供不同创意方向

方向尚未确定时，可以给出两到三个真正不同的方案，而不是只更换标题和风格词。

每个方向会明确：

- 主角或主体；
- 核心任务；
- 主要关系；
- 核心事件、机制或形式规则；
- 主要冲突和代价；
- 视觉身份；
- 高潮由谁选择和行动；
- 结尾方向；
- 该方向的优势、风险和制作难度。

确认方向后再进入故事方案，避免在错误方向上直接写完整剧本。

## 3. 故事方案与一句话概念

故事方案不是背景设定堆积，而是建立能够推动整片的因果结构。

可以完成：

- 一句话故事或核心概念；
- 观众在观看过程中持续关心的问题；
- 主题问题和核心体验；
- 主角的可观察任务；
- 主要关系和隐藏状态；
- 核心事件、世界机制或形式规则；
- 机制的代价、限制和失败后果；
- 开场偏差或第一次行动；
- 中段变化；
- 递进、风险和代价升级；
- 无法两全的关键选择；
- 高潮的选择者、行动者和承担代价者；
- 结局事实、开放事实和最终图像。

高概念项目会压缩为一个核心机制、一个人物任务和一个无法两全的选择，避免把长片信息量塞进短片。

## 4. 情节叙事、视觉叙事和混合叙事

### 情节叙事

通过任务、事件、冲突、信息和选择形成明确因果。

### 视觉推断叙事

通过人物行动、空间痕迹、物件状态、重复动作、声音和画面变化，让观众自己推断关系、历史和真实含义。

### 混合叙事

情节和视觉必须服务同一个故事，不能让台词讲一部作品、画面又表现另一部作品。

无对白、MV、广告、意识流和实验作品同样会建立完整视觉脚本，不会只输出一组互不相关的意象。

## 5. 人物、任务和关系设计

Skill会检查人物是否真正影响故事，而不只是观看异常世界。

人物设计可以包括：

- 外在身份与当前处境；
- 隐藏状态；
- 欲望、任务和阻碍；
- 可观察行动；
- 有意等待、拒绝或不行动；
- 与其他人物、空间、系统或物件的关系；
- 人物掌握的信息和误解；
- 关系变化；
- 私人代价；
- 关键选择；
- 高潮后的不可逆变化。

“寻找真相”“理解自己”“拯救世界”等抽象目标会被转成能够拍摄和生成的具体行为。

## 6. 核心机制和高概念压缩

高概念或形式规则必须真正影响：

- 世界如何运作；
- 人物如何行动；
- 代价如何产生；
- 视觉如何变化；
- 高潮如何选择；
- 结尾留下什么残余。

如果一个规则只带来漂亮特效，却不影响人物和因果，它不会被当成真正核心机制。

当项目概念过多时，可以：

- 选择最强独特概念；
- 合并相似机制；
- 删除不影响主线的设定；
- 把抽象世界问题转成主角的私人代价；
- 让奇观承担具体剧情功能；
- 将移除的好点子保存为其他项目素材。

## 7. 视觉母题与重解释

视觉叙事项目可以设计：

- 重复动作；
- 关系物件；
- 空间痕迹；
- 声音母题；
- 第一次提出问题的图像；
- 中段改变理解的图像；
- 后段重解释前文的图像；
- 结尾留下残余的图像。

母题不能只重复出现或更换颜色，而要在不同阶段改变含义。

## 8. 场景结构与节奏

每个场景都会明确它为什么必须存在，以及它改变了什么。

场景可以承担：

- 推进人物任务；
- 展示或升级核心机制；
- 提供新信息；
- 增加风险或代价；
- 改变人物关系；
- 改变物件状态；
- 增加选择压力；
- 完成视觉母题的变义；
- 为高潮或最后图像做铺垫；
- 承担钩子、留存、转折或情绪停留。

对短片会根据目标时长控制场景数量和信息密度，避免每场都加入新设定。

## 9. 正式剧本与视觉脚本

剧情剧本可以包含：

```text
SCENE编号
内景/外景｜地点｜时间｜现实层级
预计时长
可观看的动作、空间和道具状态
人物动作和表演
对白
旁白
录音或设备播放内容
环境声与动作声
画面文字
场景退出状态
```

每场还可以记录制作与连续性信息：

- 当前任务和推进程度；
- 核心机制当前状态；
- 新增信息与新代价；
- 选择压力；
- 人物掌握的信息变化；
- 关系变化；
- 道具变化；
- 形式规则变化；
- 必须口型同步的内容；
- 可转为画外声的内容；
- 后期制作的精确文字；
- 高风险动作；
- 稳定替代方案；
- 该场景结束后必须被下一场继承的状态。

无对白视觉脚本会明确：

- 主体初始状态；
- 可观察动作；
- 环境变化；
- 道具变化；
- 情绪或关系变化；
- 最终状态；
- 与下一场的连接。

## 10. 对白、旁白、声音和画面文字

Skill不会为了“视觉化”机械删除所有对白。

对白可以承担：

- 请求、拒绝、承诺、试探和欺骗；
- 关系压力；
- 信息差和误解；
- 人物身份与语言差异；
- 高潮选择。

当对白、旁白或字幕只是在解释本可被看到的内容时，可以转化为：

- 人物行动；
- 物件位置或损坏；
- 空间使用痕迹；
- 重复动作的变化；
- 声音提前、延后、反差或缺席；
- 结果镜头。

声音设计可以包含世界声、人物声、动作声、声音母题、音乐曲线和主动沉默，而不是默认全程铺背景音乐。

## 11. 高潮、艰难选择和结尾

高潮不只是最大的视觉场面，而是人物必须在两个真实价值之间作出不可逆选择。

Skill会锁定：

- 谁作出选择；
- 谁执行行动；
- 谁承担代价；
- 哪些两全方案被排除；
- 选择如何改变前文含义；
- 高潮后剩下什么不可逆事实。

开放结尾不等于故事未完成。结尾至少完成人物、关系、情绪、主题或形式中的一项，并留下可以复述的最终事实和最后图像。

结尾检查可以包括：

- 人物任务结果；
- 关键选择结果；
- 不可逆损失；
- 核心机制残余；
- 关键物件的新含义；
- 最后一幅画面；
- 与开场的呼应；
- 已完成与仍开放的内容；
- 是否解释过度。

## 12. 已有作品的保护与改编

用户提供已有作品时，Skill会区分：

- 必须保护的人物、关系、事实、机制、高潮和结尾；
- 允许改变的实现方式；
- 禁止变化；
- 改写等级；
- 期望收益；
- 可以接受的损失。

未经授权不会随意：

- 改变人物关系性质；
- 添加背叛或身份反转；
- 改变谁选择、谁行动、谁承担代价；
- 把开放结尾改成明确结论；
- 为降低生成难度而改变故事核心。

# 实际使用阶段｜S00—S13

以下是从零创作时可能经历的完整阶段。阶段可以根据用户已有材料跳过，但每项交付都有明确职责。

## S00｜创作需求

明确类型、目标情绪、叙事形式、主角、时长、画幅、平台、声音和禁忌。

**输出：**`CREATIVE_BRIEF`

## S01｜创意方向

提供两到三个不同创意方向，比较主角、核心任务、机制、视觉身份、高潮、结尾和制作风险。

用户确认方向后进入下一阶段。

**输出：**`DIRECTION_OPTIONS`

## S02｜故事方案

完成一句话故事、主角任务、核心事件或规则、递进、中段变化、关键选择、高潮和最后图像。

**输出：**`STORY_TREATMENT`

## S03｜剧本或视觉脚本

完成正式场景、动作、对白、旁白、声音、道具变化、场景退出状态和必要制作标记。

无对白项目完成可制作视觉脚本。

用户确认剧本后，同一个Skill继续进入下游生产。

**输出：**`SCRIPT_PACKAGE`

## S04｜剧本制作拆解

从已确认剧本中提取真正影响画面和生成的内容：

- 主要人物；
- 服装和状态变化；
- 主要场景；
- 核心道具；
- 每场主要动作；
- 时间、天气和光线变化；
- 声音与剪辑连接；
- 高风险镜头；
- 必须继承的结束状态；
- 应留给后期完成的内容。

**输出：**`SCRIPT_BREAKDOWN`

## S05｜视觉设定

确定：

- 画幅和视觉风格；
- 主色、辅色和强调色；
- 色温、饱和度和对比度；
- 真实光源及世界空间方向；
- 皮肤、布料、木材、金属、纸张等材质规则；
- 摄影和镜头倾向；
- 禁止出现的视觉效果。

**输出：**`VISUAL_RULESET`

## S06｜最小核心参考计划

判断真正需要哪些参考图，而不是默认建立庞大资产库。

通常包括：

- 每名主要角色一张身份主参考；
- 每个主要场景一张无人物空镜；
- 必须跨镜头稳定的核心道具；
- 剧情必须精确控制的特殊状态；
- 确有需要时才增加的全身、面部、手部、多视图或第二机位。

**输出：**`MINIMUM_REFERENCE_PLAN`

## S07｜核心参考图Prompt

一次性交付所有必要角色、场景、道具和状态参考图Prompt。

每项包含：

- 资产名称和文件名；
- 资产形式与选择理由；
- 参考输入及职责；
- 可直接复制的完整正向Prompt；
- 负面Prompt；
- 画幅、分辨率和输出规则。

摄影、焦点、曝光、灯光、色彩和材质会融合进最终正向Prompt，不要求用户自行拼接。

**输出：**`REFERENCE_PROMPT_PACK`

## S08｜唯一母参考选择

实际生成参考图后，为每个长期继承的角色、场景、道具和特殊状态选定一个当前主版本。

记录：

- 选中的文件；
- 锁定的身份、服装、空间和结构特征；
- 已知限制；
- 未选候选的原因；
- 后续不得混用的相似版本。

只有真实选定母参考后，项目才进入`REFERENCE_READY`。

**输出：**`CANONICAL_REFERENCE_RECORD`

## S09｜整片镜头设计

一次性完成整片镜头表，而不是逐镜头临时抽卡。

每镜明确：

- 镜头目的；
- 输入状态；
- 静态起点；
- 主要动作；
- 景别、焦段和机位；
- 轴线和屏幕方向；
- 前中后景和构图；
- 摄影机运动及动机；
- 焦点、景深和曝光；
- 当前镜头具体灯光；
- 时长；
- 精确结束状态；
- 下一镜继承；
- 声音和剪辑连接；
- 风险与稳定替代方案。

**输出：**`SHOT_LIST_AND_CAMERA_PLAN`

## S10｜分镜首尾帧与控制架构

为整片镜头设计：

- 首帧；
- 必要尾帧；
- 动作中间控制帧；
- 遮挡切换桥接帧；
- 镜面、倒影和特殊状态控制图；
- 局部修复Prompt；
- 控制帧依赖关系；
- 每镜`END_FRAME_CONTRACT`。

后续画面优先继承唯一母参考和上一张已经选定的控制帧。

**输出：**`FRAME_PROMPT_PACK`

## S11｜代表性样片门槛

正式批量生产前，先测试：

- 一个来自正片的普通镜头；
- 项目存在镜面、变形、复杂手部、多人同步、遮挡切换或复杂运镜时，再测试一个高风险镜头。

检查：

- 首帧忠实度；
- 尾帧能否抵达；
- 人物、场景和道具连续性；
- 手部和动作物理；
- 摄影机终点；
- 焦点、曝光和灯光稳定；
- 镜头是否可剪辑。

没有真实生成媒体时，只能输出样片计划，不能宣称样片已经通过。

**输出：**`CORE_SAMPLE_PACK_AND_ACCEPTANCE_RECORD`

## S12｜导演级视频Prompt与生产执行包

为每个镜头编译完整视频Prompt，并建立实际生产运行手册。

每镜Prompt可以包含：

- 生成模式和输入控制帧；
- 场景空间与构图；
- 主体起始状态；
- 按秒动作时间轴；
- 动作距离、角度、速度、重量和接触；
- 摄影机合同；
- 焦点、景深、曝光和白平衡；
- 逐镜灯光合同；
- 材质与环境动态；
- 精确结束帧；
- 下一镜继承；
- 声音；
- 必须保持项和负面约束。

支持的生成方式：

- `SINGLE_START_FRAME`：单首帧低幅度运动；
- `FIRST_LAST_FRAME`：首尾帧控制；
- `TAIL_FRAME_CONTINUATION`：抽尾帧续拍；
- `TWO_SEGMENT_HARD_CUT`：两段硬切；
- `OCCLUSION_SWITCH`：遮挡切换；
- `LAYERED_COMPOSITE`：分层合成。

生产执行包同时包含：

- 当前生产状态；
- 唯一母参考记录；
- 样片记录；
- 控制帧依赖图；
- 镜头生成队列；
- 候选版本和命名规则；
- 镜头台账；
- 失败分层诊断；
- 资产升级记录；
- 续拍、硬切和分层计划；
- 剪辑、声音、调色和后期文字方案。

**输出：**`VIDEO_PROMPT_PACK_AND_PRODUCTION_RUNBOOK`

## S13｜实际镜头验收、剪辑与交付

用户提供真实图片或视频后，Skill检查：

- 剧本和镜头目的是否被实现；
- 首尾帧是否忠实；
- 人物身份、服装、场景和道具是否连续；
- 手部和接触是否正确；
- 动作物理是否可信；
- 摄影机、焦点、景深和曝光是否正确；
- 灯光与色彩是否稳定；
- 镜头是否可以和前后内容连接；
- 问题应重新生成、局部修复还是转入后期。

失败会被归入：

- `REFERENCE_FAILURE`；
- `CONTROL_FRAME_FAILURE`；
- `PROMPT_FAILURE`；
- `MODEL_CAPABILITY_FAILURE`；
- `POST_PRODUCTION_FAILURE`。

只有通过验收的镜头版本进入时间线。最终继续完成：

- 镜头选择；
- 入点和出点；
- 动作、视线和声音匹配；
- 硬切、遮挡切换和分层合成；
- 精确文字、字幕和图形；
- 环境声、动作声、音乐和沉默；
- 曝光、色彩、颗粒和镜头连续性；
- 最终时长、导出规格和质量检查。

**输出：**`SHOT_ACCEPTANCE_REPORT_AND_DELIVERY_PACKAGE`

# 生图功能

## 核心参考图

可以生成：

- 角色身份主参考；
- 全身服装参考；
- 面部特写；
- 手部与核心道具交互；
- 标准人物三视图；
- 综合角色板；
- 无人物场景空镜；
- 场景必要第二机位；
- 核心道具结构与状态图；
- 特殊状态参考图。

角色默认先判断一张身份主参考是否足够，不默认密集六宫格或固定多张资产。

## 分镜与控制图

可以生成：

- 镜头首帧；
- 镜头尾帧；
- 中间动作控制帧；
- 遮挡桥接帧；
- 镜面或倒影分层底图；
- 状态变化控制图；
- 续拍起点；
- 局部编辑和修复Prompt。

## 完整正向Prompt

每条最终图片正向Prompt会自然融合：

```text
主体身份与用途
+ 构图和主体位置
+ 摄影机、焦段、机位和角度
+ 焦点、景深和曝光
+ 白平衡、高光和暗部
+ 主光来源、方向、色温、软硬和光比
+ 皮肤、布料、木材、金属、纸张等材质
+ 背景、空间和连续性要求
```

负面Prompt和画幅、分辨率等输出设置可以独立提供。

# 生视频功能

## 先设计镜头，再编写Prompt

视频Prompt不会只写“电影感、缓慢推进、人物自然移动”。

每镜会先建立明确的画面和导演合同，再转成模型可以执行的完整Prompt。

## 动作时间轴

复杂动作会拆成按秒或按阶段的节拍，包括：

- 动作何时开始；
- 移动方向；
- 距离和角度；
- 速度变化；
- 重量和接触；
- 何时减速；
- 何时停止；
- 尾帧稳定多久。

## 摄影和光学

每镜可以明确：

- 焦段或等效视角；
- 机位高度和距离；
- 景别；
- 轴线与屏幕方向；
- 固定、推进、拉远、横移、摇镜或其他运动；
- 运镜开始时间、速度、幅度和终点；
- 起始焦点、焦点变化和最终焦点；
- 景深、曝光、白平衡、高光和暗部；
- 镜头呼吸、运动模糊和自动曝光限制。

## 逐镜灯光

每条最终视频Prompt可以包含：

- 真实主光来源；
- 世界空间方向；
- 相对人物方向和高度；
- 色温；
- 软硬和强弱；
- 主要受光区域；
- 阴影区域；
- 辅光和实景灯；
- 光比；
- 与前后镜头的连续性。

## 连续性和精确尾帧

每镜都会记录：

- 输入状态；
- 必须保持的人物、服装、场景和道具；
- 精确结束状态；
- 下一镜必须继承的内容；
- 剪辑连接；
- 是否需要预生成尾帧、抽尾帧或桥接帧。

## 复杂内容的稳定实现

以下内容不强迫一个模型一次完成：

- 镜中人物；
- 水面倒影；
- 薄雾和呼吸；
- 精确文字；
- 复杂手部；
- 多种状态同时变化；
- 遮挡前后身份切换；
- 长动作和复杂运镜。

可以改用分段、结果镜头、遮挡切换、抽尾帧续拍或分层合成。

# 实际生产与状态

项目状态依据真实证据标记：

```text
DESIGN_READY
PROMPT_READY
REFERENCE_READY
SAMPLE_VALIDATED
BATCH_GENERATION_READY
EDIT_READY
DELIVERY_READY
```

- 已完成设计，但Prompt尚未完成：`DESIGN_READY`；
- Prompt已完成，但真实参考图尚未选定：`PROMPT_READY`；
- 唯一母参考已经选定：`REFERENCE_READY`；
- 普通样片和必要高风险样片已经通过：`SAMPLE_VALIDATED`；
- 样片通过并已修复薄弱层，可以进入整片生产：`BATCH_GENERATION_READY`；
- 所有必要镜头已有通过版本：`EDIT_READY`；
- 剪辑、声音、文字、调色和最终检查完成：`DELIVERY_READY`。

没有实际媒体时，不会声称样片通过、可剪辑或项目已经完成。

- `CANONICAL_REFERENCE_RECORD`：唯一母参考记录；

# 使用原则

- 用户已有的事实和材料不重复询问；
- 可以从任何已有阶段直接进入；
- 剧本确认后继续完成下游制作，不要求切换Skill；
- 无对白不等于没有剧本；
- 人物选择、高潮和结尾不会为了技术方便被随意改变；
- 普通短片只制作最少但够用的参考资产；
- 最终图片和视频Prompt可直接复制；
- 每个镜头都具有明确结束帧合同；
- 复杂生成问题通过分段、遮挡、续拍和分层解决；
- 失败时只修复真正薄弱的层级；
- 未通过验收的镜头不会进入最终时间线；
- 用户说“下一步”时，进入下一个完整交付阶段，而不是强制逐张图片确认。
